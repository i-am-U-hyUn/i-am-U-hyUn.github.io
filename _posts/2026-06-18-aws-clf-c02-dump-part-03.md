## Q1. NoSQL 데이터베이스 서비스

다음 중 빠르고 신뢰할 수 있는 NoSQL 데이터베이스 서비스는 무엇입니까?

- A. Amazon Redshift
- B. Amazon RDS
- C. Amazon DynamoDB
- D. Amazon S3

**정답: C**

✅ **C. Amazon DynamoDB**: DynamoDB는 AWS가 제공하는 완전 관리형 NoSQL 데이터베이스 서비스로, 밀리초 단위의 빠른 응답 속도와 높은 신뢰성을 제공합니다. 키-값(Key-Value) 및 문서(Document) 데이터 모델을 지원하며, 자동으로 확장됩니다.

❌ **A. Amazon Redshift**: Redshift는 페타바이트 규모의 데이터 웨어하우스 서비스로, SQL 기반의 분석용 관계형 데이터베이스입니다. NoSQL이 아닙니다.

❌ **B. Amazon RDS**: RDS(Relational Database Service)는 MySQL, PostgreSQL, Oracle 등을 지원하는 관리형 관계형(SQL) 데이터베이스 서비스입니다. NoSQL이 아닙니다.

❌ **D. Amazon S3**: S3는 객체 스토리지 서비스로 데이터베이스가 아닙니다. 파일이나 이미지 같은 객체를 저장하는 용도로 사용됩니다.

💡 **시험 꿀팁**: NoSQL = DynamoDB / 관계형(SQL) = RDS / 데이터 웨어하우스 = Redshift / 객체 스토리지 = S3. 이 4가지 서비스의 역할 구분은 시험 단골 문제입니다.

## Q2. AWS 클라우드 민첩성(Agility)

AWS Cloud의 민첩성 예는 무엇입니까?

- A. 여러 인스턴스 유형에 대한 액세스
- B. 관리형 서비스에 대한 액세스
- C. 통합 청구서를 사용하여 하나의 청구서 작성
- D. 새로운 컴퓨팅 리소스의 구입 시간 단축

**정답: D**

✅ **D. 새로운 컴퓨팅 리소스의 구입 시간 단축**: 클라우드 민첩성(Agility)의 핵심은 리소스를 필요할 때 즉시 프로비저닝할 수 있다는 점입니다. 온프레미스에서는 서버 구매에 수주~수개월이 걸리지만, AWS에서는 몇 분 안에 리소스를 시작할 수 있어 비즈니스 민첩성이 크게 향상됩니다.

❌ **A. 여러 인스턴스 유형에 대한 액세스**: 다양한 인스턴스 유형 제공은 유연성(Flexibility)에 가깝습니다. 민첩성의 핵심 개념과는 다릅니다.

❌ **B. 관리형 서비스에 대한 액세스**: 관리형 서비스는 운영 부담 감소(운영 효율성)와 관련된 이점으로, 민첩성의 정의와는 구별됩니다.

❌ **C. 통합 청구서를 사용하여 하나의 청구서 작성**: 이는 AWS Organizations의 통합 과금(Consolidated Billing) 기능으로, 비용 관리와 관련된 이점입니다.

💡 **시험 꿀팁**: AWS 민첩성(Agility) = 빠른 리소스 프로비저닝, 실패 비용 최소화, 빠른 실험 가능. "몇 주/몇 달 → 몇 분"으로 바뀌는 것이 민첩성의 핵심입니다.

## Q3. 다중 AWS 계정 중앙 관리

고객이 여러 AWS 계정을 통합하고 중앙에서 관리하기 위해 사용해야 하는 서비스는 무엇입니까?

- A. AWS IAM
- B. AWS Organizations
- C. AWS Schema Conversion Tool
- D. AWS Config

**정답: B**

✅ **B. AWS Organizations**: AWS Organizations는 여러 AWS 계정을 중앙에서 통합 관리할 수 있는 서비스입니다. 계정 그룹화(OU), 정책 기반 관리(SCP), 통합 과금 등의 기능을 제공하여 대규모 멀티 계정 환경을 효율적으로 운영할 수 있습니다.

❌ **A. AWS IAM**: IAM(Identity and Access Management)은 단일 AWS 계정 내에서 사용자, 역할, 권한을 관리하는 서비스입니다. 여러 계정을 통합 관리하는 기능은 없습니다.

❌ **C. AWS Schema Conversion Tool**: 이 도구는 데이터베이스 마이그레이션 시 스키마를 변환하는 용도로 사용됩니다. 계정 관리와는 무관합니다.

❌ **D. AWS Config**: Config는 AWS 리소스의 구성 변경을 추적하고 규정 준수를 평가하는 서비스입니다. 여러 계정을 통합하는 기능이 아닙니다.

💡 **시험 꿀팁**: 여러 계정 통합 관리 = AWS Organizations / 단일 계정 내 권한 관리 = IAM / 리소스 구성 추적 = AWS Config. "Organizations = 조직 전체 관리"로 기억하세요.

## Q4. 병렬 처리와 AWS 아키텍처 원칙

AWS 아키텍처 원칙을 준수하는 다수의 개별 비디오 파일을 변환하는 방법은 무엇입니까?

- A. 많은 인스턴스를 병렬로 사용
- B. 한가한 시간에 하나의 대형 인스턴스 사용
- C. 전용 하드웨어 사용
- D. 대형 GPU 인스턴스 유형 사용

**정답: A**

✅ **A. 많은 인스턴스를 병렬로 사용**: AWS Well-Architected Framework의 핵심 원칙 중 하나는 수평적 확장(Scale Horizontally)입니다. 다수의 비디오 파일을 변환할 때 여러 인스턴스를 병렬로 사용하면 처리 시간을 대폭 단축하고 효율성을 극대화할 수 있습니다.

❌ **B. 한가한 시간에 하나의 대형 인스턴스 사용**: 단일 대형 인스턴스에 모든 작업을 몰아서 처리하는 것은 수직 확장(Scale Up) 방식으로, AWS 클라우드 아키텍처 모범 사례에 부합하지 않습니다.

❌ **C. 전용 하드웨어 사용**: 전용 하드웨어는 특수한 규정 준수 요건이 있을 때 사용하며, 일반적인 작업에서 AWS 아키텍처 원칙의 모범 사례가 아닙니다.

❌ **D. 대형 GPU 인스턴스 유형 사용**: GPU 인스턴스는 머신러닝이나 그래픽 연산에 특화되어 있으며, 일반 비디오 변환 작업의 최적 솔루션은 병렬 처리입니다.

💡 **시험 꿀팁**: AWS 아키텍처 원칙 = 수평 확장(Scale Out) 선호 / "크게 하나" 보다 "작게 여럿"이 클라우드 모범 사례. 병렬처리 = 클라우드의 강점입니다.

## Q5. AWS가 전적으로 책임지는 감사 프로세스

AWS가 전적으로 책임지는 감사 프로세스는 무엇입니까?

- A. AWS IAM 정책
- B. 물리적 보안
- C. Amazon S3 버킷 정책
- D. AWS CloudTrail 로그

**정답: B**

✅ **B. 물리적 보안**: AWS 공유 책임 모델에서 AWS는 데이터센터의 물리적 보안에 대해 전적으로 책임집니다. 출입 통제, 감시 카메라, 보안 요원 등 물리적 인프라 보호는 고객이 접근하거나 감사할 수 없으며 AWS가 완전히 관리합니다.

❌ **A. AWS IAM 정책**: IAM 정책은 고객이 직접 생성하고 관리하는 책임입니다. 누가 무엇에 접근할 수 있는지 정의하는 것은 고객의 책임입니다.

❌ **C. Amazon S3 버킷 정책**: S3 버킷 정책도 고객이 설정하고 관리해야 하는 고객 책임 영역입니다. 잘못된 버킷 정책으로 인한 데이터 노출은 고객 책임입니다.

❌ **D. AWS CloudTrail 로그**: CloudTrail은 AWS API 호출을 기록하는 서비스이지만, 이를 활성화하고 로그를 관리하는 것은 고객의 책임입니다.

💡 **시험 꿀팁**: AWS 책임 = 물리적 보안, 하드웨어, 네트워크 인프라, 글로벌 인프라 / 고객 책임 = IAM 정책, 버킷 정책, 암호화, 애플리케이션. "클라우드의 보안(Security OF the Cloud)" = AWS 책임입니다.

## Q6. 국제 기업의 짧은 지연 시간 요구사항

AWS Cloud의 어떤 기능이 모든 고객에게 짧은 지연 시간을 요구하는 국제 기업의 요구사항을 지원합니까?

- A. 내결함성
- B. 글로벌 리치(Global Reach)
- C. 종량제 가격
- D. 고가용성

**정답: B**

✅ **B. 글로벌 리치(Global Reach)**: AWS는 전 세계 여러 리전(Region)과 엣지 로케이션(Edge Location)을 운영하고 있어, 사용자와 가까운 곳에 리소스를 배치하여 지연 시간을 최소화할 수 있습니다. 국제 기업이 전 세계 고객에게 빠른 서비스를 제공할 수 있는 것은 AWS의 글로벌 인프라 덕분입니다.

❌ **A. 내결함성**: 내결함성(Fault Tolerance)은 시스템 일부가 장애를 겪어도 서비스가 계속되는 능력입니다. 지연 시간 단축과는 직접적인 관계가 없습니다.

❌ **C. 종량제 가격**: 사용한 만큼만 비용을 지불하는 과금 방식으로, 지연 시간과는 무관합니다.

❌ **D. 고가용성**: 고가용성(High Availability)은 서비스 중단 없이 지속적으로 운영되는 능력입니다. 지연 시간을 줄이는 것과는 별개의 개념입니다.

💡 **시험 꿀팁**: 짧은 지연 시간(Low Latency) + 전 세계 사용자 = 글로벌 리치 / AWS 엣지 로케이션 = CloudFront CDN 사용 = 지연 시간 최소화. "국제/글로벌" 키워드가 보이면 글로벌 리치를 떠올리세요.

## Q7. 공유 책임 모델 - 고객 책임

다음 중 AWS 공유 책임 모델에서 고객의 책임은 무엇입니까?

- A. 기반 인프라 패치 적용
- B. 물리적 보안
- C. Amazon EC2 인스턴스 패치 적용
- D. 네트워크 인프라 패치 적용

**정답: C**

✅ **C. Amazon EC2 인스턴스 패치 적용**: 공유 책임 모델에서 EC2 인스턴스의 운영체제(OS) 패치 및 업데이트는 고객의 책임입니다. AWS는 EC2 서비스 자체(하이퍼바이저, 물리 서버)를 관리하지만, 그 위에서 실행되는 OS와 애플리케이션 관리는 고객이 담당합니다.

❌ **A. 기반 인프라 패치 적용**: 물리 서버, 네트워크 장비 등 기반 인프라의 패치는 AWS의 책임입니다.

❌ **B. 물리적 보안**: 데이터센터의 물리적 보안은 AWS가 전적으로 책임집니다.

❌ **D. 네트워크 인프라 패치 적용**: AWS 글로벌 네트워크 인프라의 패치는 AWS의 책임입니다. 고객이 설정한 보안 그룹이나 VPC 설정 관리는 고객 책임이지만, 인프라 자체 패치는 AWS 몫입니다.

💡 **시험 꿀팁**: EC2의 경우 "하이퍼바이저 아래 = AWS 책임 / OS 위 = 고객 책임"으로 기억하세요. 반면 RDS(관리형 DB)는 OS 패치도 AWS가 담당합니다.

## Q8. 볼륨 할인과 다중 계정 관리

고객이 별도의 청구와 함께 여러 AWS 계정을 사용하고 있습니다. 고객이 AWS 리소스에 미치는 영향을 최소화하면서 볼륨 할인을 활용하는 방법은 무엇입니까?

- A. 하나의 글로벌 AWS 계정을 만들고 모든 AWS 리소스를 해당 계정으로 이동합니다.
- B. 3년간의 예약 인스턴스 가격에 미리 가입합니다.
- C. AWS Organizations의 통합 과금 기능을 사용합니다.
- D. AWS Enterprise 지원 계획에 가입하여 볼륨 할인을 받으십시오.

**정답: C**

✅ **C. AWS Organizations의 통합 과금 기능을 사용합니다.**: AWS Organizations의 통합 과금(Consolidated Billing)을 사용하면 여러 계정의 사용량을 합산하여 볼륨 할인을 받을 수 있습니다. 각 계정의 독립성은 유지하면서 결제만 통합하므로, 기존 리소스에 영향 없이 비용을 절감할 수 있습니다.

❌ **A. 하나의 글로벌 AWS 계정으로 이동**: 모든 리소스를 하나의 계정으로 이동하면 기존 리소스에 큰 영향을 미칩니다. 이는 문제 조건("리소스 영향 최소화")에 위배됩니다.

❌ **B. 3년간의 예약 인스턴스 가격에 미리 가입**: 예약 인스턴스는 장기 약정을 통한 할인이지, 볼륨 할인과는 다른 개념입니다. 여러 계정 통합과도 무관합니다.

❌ **D. AWS Enterprise 지원 계획에 가입**: Enterprise Support는 기술 지원 서비스이며, 볼륨 할인을 제공하는 서비스가 아닙니다.

💡 **시험 꿀팁**: 통합 과금(Consolidated Billing) = 여러 계정 사용량 합산 → 볼륨 할인 + 계정 독립성 유지 + 단일 청구서. AWS Organizations의 대표적인 이점으로 시험에 자주 출제됩니다.

## Q9. AWS 관리형 DNS 서비스

다음 중 AWS 관리 DNS(Domain Name System) 웹 서비스는 무엇입니까?

- A. Amazon Route 53
- B. Amazon Neptune
- C. Amazon SageMaker
- D. Amazon Ray

**정답: A**

✅ **A. Amazon Route 53**: Route 53은 AWS의 완전 관리형 DNS(Domain Name System) 웹 서비스입니다. 도메인 이름을 IP 주소로 변환하는 DNS 기능 외에도 도메인 등록, 상태 확인(Health Check), 트래픽 라우팅 등의 기능을 제공합니다.

❌ **B. Amazon Neptune**: Neptune은 AWS의 완전 관리형 그래프 데이터베이스 서비스입니다. DNS와는 전혀 무관합니다.

❌ **C. Amazon SageMaker**: SageMaker는 머신러닝 모델을 구축, 훈련, 배포하기 위한 완전 관리형 ML 플랫폼입니다. DNS 서비스가 아닙니다.

❌ **D. Amazon Ray**: 실제 AWS 서비스가 아닌 오답 보기입니다. AWS에는 Ray라는 서비스가 없습니다.

💡 **시험 꿀팁**: Route 53 = DNS + 도메인 등록 + 라우팅 정책(단순/가중치/장애조치/지리적). 이름의 유래: DNS는 포트 53번을 사용하기 때문에 "Route 53"입니다.

## Q10. AWS 리전 선택 요소

고객이 새 애플리케이션을 배포하고 있으며 AWS 리전을 선택해야 합니다. 다음 중 고객의 결정에 영향을 미칠 수 있는 요소는 무엇입니까? (두 개를 선택합니다.)

- A. 사용자 대기 시간 단축
- B. 응용 프로그램의 현지 언어 프레젠테이션
- C. 데이터 주권 준수
- D. 더 더운 기후에서의 냉각 비용
- E. 현장 방문을 위한 고객 사무실과의 근접성

**정답: A, C**

✅ **A. 사용자 대기 시간 단축**: 사용자와 가까운 리전을 선택하면 네트워크 지연 시간(Latency)을 줄일 수 있습니다. 이는 리전 선택의 핵심 기준 중 하나입니다.

✅ **C. 데이터 주권 준수**: 일부 국가는 개인정보나 민감한 데이터가 자국 내에 저장되어야 한다는 법적 요건(데이터 레지던시/주권)이 있습니다. 규정 준수를 위해 특정 리전을 선택해야 할 수 있습니다.

❌ **B. 응용 프로그램의 현지 언어 프레젠테이션**: 애플리케이션의 언어는 소프트웨어 레벨에서 구현하는 것으로, 리전 선택과는 무관합니다.

❌ **D. 더 더운 기후에서의 냉각 비용**: 데이터센터 냉각 비용은 AWS가 관리하는 영역이며, 고객이 리전을 선택할 때 고려하는 요소가 아닙니다.

❌ **E. 현장 방문을 위한 고객 사무실과의 근접성**: AWS 리전의 물리적 위치를 고객이 직접 방문하는 것은 일반적이지 않으며, 리전 선택 기준이 아닙니다.

💡 **시험 꿀팁**: AWS 리전 선택 4대 기준 = ① 지연 시간(사용자 근접성) ② 데이터 규정 준수(법적 요건) ③ 서비스 가용성(일부 서비스는 특정 리전만 제공) ④ 비용(리전마다 가격 차이). 시험에서 두 가지 고르라면 지연 시간 + 규정 준수가 정답인 경우가 많습니다.

## Q11. 정적 웹사이트 호스팅을 위한 스토리지

정적 웹 사이트를 호스팅하기 위한 경제적인 옵션으로 사용할 수 있는 스토리지 서비스는 무엇입니까?

- A. Amazon Glacier
- B. Amazon DynamoDB
- C. Amazon Elastic File System(Amazon EFS)
- D. Amazon Simple Storage Service(Amazon S3)

**정답: D**

✅ **D. Amazon S3**: Amazon S3는 정적 웹사이트(HTML, CSS, JavaScript, 이미지 등 정적 파일) 호스팅을 기본 기능으로 제공하며, 매우 저렴한 비용으로 사용할 수 있습니다. S3 버킷에 정적 웹사이트 호스팅을 활성화하면 별도의 웹 서버 없이 웹사이트를 운영할 수 있습니다.

❌ **A. Amazon Glacier**: Glacier(현재 S3 Glacier)는 장기 아카이브 및 백업을 위한 저비용 스토리지 서비스입니다. 데이터 검색에 시간이 걸려 웹 호스팅에 적합하지 않습니다.

❌ **B. Amazon DynamoDB**: DynamoDB는 NoSQL 데이터베이스 서비스로, 스토리지나 웹 호스팅 서비스가 아닙니다.

❌ **C. Amazon EFS**: EFS는 EC2 인스턴스에 마운트하는 네트워크 파일 시스템(NFS)으로, 정적 웹사이트 호스팅에 직접 사용하지 않습니다.

💡 **시험 꿀팁**: S3 = 정적 웹사이트 호스팅 + 객체 스토리지 + 글로벌 + 내구성 99.999999999% (11 9s). 정적 = HTML/CSS/JS 파일, 동적 = EC2나 Lambda가 필요합니다.

## Q12. 최대 90% 할인 EC2 가격 모델

다음 중 최대 90% 할인을 제공하는 Amazon EC2 인스턴스 가격 모델은 무엇입니까?

- A. 예약 인스턴스(Reserved Instances)
- B. 온디맨드(On-Demand)
- C. 전용 호스트(Dedicated Hosts)
- D. 스팟 인스턴스(Spot Instances)

**정답: D**

✅ **D. 스팟 인스턴스(Spot Instances)**: 스팟 인스턴스는 AWS의 여유 컴퓨팅 용량을 활용하는 방식으로, 온디맨드 대비 최대 90%까지 저렴하게 사용할 수 있습니다. 단, AWS가 필요할 때 인스턴스를 회수할 수 있어 중단이 허용되는 워크로드에 적합합니다.

❌ **A. 예약 인스턴스**: 1년 또는 3년 약정을 통해 최대 72%까지 할인받을 수 있습니다. 90% 할인은 스팟 인스턴스의 특징입니다.

❌ **B. 온디맨드**: 약정 없이 사용한 만큼 지불하는 기본 가격 모델로, 할인이 없습니다.

❌ **C. 전용 호스트**: 전용 물리 서버를 단독으로 사용하는 방식으로, 오히려 비용이 더 많이 드는 옵션입니다.

💡 **시험 꿀팁**: 스팟(Spot) = 최대 90% 할인 + 중단 가능한 워크로드 / 예약(Reserved) = 최대 72% 할인 + 1~3년 약정 / 온디맨드(On-Demand) = 할인 없음 + 유연성 최대. "90%"라는 숫자가 나오면 무조건 스팟 인스턴스입니다.

## Q13. 공유 책임 모델 - 고객 데이터 보안

AWS 공유 책임 모델에 따라 AWS 고객은 무엇을 책임집니까?

- A. 물리적 접근 제어
- B. 데이터 암호화
- C. 저장 장치의 안전한 폐기
- D. 환경 위험 관리

**정답: B**

✅ **B. 데이터 암호화**: 데이터 암호화(저장 중 암호화 및 전송 중 암호화)는 고객의 책임입니다. AWS는 암호화 도구(KMS, S3 서버 측 암호화 등)를 제공하지만, 이를 적용하고 암호화 키를 관리하는 것은 고객이 결정합니다.

❌ **A. 물리적 접근 제어**: 데이터센터의 물리적 접근 통제는 AWS가 담당합니다. 고객은 물리적 시설에 접근할 수 없습니다.

❌ **C. 저장 장치의 안전한 폐기**: 하드 드라이브 등 물리적 저장 장치의 안전한 폐기(데이터 완전 삭제 후 폐기)는 AWS의 책임입니다.

❌ **D. 환경 위험 관리**: 데이터센터의 화재, 홍수 등 환경적 위험 관리는 AWS가 책임집니다.

💡 **시험 꿀팁**: 공유 책임 모델 핵심 구분 - AWS(클라우드 자체의 보안): 물리적 보안, 하드웨어 폐기, 환경 관리 / 고객(클라우드 내에서의 보안): 데이터 암호화, IAM 설정, OS 패치, 방화벽 규칙.

## Q14. 고객 관리형 관계형 데이터베이스

다음 중 고객이 관리하는 관계형 데이터베이스를 실행하는 데 사용할 수 있는 AWS 클라우드 서비스는 무엇입니까?

- A. Amazon EC2
- B. Amazon Route 53
- C. Amazon ElastiCache
- D. Amazon DynamoDB

**정답: A**

✅ **A. Amazon EC2**: EC2 인스턴스에 직접 MySQL, PostgreSQL, Oracle 등 관계형 데이터베이스 소프트웨어를 설치하고 운영할 수 있습니다. 이 방식은 고객이 OS부터 DB까지 모든 것을 직접 관리하는 "고객 관리형" 방식입니다.

❌ **B. Amazon Route 53**: Route 53은 DNS 서비스이며 데이터베이스와 무관합니다.

❌ **C. Amazon ElastiCache**: ElastiCache는 Redis 또는 Memcached 기반의 인메모리 캐싱 서비스로, 관계형 데이터베이스가 아닙니다.

❌ **D. Amazon DynamoDB**: DynamoDB는 NoSQL 데이터베이스 서비스로, 관계형(SQL) 데이터베이스가 아닙니다.

💡 **시험 꿀팁**: "고객이 직접 관리" = EC2에 직접 설치 / "AWS가 관리" = RDS(관리형 관계형 DB). EC2는 최대 제어권, RDS는 편의성과 자동화가 장점입니다.

## Q15. 확장 가능한 데이터 웨어하우스

한 회사가 확장 가능한 데이터 웨어하우스 솔루션을 찾고 있습니다. 다음 중 회사의 요구를 충족하는 AWS 솔루션은 무엇입니까?

- A. Amazon Simple Storage Service(Amazon S3)
- B. Amazon DynamoDB
- C. Amazon Kinesis
- D. Amazon Redshift

**정답: D**

✅ **D. Amazon Redshift**: Redshift는 페타바이트 규모까지 확장 가능한 완전 관리형 클라우드 데이터 웨어하우스 서비스입니다. 대용량 데이터 분석에 최적화된 컬럼형 스토리지와 병렬 처리를 통해 빠른 쿼리 성능을 제공합니다.

❌ **A. Amazon S3**: S3는 객체 스토리지 서비스로 데이터 레이크로 활용할 수 있지만, 데이터 웨어하우스 기능을 갖춘 서비스는 아닙니다.

💡 **시험 꿀팁**: 데이터 웨어하우스 = Redshift / 실시간 스트리밍 = Kinesis / NoSQL DB = DynamoDB / 객체 스토리지 = S3. "데이터 웨어하우스", "BI(비즈니스 인텔리전스)", "분석 쿼리" 키워드가 보이면 Redshift입니다.

## Q16. Elastic Load Balancing 설명

다음 중 Elastic Load Balancing을 가장 잘 설명한 것은 무엇입니까?

- A. DNS를 사용하여 도메인 이름을 IP 주소로 변환합니다.
- B. 들어오는 애플리케이션 트래픽을 하나 이상의 Amazon EC2 인스턴스에 분산시킵니다.
- C. 연결된 Amazon EC2 인스턴스에서 메트릭을 수집합니다.
- D. 들어오는 트래픽을 지원하기 위해 자동으로 Amazon EC2 인스턴스 수를 조정합니다.

**정답: B**

✅ **B. 들어오는 애플리케이션 트래픽을 하나 이상의 Amazon EC2 인스턴스에 분산시킵니다.**: ELB(Elastic Load Balancing)의 핵심 기능은 수신 트래픽을 여러 EC2 인스턴스에 균등하게 분배하여 단일 인스턴스에 부하가 집중되는 것을 방지하는 것입니다. 이를 통해 가용성과 내결함성을 향상시킵니다.

❌ **A. DNS를 사용하여 도메인 이름을 IP 주소로 변환**: 이는 Amazon Route 53(DNS 서비스)의 기능입니다.

❌ **C. 연결된 EC2 인스턴스에서 메트릭을 수집**: 이는 Amazon CloudWatch의 기능입니다. CloudWatch가 CPU 사용률, 네트워크 트래픽 등의 메트릭을 수집합니다.

❌ **D. 자동으로 EC2 인스턴스 수를 조정**: 이는 Auto Scaling의 기능입니다. ELB는 트래픽을 분산하고, Auto Scaling은 인스턴스 수를 자동 조정합니다.

💡 **시험 꿀팁**: ELB(로드 밸런서) = 트래픽 분산 / Auto Scaling = 인스턴스 수 자동 조정 / CloudWatch = 모니터링 및 메트릭 수집 / Route 53 = DNS. 이 4가지는 자주 혼동되므로 반드시 구분하세요.

## Q17. AWS 서비스 상호작용 방법

다음 중 고객이 AWS 서비스와 상호 작용할 수 있는 유효한 방법은 무엇입니까? (두 개를 선택합니다.)

- A. 명령줄 인터페이스(CLI)
- B. 사내(On-premises)
- C. 소프트웨어 개발 키트(SDK)
- D. SaaS(Software-as-a-Service)
- E. 하이브리드(Hybrid)

**정답: A, C**

✅ **A. 명령줄 인터페이스(CLI)**: AWS CLI(Command Line Interface)는 터미널/명령 프롬프트에서 AWS 서비스를 제어할 수 있는 도구입니다. 스크립트 자동화와 배치 작업에 유용합니다.

✅ **C. 소프트웨어 개발 키트(SDK)**: AWS SDK는 Python(boto3), Java, JavaScript, Go 등 다양한 프로그래밍 언어로 AWS 서비스를 프로그래밍 방식으로 제어할 수 있는 라이브러리 모음입니다.

❌ **B. 사내(On-premises)**: 사내(온프레미스)는 AWS 서비스와 상호작용하는 방법이 아니라, 자체 데이터센터 환경을 의미합니다.

❌ **D. SaaS**: SaaS는 클라우드 서비스 제공 모델 중 하나로, AWS와 상호작용하는 방법이 아닙니다.

❌ **E. 하이브리드**: 하이브리드는 온프레미스와 클라우드를 혼합한 아키텍처 방식으로, AWS 서비스 접근 방법이 아닙니다.

💡 **시험 꿀팁**: AWS 서비스 접근 방법 3가지 = ① AWS Management Console(웹 GUI) ② AWS CLI(명령줄) ③ AWS SDK(프로그래밍). 시험에서 이 3가지를 꼭 기억하세요.

## Q18. AWS 다중 가용 영역(Multi-AZ)의 예

AWS Cloud의 다중 영역은 다음과 같은 예입니다.

- A. 민첩성(Agility)
- B. 글로벌 인프라(Global Infrastructure)
- C. 탄력성(Elasticity)
- D. 종량제 가격(Pay-as-you-go)

**정답: B**

✅ **B. 글로벌 인프라(Global Infrastructure)**: AWS의 다중 가용 영역(Multiple Availability Zones)은 AWS 글로벌 인프라의 핵심 구성 요소입니다. 각 리전 내에 물리적으로 분리된 여러 개의 가용 영역이 존재하며, 이는 AWS의 글로벌 인프라 설계의 예입니다.

❌ **A. 민첩성(Agility)**: 민첩성은 빠른 리소스 프로비저닝과 실험 가능성에 관한 개념으로, 다중 AZ와는 직접적인 관련이 없습니다.

❌ **C. 탄력성(Elasticity)**: 탄력성은 수요에 따라 리소스를 자동으로 늘리거나 줄이는 능력입니다. 다중 AZ는 가용성과 관련된 인프라 설계입니다.

❌ **D. 종량제 가격**: 사용한 만큼만 지불하는 AWS 과금 방식으로, 다중 AZ와는 무관합니다.

💡 **시험 꿀팁**: AWS 글로벌 인프라 구성 = 리전(Region) > 가용 영역(AZ) > 엣지 로케이션(Edge Location). 다중 AZ = 고가용성 및 내결함성 구현을 위한 글로벌 인프라의 핵심 설계입니다.

## Q19. 낮은 지연 시간의 비디오 콘텐츠 서비스

다음 AWS 서비스 중 지연 시간이 가장 짧은 대량의 온라인 비디오 콘텐츠를 서비스하는 데 사용할 수 있는 서비스는 무엇입니까? (두 개를 선택합니다.)

- A. AWS Storage Gateway
- B. Amazon S3
- C. Amazon EFS(Elastic File System)
- D. Amazon Glacier
- E. Amazon CloudFront

**정답: B, E**

✅ **B. Amazon S3**: S3는 비디오 파일 등 대용량 미디어 콘텐츠를 저장하기에 적합한 객체 스토리지 서비스입니다. 높은 내구성과 가용성을 제공하며, 대규모 미디어 스토리지 솔루션의 기반으로 사용됩니다.

✅ **E. Amazon CloudFront**: CloudFront는 AWS의 CDN(Content Delivery Network) 서비스로, 전 세계 엣지 로케이션을 통해 사용자와 가까운 곳에서 콘텐츠를 제공하여 지연 시간을 최소화합니다. 비디오 스트리밍에 최적화된 서비스입니다.

❌ **A. AWS Storage Gateway**: Storage Gateway는 온프레미스 환경과 AWS 클라우드 스토리지를 연결하는 하이브리드 스토리지 서비스입니다. 콘텐츠 배포에 적합하지 않습니다.

❌ **C. Amazon EFS**: EFS는 EC2 인스턴스용 네트워크 파일 시스템으로, 대규모 비디오 콘텐츠 배포에 최적화되어 있지 않습니다.

❌ **D. Amazon Glacier**: Glacier는 장기 아카이브용 스토리지로 데이터 검색에 수분~수시간이 걸립니다. 실시간 비디오 서비스에 전혀 적합하지 않습니다.

💡 **시험 꿀팁**: 비디오 콘텐츠 배포 = S3(저장) + CloudFront(배포/CDN). CloudFront = 엣지 로케이션을 통한 지연 시간 최소화 + 전 세계 빠른 콘텐츠 전달. "낮은 지연 시간 + 대용량 콘텐츠 = CloudFront" 공식을 기억하세요.

## Q20. 하이브리드 아키텍처

Amazon EC2에서 실행되는 웹 서버는 회사 데이터 센터에서 실행되는 레거시 애플리케이션에 액세스합니다. 이 모델을 설명하는 용어는 무엇입니까?

- A. 클라우드 네이티브(Cloud Native)
- B. 파트너 네트워크(Partner Network)
- C. 하이브리드 아키텍처(Hybrid Architecture)
- D. 서비스형 인프라(IaaS)

**정답: C**

✅ **C. 하이브리드 아키텍처(Hybrid Architecture)**: 하이브리드 아키텍처는 클라우드(AWS)와 온프레미스(회사 데이터 센터) 환경이 함께 사용되는 구성입니다. EC2의 웹 서버가 자사 데이터센터의 레거시 앱에 접근하는 시나리오가 정확히 하이브리드의 예입니다.

❌ **A. 클라우드 네이티브**: 클라우드 네이티브는 모든 구성 요소가 클라우드 환경에서 실행되도록 설계된 아키텍처입니다. 온프레미스 레거시 애플리케이션이 포함된 이 시나리오는 클라우드 네이티브가 아닙니다.

❌ **B. 파트너 네트워크**: AWS 파트너 네트워크(APN)는 AWS와 협력하는 IT 기업들의 생태계를 의미하며, 아키텍처 모델이 아닙니다.

❌ **D. 서비스형 인프라(IaaS)**: IaaS는 가상 서버, 스토리지, 네트워크 등 인프라를 서비스로 제공하는 클라우드 서비스 모델입니다. 특정 아키텍처 패턴을 설명하는 용어가 아닙니다.

💡 **시험 꿀팁**: 클라우드 + 온프레미스 = 하이브리드(Hybrid) / 100% 클라우드 = 클라우드 네이티브 / 온프레미스만 = 레거시. AWS Direct Connect나 AWS VPN은 하이브리드 아키텍처를 구현하는 대표적인 서비스입니다.
