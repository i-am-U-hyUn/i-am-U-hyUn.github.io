## Q1. Amazon VPC 대시보드에서 구성 가능한 기능 (2개 선택)

Amazon VPC(Virtual Private Cloud) 대시보드를 통해 구성할 수 있는 기능은 무엇입니까? (2개 선택)

- A. Amazon CloudFront 배포
- B. Amazon Route 53
- C. Security Groups
- D. Subnets
- E. Elastic Load Balancing

**정답: C, D**

✅ **C. Security Groups**: 보안 그룹은 EC2 인스턴스의 가상 방화벽 역할을 하는 VPC의 핵심 네트워킹 기능입니다. VPC 대시보드에서 인바운드 및 아웃바운드 트래픽을 제어하는 규칙을 직접 구성할 수 있습니다.

✅ **D. Subnets**: 서브넷은 VPC 내에서 IP 주소 범위를 분할하는 구성 요소로, VPC 대시보드에서 직접 생성하고 관리합니다.

❌ **A. Amazon CloudFront 배포**: CloudFront는 별도의 CDN 서비스로, 자체 콘솔에서 관리하며 VPC 대시보드와는 독립적입니다.

❌ **B. Amazon Route 53**: Route 53은 DNS 및 도메인 등록 서비스로, VPC 대시보드와 별도로 독립적으로 관리됩니다.

❌ **E. Elastic Load Balancing**: ELB는 EC2 콘솔 또는 전용 콘솔 섹션에서 구성하며, VPC 대시보드를 통해 직접 관리하지 않습니다.

💡 **시험 꿀팁**: VPC 대시보드에서 관리하는 항목 = 서브넷, 라우팅 테이블, 인터넷 게이트웨이, NAT 게이트웨이, 보안 그룹, 네트워크 ACL. CloudFront, Route 53, ELB는 별도 서비스 콘솔에서 관리합니다.

## Q2. AWS 계정 활동 정보 수집 서비스 (2개 선택)

AWS 계정 활동에 대한 정보를 수집하는 데 사용할 수 있는 AWS 서비스는 무엇입니까? (2개 선택)

- A. Amazon CloudFront
- B. AWS Cloud9
- C. AWS CloudTrail
- D. AWS CloudHSM
- E. Amazon CloudWatch

**정답: C, E**

✅ **C. AWS CloudTrail**: CloudTrail은 AWS 인프라 전반의 모든 API 호출 및 계정 활동을 기록하여, 누가 언제 어디서 무엇을 했는지에 대한 완전한 감사 추적을 제공합니다.

✅ **E. Amazon CloudWatch**: CloudWatch는 AWS 리소스의 지표, 로그, 이벤트를 포함한 운영 데이터를 수집하고 모니터링하여 계정 및 애플리케이션 활동을 실시간으로 관찰할 수 있게 합니다.

❌ **A. Amazon CloudFront**: CloudFront는 콘텐츠를 전 세계에 캐싱하고 전달하는 CDN 서비스로, 계정 활동 정보를 수집하지 않습니다.

❌ **B. AWS Cloud9**: Cloud9은 코드를 작성하고 디버깅하는 클라우드 기반 IDE이며, 모니터링 또는 로깅 서비스가 아닙니다.

❌ **D. AWS CloudHSM**: CloudHSM은 키 관리 및 암호화에 사용되는 하드웨어 보안 모듈 서비스이며, 계정 활동 모니터링과는 관계가 없습니다.

💡 **시험 꿀팁**: CloudTrail = 누가 무엇을 했는지(API 감사 로그) | CloudWatch = 지금 무슨 일이 일어나고 있는지(지표, 로그, 알람). 이 두 서비스는 시험에서 자주 등장하는 모니터링 쌍입니다.

## Q3. AWS 엣지 로케이션 활용 방법 (2개 선택)

AWS 엣지 로케이션을 어떤 용도로 활용할 수 있습니까? (2개 선택)

- A. 애플리케이션 호스팅
- B. 사용자에게 더 가까운 위치에서 콘텐츠 전달
- C. NoSQL 데이터베이스 캐싱 서비스 실행
- D. 응답을 캐싱하여 서버 트래픽 감소
- E. 최종 사용자에게 알림 메시지 전송

**정답: B, D**

✅ **B. 사용자에게 더 가까운 위치에서 콘텐츠 전달**: AWS 엣지 로케이션은 Amazon CloudFront 네트워크의 일부입니다. 최종 사용자와 지리적으로 가까운 위치에 콘텐츠 캐시 사본을 저장하여 지연 시간을 줄입니다.

✅ **D. 응답을 캐싱하여 서버 트래픽 감소**: 엣지에서 응답을 캐싱함으로써 원본 서버까지 이동해야 하는 요청 수를 줄여 부하를 낮추고 성능을 향상시킵니다.

❌ **A. 애플리케이션 호스팅**: 엣지 로케이션은 전체 애플리케이션을 호스팅하지 않습니다. 완전한 애플리케이션 호스팅은 EC2, ECS, Lambda 등이 있는 AWS 리전이 필요합니다.

❌ **C. NoSQL 데이터베이스 캐싱 서비스 실행**: ElastiCache와 같은 서비스는 엣지 로케이션이 아닌 AWS 리전에서 실행됩니다.

❌ **E. 최종 사용자에게 알림 메시지 전송**: 푸시 알림은 Amazon SNS와 같은 서비스가 처리하며, 엣지 로케이션이 담당하지 않습니다.

💡 **시험 꿀팁**: 엣지 로케이션 = CloudFront CDN 캐싱 + AWS Global Accelerator 라우팅. 리전이나 가용 영역과 동일하지 않으며, 짧은 지연 시간 콘텐츠 전달을 위한 PoP(접속 지점)입니다.

## Q4. AWS IAM 액세스 키의 용도

AWS IAM(Identity and Access Management) 액세스 키는 어떤 용도로 사용됩니까?

- A. AWS 관리 콘솔에 로그인
- B. AWS API를 통해 AWS에 프로그래밍 방식으로 호출
- C. Amazon EC2 인스턴스에 로그인
- D. AWS CodeCommit 리포지토리 인증

**정답: B**

✅ **B. AWS API를 통해 AWS에 프로그래밍 방식으로 호출**: IAM 액세스 키(액세스 키 ID + 시크릿 액세스 키)는 개발자, CLI 도구, 애플리케이션이 API 또는 SDK를 통해 AWS 서비스에 프로그래밍 방식으로 요청을 인증할 때 사용하는 자격 증명입니다.

❌ **A. AWS 관리 콘솔에 로그인**: 콘솔 로그인은 사용자 이름과 비밀번호(및 선택적 MFA)를 사용하며, 액세스 키를 사용하지 않습니다.

❌ **C. Amazon EC2 인스턴스에 로그인**: EC2 인스턴스는 SSH 키 페어(Linux) 또는 RDP 자격 증명(Windows)으로 접근하며, IAM 액세스 키를 사용하지 않습니다.

❌ **D. AWS CodeCommit 리포지토리 인증**: CodeCommit은 표준 IAM 액세스 키가 아닌 CodeCommit 전용으로 생성된 Git 자격 증명 또는 SSH 키를 사용합니다.

💡 **시험 꿀팁**: IAM 액세스 키 = CLI / SDK / API 프로그래밍 방식 접근 전용. 콘솔 = 사용자 이름 + 비밀번호. EC2 = SSH 키 페어. 이 세 가지 인증 방법을 혼동하지 마세요.

## Q5. 글로벌 기업의 AWS 클라우드 이점 (2개 선택)

전 세계 여러 국가에서 AWS 클라우드를 사용하는 회사의 이점은 무엇입니까? (2개 선택)

- A. 회사는 여러 AWS 리전에 애플리케이션을 배포하여 지연 시간을 줄일 수 있습니다.
- B. Amazon Translate는 타사 웹사이트 인터페이스를 여러 언어로 자동 변환합니다.
- C. Amazon CloudFront는 전 세계에 여러 엣지 로케이션을 보유하여 지연 시간을 줄입니다.
- D. Amazon Comprehend를 통해 사용자는 다양한 언어로 고객 요청에 응답하는 애플리케이션을 구축할 수 있습니다.
- E. Elastic Load Balancing은 지연 시간을 줄이기 위해 전 세계 여러 AWS 리전에 걸쳐 애플리케이션 웹 트래픽을 분산합니다.

**정답: A, C**

✅ **A. 여러 AWS 리전에 배포하여 지연 시간 감소**: 전 세계 사용자와 가까운 리전에서 애플리케이션을 실행하면 글로벌 고객의 왕복 지연 시간을 대폭 줄일 수 있습니다.

✅ **C. Amazon CloudFront 엣지 로케이션으로 글로벌 지연 시간 감소**: CloudFront의 전 세계 엣지 로케이션 네트워크는 최종 사용자 가까이에 콘텐츠를 캐싱하여 데이터가 이동해야 하는 거리를 줄이고 지연 시간을 낮춥니다.

❌ **B. Amazon Translate의 타사 웹사이트 자동 변환**: Amazon Translate는 자신의 애플리케이션 내 텍스트를 번역하며, 타사 웹사이트 인터페이스를 자동으로 변환하지 않습니다.

❌ **D. Amazon Comprehend의 다국어 고객 응답**: Comprehend는 텍스트 분석(감정, 개체 등)을 위한 자연어 처리 서비스이며, 다국어 응답 애플리케이션 구축에 특화되어 있지 않습니다.

❌ **E. ELB의 여러 리전 간 트래픽 분산**: Elastic Load Balancing은 단일 리전 및 VPC 내에서만 동작합니다. 여러 리전에 걸쳐 트래픽을 분산하지 않으며, 이 기능은 Route 53 또는 Global Accelerator가 담당합니다.

💡 **시험 꿀팁**: 글로벌 지연 시간 감소 = 다중 리전 배포 + CloudFront 엣지 로케이션. ELB는 단일 리전에서만 동작합니다. 리전 간 트래픽 관리는 Route 53 또는 AWS Global Accelerator를 사용하세요.

## Q6. 용량, 로드 밸런싱, Auto Scaling, 상태 모니터링을 처리하는 서비스

용량 프로비저닝, 로드 밸런싱, Auto Scaling, 애플리케이션 상태 모니터링의 구현 세부 사항을 처리하는 AWS 서비스는 무엇입니까?

- A. AWS Config
- B. AWS Elastic Beanstalk
- C. Amazon Route 53
- D. Amazon CloudFront

**정답: B**

✅ **B. AWS Elastic Beanstalk**: Elastic Beanstalk는 PaaS(Platform as a Service)로, 용량 프로비저닝, 로드 밸런싱, Auto Scaling, 애플리케이션 상태 모니터링을 포함한 인프라를 자동으로 처리합니다. 개발자는 코드 작성에만 집중할 수 있습니다.

❌ **A. AWS Config**: Config는 규정 준수 및 감사를 위해 AWS 리소스 구성을 기록하고 평가하는 서비스이며, 애플리케이션 인프라 프로비저닝을 관리하지 않습니다.

❌ **C. Amazon Route 53**: Route 53은 DNS 및 도메인 이름 관리 서비스이며, 애플리케이션 배포 플랫폼이 아닙니다.

❌ **D. Amazon CloudFront**: CloudFront는 콘텐츠 전달을 위한 CDN 서비스이며, 애플리케이션 호스팅 또는 스케일링 플랫폼이 아닙니다.

💡 **시험 꿀팁**: Elastic Beanstalk = PaaS. 코드를 업로드하면 AWS가 나머지를 처리합니다(EC2, ELB, Auto Scaling, 모니터링). 핵심 키워드: "구현 세부 사항 처리" 또는 "코드만 업로드하면 됩니다".

## Q7. EC2 인바운드 및 아웃바운드 네트워크 ACL을 제공하는 서비스

Amazon EC2에 대한 외부 연결을 강화하기 위해 인바운드 및 아웃바운드 네트워크 ACL을 제공하는 AWS 서비스는 무엇입니까?

- A. AWS IAM
- B. Amazon Connect
- C. Amazon VPC
- D. Amazon API Gateway

**정답: C**

✅ **C. Amazon VPC**: Amazon VPC는 서브넷 수준에서 스테이트리스 방화벽 역할을 하는 네트워크 액세스 제어 목록(NACL)을 제공하여 EC2 인스턴스를 포함한 서브넷으로의 인바운드 및 아웃바운드 트래픽을 제어합니다.

❌ **A. AWS IAM**: IAM은 AWS 서비스 및 리소스에 대한 ID와 액세스 권한을 관리하며, 네트워크 수준 트래픽 필터링을 제공하지 않습니다.

❌ **B. Amazon Connect**: Amazon Connect는 고객 커뮤니케이션을 위한 클라우드 기반 콜센터 서비스로, 네트워크 ACL과 전혀 관련이 없습니다.

❌ **D. Amazon API Gateway**: API Gateway는 API를 생성, 관리, 보안하기 위한 서비스이며, EC2 인스턴스에 네트워크 ACL을 제공하지 않습니다.

💡 **시험 꿀팁**: 네트워크 ACL(NACL) = VPC 내 서브넷 수준의 스테이트리스 방화벽. 보안 그룹 = 인스턴스 수준의 스테이트풀 방화벽. 두 기능 모두 VPC 기능입니다. NACL은 번호 순서대로 규칙을 평가합니다.

## Q8. 여러 AWS 리전에 웹 서버를 프로비저닝할 때 증가하는 것

회사가 여러 AWS 리전에 웹 서버를 프로비저닝하면 무엇이 증가합니까?

- A. 결합도(Coupling)
- B. 가용성(Availability)
- C. 보안(Security)
- D. 내구성(Durability)

**정답: B**

✅ **B. 가용성**: 여러 AWS 리전에 웹 서버를 배포하면 한 리전에서 장애가 발생해도 다른 리전에서 사용자에게 서비스를 제공할 수 있어 전반적인 애플리케이션 가용성이 크게 향상됩니다.

❌ **A. 결합도**: 결합도는 컴포넌트 간 의존성 정도를 의미합니다. 다중 리전 배포는 고가용성 전략이며, 결합도와는 직접적인 관련이 없습니다. 오히려 좋은 클라우드 아키텍처는 느슨한 결합을 추구합니다.

❌ **C. 보안**: 여러 리전에 서버를 프로비저닝한다고 해서 자동으로 보안이 향상되지는 않습니다.

❌ **D. 내구성**: 내구성은 데이터의 장기적인 보존(예: S3의 11 9's 내구성)을 의미합니다. 여러 리전에 웹 서버를 프로비저닝하는 것은 가용성에 관한 것이지 데이터 내구성이 아닙니다.

💡 **시험 꿀팁**: 다중 리전 = 고가용성 + 재해 복구. 리전 내 다중 AZ = 내결함성. 내구성 = 데이터 지속성(S3). 가용성, 내구성, 내결함성의 차이를 명확히 구분하세요.

## Q9. AWS 종량제 요금 모델의 이점 (2개 선택)

다음 중 AWS 종량제 요금 모델의 이점은 무엇입니까? (2개 선택)

- A. 자본 지출 감소
- B. AWS 서비스에 대한 선불 결제 필요
- C. Amazon EC2, Amazon S3, Amazon RDS에만 적용
- D. 운영 비용 감소

**정답: A, D**

✅ **A. 자본 지출(CapEx) 감소**: 종량제 방식을 사용하면 물리적 하드웨어를 구매하고 유지 관리하는 데 필요한 대규모 초기 투자가 필요 없어집니다. 자본 지출이 가변적인 운영 지출로 전환됩니다.

✅ **D. 운영 비용 감소**: 실제 사용한 만큼만 비용을 지불하므로, 유휴 또는 과잉 프로비저닝된 온프레미스 인프라와 관련된 비용이 사라집니다.

❌ **B. AWS 서비스에 대한 선불 결제 필요**: 종량제는 선불 약정 없이 소비한 만큼만 지불하는 것을 의미합니다. 선불 결제는 예약 인스턴스나 Savings Plans에 해당하며, 기본 모델이 아닙니다.

❌ **C. EC2, S3, RDS에만 적용**: AWS 종량제 요금은 세 가지 서비스에 국한되지 않고 사실상 모든 AWS 서비스에 적용됩니다.

💡 **시험 꿀팁**: AWS 종량제 = 선불 비용 없음 + 장기 계약 없음 + 사용한 만큼만 지불 = CapEx에서 OpEx로 전환. 이것은 CLF-C02 시험에서 가장 기본적인 클라우드 경제 원칙 중 하나입니다.

## Q10. 공유 책임 모델에서 AWS의 보안 책임

AWS 공유 책임 모델에서 AWS는 어떤 보안 관련 작업을 담당합니까?

- A. IAM 자격 증명 수명 주기 관리
- B. 글로벌 인프라의 물리적 보안
- C. Amazon EBS 볼륨 암호화
- D. 방화벽 구성

**정답: B**

✅ **B. 글로벌 인프라의 물리적 보안**: AWS는 클라우드의 보안을 담당하며, 여기에는 데이터 센터의 물리적 보안, 하드웨어, 네트워킹 인프라, AWS 서비스가 실행되는 글로벌 시설이 포함됩니다.

❌ **A. IAM 자격 증명 수명 주기 관리**: IAM 사용자 생성, 비밀번호 정책, 액세스 키 교체, MFA 구성은 고객의 책임입니다. AWS는 도구를 제공하지만 ID 관리는 고객이 합니다.

❌ **C. Amazon EBS 볼륨 암호화**: EBS 암호화는 고객의 책임입니다. AWS는 기능(KMS 통합)을 제공하지만 고객이 직접 암호화를 활성화하고 관리해야 합니다.

❌ **D. 방화벽 구성**: 보안 그룹 및 네트워크 ACL(가상 방화벽) 구성은 고객의 책임입니다. AWS는 기본 물리적 네트워크 하드웨어를 관리합니다.

💡 **시험 꿀팁**: AWS = 클라우드의 보안(하드웨어, 시설, 글로벌 네트워크, 하이퍼바이저). 고객 = 클라우드에서의 보안(OS 패치, 앱 구성, 데이터 암호화, IAM, 방화벽 규칙). CLF-C02 보안 도메인에서 가장 많이 출제되는 개념입니다.

## Q11. AWS 공유 책임 모델에서 AWS 클라우드 보안의 예

AWS 공유 책임 모델에서 다음 중 AWS 클라우드의 보안(AWS의 책임)의 예는 무엇입니까?

- A. 엣지 로케이션 관리
- B. 물리적 보안
- C. 방화벽 구성
- D. 글로벌 인프라

**정답: B**

✅ **B. 물리적 보안**: AWS 데이터 센터의 물리적 보안(접근 제어, 감시, 환경 보호, 현장 보안 포함)은 전적으로 AWS의 책임입니다. 고객은 AWS 하드웨어에 물리적으로 접근할 수 없습니다.

❌ **A. 엣지 로케이션 관리**: AWS가 물리적 엣지 로케이션 인프라를 관리하지만, CDN 구성(CloudFront 배포, 캐시 동작) 맥락에서의 "엣지 로케이션 관리"는 고객의 책임입니다.

❌ **C. 방화벽 구성**: VPC 내 보안 그룹 및 NACL 구성은 고객의 책임입니다. AWS는 데이터 센터의 물리적 네트워크 방화벽 어플라이언스를 관리합니다.

❌ **D. 글로벌 인프라**: 글로벌 인프라(리전, AZ, 물리적 시설로서의 엣지 로케이션) 자체는 AWS의 책임이지만, B(물리적 보안)보다 덜 구체적입니다. 시험에서 B와 D 모두 제시된다면, B(물리적 보안)가 AWS 책임에 대한 더 정확하고 자주 출제되는 답입니다.

💡 **시험 꿀팁**: AWS 책임 = 물리적 데이터 센터 보안, 하드웨어 유지보수, 관리형 서비스 패치(예: RDS OS), 글로벌 네트워크. 간단한 규칙: "만질 수 없다면 AWS가 책임집니다."

AWS Basic 지원 플랜을 가진 AWS 사용자가 AWS에서 기술 지원을 받을 수 있는 방법은 무엇입니까? (2개 선택)

💡 **시험 꿀팁**: Basic 지원 = AWS 문서 + Trusted Advisor(핵심 검사) + 커뮤니티 포럼 + AWS 상태 대시보드. Developer = 업무 시간 이메일 지원. Business = 24/7 전화/채팅. Enterprise = TAM + Concierge.

## Q15. 여러 가용 영역에 애플리케이션을 배포할 때의 이점

여러 가용 영역에 걸쳐 애플리케이션을 배포하면 어떤 이점이 있습니까?

- A. 특정 AWS 리전이 자연 재해로 인해 서비스 중단을 경험하는 경우 서비스 장애 위험이 줄어듭니다.
- B. 하나의 가용 영역의 중단을 견딜 수 있기 때문에 가용성이 높아집니다.
- C. 가용 영역이 지리적으로 멀리 떨어져 있어 더 넓은 지역을 커버할 수 있습니다.
- D. 애플리케이션 지연 시간이 줄어들어 사용자 경험이 향상됩니다.

**정답: B**

✅ **B. 하나의 AZ 중단을 견딜 수 있어 가용성 증가**: 가용 영역은 동일한 리전 내의 격리된 데이터 센터입니다. 하나의 AZ가 장애를 겪더라도(전력, 네트워킹, 하드웨어), 여러 AZ에 배포된 애플리케이션은 나머지 AZ에서 계속 실행되어 고가용성을 유지합니다.

❌ **A. 리전에 영향을 미치는 자연 재해의 위험 감소**: 이것은 다중 리전 배포를 설명하는 것이지, 다중 AZ가 아닙니다. 동일한 리전 내의 AZ는 대규모 지역적 재해의 영향을 받을 수 있습니다. AZ는 지역화된 장애를 방지하지만, 전체 리전 장애는 방지하지 못합니다.

❌ **C. 더 넓은 지리적 범위**: 리전 내 AZ는 지리적으로 가깝습니다(일반적으로 100km 이내). 지리적 범위 확장을 위해 설계된 것이 아닙니다.

❌ **D. 애플리케이션 지연 시간 감소**: 다중 AZ 배포는 내결함성과 고가용성을 위한 것이지, 지연 시간 감소를 위한 것이 아닙니다. 지연 시간 감소에는 엣지 로케이션, CDN, 다중 리전 배포가 사용됩니다.

💡 **시험 꿀팁**: 다중 AZ = 내결함성 + 고가용성(리전 내). 다중 리전 = 재해 복구 + 지리적 범위. 이 두 가지 아키텍처 패턴을 시험에서 혼동하지 마세요.

## Q16. 새 AWS 애플리케이션 비용 추정 방법

Cloud Practitioner가 AWS에서 새 애플리케이션 사용 비용을 추정하는 방법을 물어봅니다. 가장 적절한 응답은 무엇입니까?

- A. AWS 요금이 온디맨드 가격을 허용한다고 사용자에게 알립니다.
- B. 사용자에게 견적을 위해 AWS Pricing Calculator를 안내합니다.
- C. Amazon QuickSight를 사용하여 현재 사내 지출을 분석합니다.
- D. Amazon AppStream 2.0을 사용하여 실시간 요금 분석을 합니다.

**정답: B**

✅ **B. AWS Pricing Calculator**: AWS Pricing Calculator(calculator.aws)는 배포 전에 AWS 서비스 비용을 추정하기 위한 공식 도구입니다. 사용자는 서비스를 구성하고 옵션을 선택하여 상세한 월별 비용 견적을 받을 수 있습니다.

❌ **A. 온디맨드 요금에 대해 알리기**: 온디맨드 요금의 존재를 아는 것만으로는 여러 서비스와 구성을 가진 새 애플리케이션의 총 비용을 추정하는 데 도움이 되지 않습니다.

❌ **C. Amazon QuickSight로 사내 지출 분석**: QuickSight는 비즈니스 인텔리전스(BI) 및 데이터 시각화 서비스이며, AWS 서비스 비용 추정 도구가 아닙니다.

❌ **D. Amazon AppStream 2.0**: AppStream 2.0은 브라우저에 데스크톱 앱을 스트리밍하기 위한 완전 관리형 서비스로, 요금 분석과 전혀 관련이 없습니다.

💡 **시험 꿀팁**: AWS 비용 도구 구분 — **Pricing Calculator** = 배포 전 미래 비용 추정. **Cost Explorer** = 과거 및 현재 비용 분석. **Budgets** = 비용이 임계값을 초과할 때 알림 설정. **Cost and Usage Report** = 상세 청구 데이터.

## Q17. VPC의 애플리케이션을 온프레미스 리소스에 연결 (2개 선택)

회사가 AWS VPC로 애플리케이션을 마이그레이션하려 합니다. 이 애플리케이션은 온프레미스 리소스에 접근해야 합니다. 이 목표를 달성하기 위해 회사가 취할 수 있는 작업 조합은 무엇입니까? (2개 선택)

- B. 가상 프라이빗 게이트웨이를 사용하여 새 VPC와 온프레미스 장치 사이에 VPN 연결을 설정합니다.
- C. Amazon Athena를 사용하여 온프레미스 데이터베이스 서버의 데이터를 쿼리합니다.

- E. Amazon CloudFront를 사용하여 온프레미스 웹 서버를 통해 제공되는 정적 웹 콘텐츠에 대한 액세스를 제한합니다.

**정답: B, D**

✅ **B. 가상 프라이빗 게이트웨이를 사용한 VPN 연결**: AWS Site-to-Site VPN 연결은 AWS 측의 가상 프라이빗 게이트웨이와 온프레미스 측의 고객 게이트웨이를 사용하여 인터넷을 통해 암호화된 터널을 만들어 VPC와 온프레미스 간의 안전한 연결을 가능하게 합니다.

✅ **D. AWS Direct Connect**: Direct Connect는 온프레미스 데이터 센터에서 AWS까지 전용 프라이빗 네트워크 연결을 제공하여 공용 인터넷을 우회함으로써 더욱 일관된 네트워크 성능과 낮은 지연 시간을 제공합니다.

❌ **A. AWS Service Catalog**: Service Catalog는 조직 내 사전 승인된 AWS 서비스 포트폴리오를 관리하고 프로비저닝하는 서비스이며, 마이그레이션을 위한 온프레미스 리소스를 식별하지 않습니다.

❌ **C. Amazon Athena**: Athena는 Amazon S3에 저장된 데이터에 대한 서버리스 SQL 쿼리 서비스이며, 온프레미스 데이터베이스 서버를 직접 쿼리하는 서비스가 아닙니다.

❌ **E. Amazon CloudFront**: CloudFront는 콘텐츠를 전 세계적으로 배포하는 CDN이며, 액세스를 제한하거나 온프레미스 웹 서버를 VPC에 연결하는 도구가 아닙니다.

💡 **시험 꿀팁**: 하이브리드 연결 옵션 — **VPN** = 인터넷을 통한 암호화 터널(빠른 설정, 저비용) vs. **Direct Connect** = 전용 프라이빗 회선(일관된 속도, 고비용, 수 주 소요). 둘 다 온프레미스를 AWS VPC에 연결합니다.

## Q18. 악의적인 IP 기반 요청으로부터 애플리케이션 보호

AWS에서 실행 중인 웹 애플리케이션이 반복적인 IP 주소 집합에서 오는 악의적인 요청으로 스팸 공격을 받고 있습니다. 애플리케이션을 보호하고 악성 트래픽을 차단하는 데 도움이 되는 AWS 서비스는 무엇입니까?

- A. AWS IAM
- B. Amazon GuardDuty
- C. Amazon Simple Notification Service (Amazon SNS)
- D. AWS WAF

**정답: D**

✅ **D. AWS WAF**: AWS WAF(Web Application Firewall)는 IP 주소, HTTP 헤더, 요청 본문, URI 문자열 등의 조건에 따라 웹 요청을 차단, 허용 또는 모니터링하는 규칙을 만들 수 있습니다. 알려진 악성 IP 집합에서의 트래픽 차단에 이상적입니다.

❌ **A. AWS IAM**: IAM은 사용자 ID와 AWS 서비스에 대한 액세스 권한을 관리하며, 웹 애플리케이션 트래픽을 필터링하거나 차단하는 기능이 없습니다.

❌ **B. Amazon GuardDuty**: GuardDuty는 머신 러닝을 사용하여 AWS 계정에서 의심스러운 활동을 식별하는 위협 탐지 서비스입니다. 위협을 감지하지만 웹 트래픽을 능동적으로 차단하지 않습니다.

❌ **C. Amazon SNS**: SNS는 구독자에게 메시지를 보내는 메시징 및 알림 서비스로, 네트워크 트래픽을 차단하거나 필터링할 수 없습니다.

💡 **시험 꿀팁**: AWS WAF = 레이어 7(애플리케이션 계층) 보호. IP, 지리, 속도 제한, SQL 주입, XSS 기반 차단. 주로 CloudFront 또는 ALB와 함께 배포. AWS Shield = 레이어 3/4 DDoS 보호. GuardDuty = 위협 탐지(차단 없음). 이 세 가지 보안 서비스와 차이점을 숙지하세요.

## Q19. AWS 클라우드에서 인프라를 코드로 처리하는 이점

AWS 클라우드에서 인프라를 코드로 처리하는 이점은 다음 중 무엇입니까?

- A. 온프레미스 하드웨어를 AWS 데이터 센터로 마이그레이션하는 작업을 자동화합니다.
- B. 타사가 AWS 인프라 감사를 자동화할 수 있도록 합니다.
- C. 애플리케이션 코드를 AWS 인프라에서 실행되도록 변환합니다.
- D. 인프라 프로비저닝 프로세스를 자동화합니다.

**정답: D**

✅ **D. 인프라 프로비저닝 프로세스 자동화**: 인프라를 코드로(IaC) — AWS CloudFormation이나 AWS CDK 같은 도구 사용 — AWS 인프라를 코드/템플릿으로 정의하고 프로비저닝할 수 있게 하여, 수동 콘솔 단계 없이 반복 가능하고 자동화된 버전 관리 배포가 가능합니다.

❌ **A. 온프레미스 하드웨어의 AWS 마이그레이션 자동화**: IaC는 코드를 통해 클라우드 리소스를 프로비저닝하는 것이지, 물리적으로 하드웨어를 마이그레이션하는 것이 아닙니다. AWS Migration Hub와 SMS가 물리적-클라우드 마이그레이션을 처리합니다.

❌ **B. 타사의 인프라 감사 자동화 허용**: IaC 템플릿은 규정 준수를 위해 검토될 수 있지만, IaC의 주요 이점은 자동화와 반복성이지 타사 감사 허용이 아닙니다.

❌ **C. 애플리케이션 코드를 클라우드 플랫폼에서 실행되도록 변환**: IaC는 인프라(서버, 네트워크, 데이터베이스)를 프로비저닝하며, 애플리케이션 코드를 변환하거나 적응시키지 않습니다.

💡 **시험 꿀팁**: 인프라를 코드로(IaC) 핵심 이점: 자동화, 반복성, 버전 관리, 환경 간 일관성. AWS CloudFormation이 기본 IaC 서비스입니다. 시험 핵심 키워드: "프로비저닝 자동화" 또는 "인프라를 소프트웨어처럼 처리".

## Q20. 온프레미스와 AWS 클라우드 간 전용 네트워크 연결

회사가 온프레미스 서버와 AWS 클라우드 간 전용 네트워크 연결이 필요합니다. 어떤 AWS 서비스를 사용해야 합니까?

- A. AWS VPN
- B. AWS Direct Connect
- C. Amazon API Gateway
- D. Amazon Connect

**정답: B**

✅ **B. AWS Direct Connect**: AWS Direct Connect는 온프레미스 데이터 센터와 AWS 간에 전용 프라이빗 물리적 네트워크 연결을 설정하여 공용 인터넷을 완전히 우회합니다. 인터넷 기반 연결에 비해 일관된 대역폭, 낮은 지연 시간, 감소된 데이터 전송 비용을 제공합니다.

❌ **A. AWS VPN**: AWS Site-to-Site VPN은 공용 인터넷을 통해 암호화된 연결을 만들지만, 전용 프라이빗 회선이 아닙니다. 설정이 빠르지만 Direct Connect의 일관성과 보장된 대역폭이 없습니다.

❌ **C. Amazon API Gateway**: API Gateway는 웹 및 모바일 애플리케이션을 위한 API를 구축, 배포, 관리하는 서비스이며, 데이터 센터를 위한 네트워크 연결 솔루션이 아닙니다.

❌ **D. Amazon Connect**: Amazon Connect는 고객 전화 통화 및 상호작용을 처리하는 클라우드 기반 콜센터 서비스이며, 데이터 센터 간 네트워크 연결과는 전혀 무관합니다.

💡 **시험 꿀팁**: "전용(Dedicated)" 연결 키워드 = AWS Direct Connect(프라이빗 전용 광섬유 회선). 인터넷을 통한 "암호화(Encrypted)" 연결 = AWS VPN. Direct Connect는 프로비저닝에 수 주가 걸리지만 일관된 1Gbps 또는 10Gbps 속도를 제공합니다. VPN은 몇 분 안에 설정 가능합니다.
