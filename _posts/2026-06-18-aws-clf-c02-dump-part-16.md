## Q1. IAM 사용자 관리 모범 사례 (2개 선택)

다음 중 IAM 사용자 관리 권장 사례는 무엇입니까? (2개 선택)

- A. 지정된 기간 후 IAM 사용자가 비밀번호를 변경하도록 요구합니다.
- B. IAM 사용자가 이전 비밀번호를 재사용하지 못하도록 합니다.
- C. AWS 및 다른 사이트에서 동일한 비밀번호 사용을 권장합니다.
- D. IAM 사용자에게 비밀번호를 일반 텍스트로 저장하도록 요구합니다.
- E. IAM 사용자에 대한 MFA(다중 인증)를 비활성화합니다.

**정답: A, B**

✅ **A. 주기적 비밀번호 변경 요구**: 비밀번호 교체를 강제하면 손상된 자격 증명이 무기한 사용될 위험이 줄어듭니다. AWS IAM 비밀번호 정책은 최대 비밀번호 수명 설정을 지원합니다.

✅ **B. 비밀번호 재사용 방지**: 이전 비밀번호 재사용을 방지하면 이전 비밀번호가 유출되더라도 재활용될 수 없습니다. AWS IAM 비밀번호 정책에서 비밀번호 재사용 방지 횟수를 설정할 수 있습니다.

❌ **C. 여러 사이트에서 동일한 비밀번호 사용**: 여러 사이트에서 비밀번호를 재사용하는 것은 주요 보안 위험입니다. 한 사이트가 침해되면 해당 비밀번호를 공유하는 모든 계정이 위험에 처합니다.

❌ **D. 비밀번호를 일반 텍스트로 저장**: 비밀번호를 일반 텍스트로 저장하는 것은 치명적인 보안 취약점입니다. AWS는 이 관행을 권장하거나 허용하지 않습니다.

❌ **E. MFA 비활성화**: MFA는 두 번째 인증 계층을 추가하는 강력히 권장되는 보안 제어입니다. 비활성화하면 무단 접근 위험이 증가합니다.

💡 **시험 꿀팁**: IAM 비밀번호 정책 = 교체 + 재사용 없음 + 복잡성 요구 사항. MFA = 항상 활성화, 절대 비활성화. 이것들은 핵심 AWS 보안 모범 사례입니다.

## Q2. 온프레미스에서 AWS 클라우드로의 마이그레이션 지원 (2개 선택)

회사가 온프레미스 데이터 센터에서 AWS 클라우드로 마이그레이션하면서 실무 프로젝트 지원을 요청하고 있습니다. 이 지원을 어떻게 받을 수 있습니까? (2개 선택)

- A. AWS Marketplace 팀에 견적을 요청하여 회사의 AWS 계정으로 마이그레이션을 수행합니다.
- B. AWS Support에 연락하고 지원 케이스를 엽니다.
- C. AWS Professional Services를 사용하여 안내를 제공하고 회사의 AWS 계정에 AWS Landing Zone을 설정합니다.
- D. AWS Partner Network(APN)에서 파트너를 선택하여 마이그레이션을 지원합니다.
- E. Amazon Connect를 사용하여 AWS 클라우드 마이그레이션에 필요한 전문가 지원을 위한 새 RFP(제안 요청서)를 작성합니다.

**정답: C, D**

✅ **C. AWS Professional Services**: AWS의 자체 컨설팅 팀으로 Landing Zone 모범 사례 설정을 포함하여 고객이 클라우드 마이그레이션을 계획하고 실행하는 데 도움을 줍니다.

✅ **D. AWS Partner Network(APN)**: APN 파트너는 고객의 AWS 마이그레이션을 지원하도록 교육받은 인증 타사 회사입니다. 전문화된 전문 지식과 실무 마이그레이션 지원을 제공합니다.

❌ **A. AWS Marketplace 팀**: AWS Marketplace는 소프트웨어 구매 및 배포를 위한 디지털 카탈로그입니다. 마이그레이션 컨설팅 서비스가 아닙니다.

❌ **B. 지원 케이스 열기**: AWS Support는 기술적 문제 해결 및 서비스 문제를 처리하며, 종단 간 마이그레이션 프로젝트 관리나 실무 안내를 제공하지 않습니다.

❌ **E. RFP를 위한 Amazon Connect**: Amazon Connect는 클라우드 기반 콜센터 서비스입니다. 마이그레이션 지원이나 RFP 작성과 관련이 없습니다.

💡 **시험 꿀팁**: 마이그레이션 지원 = AWS Professional Services(AWS 자체 컨설턴트) 또는 APN 파트너(인증된 타사). AWS Support(문제 해결)와 Professional Services(프로젝트 안내)의 차이를 아세요.

## Q3. AWS Enterprise 지원 Concierge 팀의 역할

AWS Enterprise 지원 Concierge 팀은 어떻게 사용자를 지원합니까?

- A. 애플리케이션 개발 지원
- B. 아키텍처 안내 제공
- C. 청구 및 계정 문의에 응답
- D. 기술 지원 케이스에 대한 질문에 답변

**정답: C**

✅ **C. 청구 및 계정 문의에 응답**: AWS Concierge 팀은 Enterprise 지원 내의 전문 부서로 청구 질문, 계정 관리, AWS 재무 관련 사항을 처리합니다.

❌ **A. 애플리케이션 개발**: 애플리케이션 개발 지원은 Concierge 팀의 범위가 아닙니다. 개발자는 AWS 문서, 포럼 또는 Professional Services를 사용합니다.

❌ **B. 아키텍처 안내**: 아키텍처 안내는 AWS Solutions Architects 또는 Well-Architected Framework 검토에서 제공하며, Concierge 팀이 아닙니다.

❌ **D. 기술 지원 케이스**: 기술 지원은 AWS 지원 엔지니어가 처리하며, Concierge 팀이 아닙니다. Concierge는 비기술적 계정 및 청구 사항에 집중합니다.

💡 **시험 꿀팁**: AWS Concierge = 청구 + 계정 질문(Enterprise 지원 플랜에서만 제공). 기술 전략을 담당하는 TAM(기술 계정 관리자)과 혼동하지 마세요.

## Q4. 여러 가용 영역에 걸쳐 설계된 애플리케이션의 특성

애플리케이션이 여러 가용 영역에 걸쳐 설계되어 있다면 이것은 무엇을 의미합니까?

- A. 고가용성
- B. 글로벌 접근성
- C. 규모의 경제 이점 활용
- D. 탄력성

**정답: A**

✅ **A. 고가용성**: 여러 가용 영역(AZ)에 애플리케이션을 분산시키면 하나의 AZ에서 중단이 발생해도 애플리케이션이 다른 AZ에서 계속 실행됩니다. 이것이 고가용성의 정의입니다.

❌ **B. 글로벌 접근성**: 글로벌 접근성은 여러 AWS 리전 또는 CloudFront 같은 서비스를 통해 달성되며, 단일 리전 내의 여러 AZ만으로는 충분하지 않습니다.

❌ **C. 규모의 경제**: 규모의 경제는 AWS의 방대한 인프라로 인한 비용 혜택을 의미합니다. 여러 AZ에 배포하는 것은 이 개념과 직접적으로 관련이 없습니다.

❌ **D. 탄력성**: 탄력성은 수요에 따라 리소스를 자동으로 확장하거나 축소하는 능력을 의미합니다. 다중 AZ 배포는 내결함성에 관한 것이지 탄력성이 아닙니다.

💡 **시험 꿀팁**: 여러 AZ = 고가용성 + 내결함성. 여러 리전 = 글로벌 접근성 + 재해 복구. 탄력성 = Auto Scaling. 이러한 구분을 잘 알아두세요.

## Q5. 단일 지리적 지역 내에서의 고가용성

새 AWS 서비스는 고가용성을 갖추어야 하지만 규정에 따라 모든 Amazon EC2 인스턴스는 단일 지리적 영역 내에 있어야 합니다. 모범 사례에 따르면 EC2 인스턴스는 최소 몇 개에 배포해야 합니까?

- A. AWS 리전
- B. 가용 영역
- C. 서브넷
- D. 배치 그룹

**정답: B**

✅ **B. 가용 영역**: 가용 영역은 동일한 AWS 리전(동일한 지리적 영역) 내에 물리적으로 분리된 데이터 센터입니다. 최소 두 개의 AZ에 배포하면 하나의 지리적 리전 내에 머물면서 고가용성을 제공합니다. 규정 요구 사항을 충족합니다.

❌ **A. AWS 리전**: 리전은 넓은 지리적 영역입니다. 여러 리전을 사용하면 단일 지리적 영역에 머물러야 하는 요구 사항을 위반합니다.

❌ **C. 서브넷**: 서브넷은 단일 AZ 내에 존재할 수 있는 VPC 내의 네트워크 세분화입니다. 서브넷 간에만 분산시키는 것은 고가용성을 보장하지 않습니다.

❌ **D. 배치 그룹**: 배치 그룹은 성능(클러스터) 또는 내결함성(분산)을 위해 EC2 인스턴스의 물리적 배치를 제어합니다. 장애 도메인 간 고가용성의 주요 메커니즘이 아닙니다.

💡 **시험 꿀팁**: AZ = 하나의 리전 내 물리적으로 격리된 데이터 센터. 고가용성 + 규정 단일 리전 준수를 달성하려면 항상 "동일한 리전 내 여러 AZ에 배포"를 생각하세요.

## Q6. 예약 인스턴스 혜택을 단일 계정으로 제한

AWS Organization에는 여러 AWS 계정이 있으며 Amazon EC2 예약 인스턴스 혜택을 단일 계정에만 적용하려 합니다. 어떤 조치를 취해야 합니까?

- A. 마스터 결제 계정에서 예약 인스턴스를 구매하고 예약 인스턴스 공유를 끕니다.
- B. AWS 청구 및 비용 관리 콘솔에서 청구 알림을 활성화합니다.
- C. 개별 연결 계정에서 예약 인스턴스를 구매하고 결제자 수준에서 예약 인스턴스 공유를 끕니다.
- D. AWS 청구 및 비용 관리 콘솔에서 예약 인스턴스 공유를 활성화합니다.

**정답: C**

✅ **C. 연결 계정에서 RI 구매 후 결제자 수준에서 공유 비활성화**: 특정 연결 계정에서 예약 인스턴스를 구매한 다음 결제자(관리) 계정 수준에서 RI 공유를 비활성화하면 RI 혜택이 해당 특정 계정에만 적용되고 조직 전체에 공유되지 않습니다.

❌ **A. 마스터 계정에서 구매하고 공유 끄기**: 마스터 결제 계정에서 RI를 구매하고 공유를 끄면 RI가 여전히 마스터 계정에만 혜택을 주며, 의도한 대상 계정이 아닐 수 있습니다.

❌ **B. 청구 알림 활성화**: 청구 알림(CloudWatch 또는 AWS Budgets 알림)은 지출 임계값에 대해 알려줍니다. 예약 인스턴스 할인 적용 방식을 제어하지 않습니다.

❌ **D. RI 공유 활성화**: RI 공유를 활성화하면 반대 효과가 발생하여 RI 할인이 조직의 모든 계정에 분산되며, 하나의 계정으로 제한되지 않습니다.

💡 **시험 꿀팁**: AWS Organizations RI 공유 = 기본적으로 활성화. RI 혜택을 하나의 계정으로 격리하려면 해당 계정에서 RI를 구매하고 결제자 계정 수준에서 RI 공유를 비활성화하세요.

## Q7. AWS Trust & Safety 팀에 신고해야 하는 상황

어떤 상황을 AWS Trust & Safety 팀에 신고해야 합니까?

- A. 가용 영역의 서비스 중단
- B. AWS IP 주소에서 침입 시도가 발생하고 있습니다.
- C. 사용자가 AWS IP 주소에서 Amazon S3 버킷에 액세스하는 데 문제가 있습니다.
- D. 사용자가 손상으로 인해 결제 방법을 변경해야 합니다.

**정답: B**

✅ **B. AWS IP 주소에서 침입 시도**: AWS Trust & Safety는 해킹 시도, 포트 스캔, 스팸, AWS IP 주소에서 오는 기타 악의적인 활동을 포함한 AWS 인프라에서 발생하는 남용 신고를 처리합니다.

❌ **A. AZ 서비스 중단**: AZ 서비스 중단은 AWS Service Health Dashboard를 통해 모니터링하고 AWS Support에 신고해야 하며, Trust & Safety 팀이 아닙니다.

❌ **C. S3 액세스 문제**: S3 접근 어려움은 AWS Support에 제출해야 하는 기술 지원 문제이며, 남용 및 보안 위협에 중점을 둔 Trust & Safety 팀이 아닙니다.

❌ **D. 결제 방법 변경**: 결제 방법 변경은 AWS 청구 콘솔이나 AWS Support에 연락하여 처리합니다. Trust & Safety는 AWS 인프라 남용을 다루지, 계정 청구 문제를 다루지 않습니다.

💡 **시험 꿀팁**: AWS Trust & Safety = AWS 인프라에서 발생하는 남용 신고(스팸, DDoS, AWS IP에서의 해킹). 서비스 문제 → AWS Support. 청구 → AWS 청구/Support.

## Q8. 글로벌 사용자를 위한 낮은 지연 시간과 높은 전송 속도 (2개 선택)

회사가 단일 AWS 리전에서 전 세계 사용자를 대상으로 하는 e-commerce 사이트를 출시하려 합니다. 낮은 지연 시간과 높은 전송 속도로 사용자에게 도달하는 데 도움이 되는 AWS 서비스는 무엇입니까? (2개 선택)

- A. Application Load Balancer
- B. AWS Global Accelerator
- C. AWS Direct Connect
- D. Amazon CloudFront
- E. AWS Lambda

**정답: B, D**

✅ **B. AWS Global Accelerator**: Global Accelerator는 사용자 트래픽을 가장 가까운 AWS 엣지 로케이션으로 AWS 글로벌 네트워크 백본을 통해 라우팅하여 애플리케이션이 어디에 호스팅되든 전 세계 사용자의 지연 시간을 크게 줄입니다.

✅ **D. Amazon CloudFront**: CloudFront는 전 세계 400개 이상의 엣지 로케이션에서 정적 및 동적 콘텐츠를 캐싱하고 전달하는 CDN(콘텐츠 전달 네트워크)으로, 낮은 지연 시간으로 글로벌 사용자에게 콘텐츠를 제공합니다.

❌ **A. Application Load Balancer**: ALB는 리전 내의 대상 간에 트래픽을 분산시킵니다. 글로벌 접근성 최적화나 다른 대륙의 사용자 지연 시간 감소에는 도움이 되지 않습니다.

❌ **C. AWS Direct Connect**: Direct Connect는 온프레미스 데이터 센터와 AWS 간에 전용 프라이빗 연결을 제공합니다. 전 세계 최종 사용자에게 더 빠른 콘텐츠를 전달하는 데 도움이 되지 않습니다.

❌ **E. AWS Lambda**: Lambda는 서버리스 컴퓨팅 서비스입니다. 여러 리전에 배포할 수 있지만 글로벌 콘텐츠 전달이나 지연 시간 최적화를 본질적으로 제공하지 않습니다.

💡 **시험 꿀팁**: 글로벌 저지연 전달 = CloudFront(CDN, 캐싱) + Global Accelerator(네트워크 라우팅 최적화). CloudFront는 정적/캐시 가능한 콘텐츠에 가장 적합하고, Global Accelerator는 동적/캐시 불가능한 트래픽에 가장 적합합니다.

## Q9. 서버리스 AWS 서비스

다음 중 서버리스 AWS 서비스 또는 리소스는 무엇입니까?

- A. AWS Lambda
- B. Amazon EC2 인스턴스
- C. Amazon Lightsail
- D. Amazon ElastiCache

**정답: A**

✅ **A. AWS Lambda**: Lambda는 이벤트에 응답하여 서버를 프로비저닝하거나 관리하지 않고 코드를 실행하는 완전 서버리스 컴퓨팅 서비스입니다. AWS가 모든 기본 인프라를 자동으로 처리합니다.

❌ **B. Amazon EC2 인스턴스**: EC2는 프로비저닝, 구성, 관리해야 하는 가상 머신(서버)을 제공합니다. 서버리스가 아닙니다.

❌ **C. Amazon Lightsail**: Lightsail은 초보자를 위한 단순화된 가상 프라이빗 서버(VPS)를 제공합니다. 여전히 서버 인스턴스가 포함되며 서버리스가 아닙니다.

❌ **D. Amazon ElastiCache**: ElastiCache는 관리형 인메모리 캐싱 서비스(Redis/Memcached)입니다. AWS가 많은 인프라를 관리하지만, 노드 유형 및 클러스터 크기를 여전히 선택하며 완전 서버리스가 아닙니다.

💡 **시험 꿀팁**: 서버리스 = 서버 관리 없음, 실행/요청당 지불. 주요 서버리스 서비스: Lambda(컴퓨팅), S3(스토리지), DynamoDB(데이터베이스), API Gateway, Fargate(컨테이너). EC2 = 서버리스가 아님.

## Q10. Amazon VPC의 구성 요소 (2개 선택)

다음 중 Amazon VPC의 구성 요소는 무엇입니까? (2개 선택)

- A. 객체
- B. 서브넷
- C. 버킷
- D. 인터넷 게이트웨이
- E. 액세스 키

**정답: B, D**

✅ **B. 서브넷**: 서브넷은 VPC의 IP 주소 범위의 세분화입니다. 리소스를 다른 네트워크 세그먼트에 배치하고 라우팅 및 접근을 제어할 수 있습니다. 각 서브넷은 단일 가용 영역에 존재합니다.

✅ **D. 인터넷 게이트웨이**: 인터넷 게이트웨이는 VPC의 리소스와 인터넷 간의 통신을 가능하게 하는 VPC 구성 요소입니다. VPC에 연결되어 공용 인터넷 접근을 허용합니다.

❌ **A. 객체**: 객체는 Amazon S3(객체 스토리지)의 개념이며, Amazon VPC의 개념이 아닙니다.

❌ **C. 버킷**: 버킷은 Amazon S3의 데이터 컨테이너이며, VPC 구성 요소가 아닙니다.

❌ **E. 액세스 키**: 액세스 키는 AWS API에 대한 프로그래밍 방식 접근에 사용되는 IAM 자격 증명입니다. VPC 네트워킹 구성 요소가 아닙니다.

💡 **시험 꿀팁**: VPC 구성 요소 = 서브넷, 인터넷 게이트웨이, 라우팅 테이블, 보안 그룹, NACL, NAT 게이트웨이, VPC 피어링. S3 구성 요소 = 버킷 + 객체. 시험에서 혼동하지 마세요.

## Q11. AWS Budgets 사용 사례

AWS Budgets는 다음에 사용할 수 있습니다:

- A. 특정 사용자가 리소스를 생성하는 것을 방지합니다.
- B. 예약 인스턴스 사용률이 특정 비율 아래로 떨어질 때 알림을 보냅니다.
- C. AWS 계정에 리소스 한도를 설정하여 초과 지출을 방지합니다.
- D. AWS 청구서를 여러 결제 방법으로 분할합니다.

**정답: B**

✅ **B. RI 사용률이 임계값 아래로 떨어질 때 알림 전송**: AWS Budgets는 예약 인스턴스(RI) 및 Savings Plans 사용률 예산을 지원하여 RI 사용률이 지정된 비율 아래로 떨어질 때 알림을 보내 예약에서 최대 가치를 얻고 있는지 확인합니다.

❌ **A. 사용자가 리소스를 생성하는 것을 방지**: AWS Budgets는 모니터링 및 알림 도구이며, 리소스 생성 제한을 강제할 수 없습니다. 이를 위해 IAM 정책이나 서비스 제어 정책(SCP)을 사용하세요.

❌ **C. 초과 지출을 방지하는 리소스 한도 설정**: AWS Budgets는 임계값이 초과될 때 알림을 보내지만, 자동으로 하드 한도를 강제하거나 리소스 생성을 중지할 수 없습니다(Budget Actions는 정책을 적용할 수 있지만 CLF 수준에서 테스트되지 않는 고급 기능).

❌ **D. 여러 결제 방법으로 청구서 분할**: AWS 청구는 결제 방법을 처리하지만, 여러 결제 방법으로 청구서를 분할하는 것은 AWS Budgets의 기능이 아닙니다.

💡 **시험 꿀팁**: AWS Budgets = 지출/사용량/RI 임계값 설정 + 이메일/SNS를 통한 알림 수신. 알림 도구이지 강제 도구가 아닙니다. 비용 할당을 위해 Cost Allocation Tags + Cost Explorer를 사용하세요.

## Q12. AWS 관리 콘솔 액세스 보안 강화 (2개 선택)

다음 중 AWS 관리 콘솔에 대한 액세스 보안을 강화할 수 있는 것은 무엇입니까? (2개 선택)

- A. AWS Secrets Manager
- B. AWS Certificate Manager
- C. AWS 다중 인증(AWS MFA)
- D. 보안 그룹
- E. 비밀번호 정책

**정답: C, E**

✅ **C. AWS 다중 인증(MFA)**: MFA는 비밀번호 외에 두 번째 인증 형식(예: 가상 MFA 디바이스의 코드)을 요구합니다. 비밀번호가 손상되더라도 무단 콘솔 접근 위험을 크게 줄입니다.

✅ **E. 비밀번호 정책**: IAM 비밀번호 정책은 최소 길이, 복잡성 요구 사항, 교체 기간, 재사용 방지 등의 규칙을 강제하여 콘솔 로그인 보안을 강화합니다.

❌ **A. AWS Secrets Manager**: Secrets Manager는 애플리케이션 시크릿(API 키, 데이터베이스 자격 증명)을 저장하고 교체하는 데 사용됩니다. 관리 콘솔 로그인 보안에 직접 사용하지 않습니다.

❌ **B. AWS Certificate Manager**: ACM은 웹 애플리케이션 및 API를 위한 SSL/TLS 인증서를 관리합니다. 콘솔 액세스 보안에 사용하지 않습니다.

❌ **D. 보안 그룹**: 보안 그룹은 EC2 인스턴스의 인바운드/아웃바운드 트래픽을 제어하는 가상 방화벽입니다. 네트워크 수준에서 컴퓨팅 리소스에 대해 작동하며, 관리 콘솔 인증에는 사용하지 않습니다.

💡 **시험 꿀팁**: 콘솔 보안 = MFA(루트 + IAM 사용자에게 항상 활성화) + 강력한 비밀번호 정책. MFA는 AWS 계정 액세스를 위한 1위 권장 보안 제어입니다.

## Q13. AWS Trusted Advisor 검사 범주 (2개 선택)

다음 중 AWS Trusted Advisor 검사에 포함된 권장 사항은 무엇입니까? (2개 선택)

- A. Amazon S3 버킷 권한에 관한 정보
- B. AWS 서비스 중단
- C. AWS 계정 루트 사용자에 대한 MFA 사용 여부
- D. 사용 가능한 소프트웨어 패치
- E. 계정의 사용자 수

**정답: A, C**

✅ **C. 루트 사용자에 대한 MFA**: Trusted Advisor는 루트 계정에 MFA가 활성화되어 있는지 확인하고 활성화되어 있지 않으면 알림을 보냅니다. 이는 기본적인 보안 권장 사항입니다.

❌ **B. AWS 서비스 중단**: 서비스 중단 및 상태 이벤트는 AWS Service Health Dashboard(이전 AWS Personal Health Dashboard)에서 보고하며, Trusted Advisor에서 보고하지 않습니다.

❌ **E. 계정의 사용자 수**: Trusted Advisor는 계정의 IAM 사용자 수를 보고하지 않습니다. IAM 사용자 관리는 IAM 콘솔에서 수행합니다.

💡 **시험 꿀팁**: Trusted Advisor 5개 기둥: 비용 최적화, 성능, 보안, 내결함성, 서비스 한도. 프리 티어는 보안 + 서비스 한도 검사를 받습니다. Business/Enterprise는 모든 검사를 받습니다.

## Q14. AWS KMS의 기능

AWS KMS(키 관리 서비스)로 사용자가 할 수 있는 것은 무엇입니까?

- A. AWS 계정 루트 사용자에 대한 AWS 액세스 키 생성 및 관리
- B. AWS 계정의 IAM 사용자에 대한 AWS 액세스 키 생성 및 관리
- C. 데이터 암호화 및 복호화를 위한 키 생성 및 관리
- D. 다중 인증을 위한 키 생성 및 관리

**정답: C**

✅ **C. 데이터 암호화 및 복호화를 위한 키 생성 및 관리**: AWS KMS는 AWS 서비스(S3, EBS, RDS, Lambda 등) 전반에서 데이터를 암호화하고 복호화하는 데 사용되는 암호화 키를 생성하고 제어하는 관리형 서비스입니다. 키를 생성, 교체, 비활성화하고 사용을 감사할 수 있습니다.

❌ **A. 루트 사용자에 대한 액세스 키**: AWS 액세스 키(API/CLI 접근용)는 KMS가 아닌 IAM 콘솔에서 관리합니다. 루트 사용자 액세스 키는 강력히 권장하지 않습니다.

❌ **B. IAM 사용자에 대한 액세스 키**: IAM 액세스 키는 KMS가 아닌 각 사용자의 보안 자격 증명 아래 IAM 콘솔에서 관리합니다.

❌ **D. 다중 인증을 위한 키**: MFA는 시간 기반 일회용 비밀번호(TOTP) 또는 하드웨어 토큰을 사용하며 IAM을 통해 관리합니다. KMS는 암호화 키 관리를 위한 것이며 MFA 토큰이 아닙니다.

💡 **시험 꿀팁**: AWS KMS = 암호화 키 관리. KMS 키는 AWS 서비스 전반의 데이터를 암호화합니다. KMS는 CMK(고객 관리 키)를 관리하며 IAM 액세스 키나 MFA 토큰을 관리하지 않습니다.

## Q15. AWS Trusted Advisor가 안내를 제공하는 방법 (2개 선택)

AWS Trusted Advisor는 어떻게 AWS 클라우드 사용자에게 안내를 제공합니까? (2개 선택)

- A. AWS에서 실행되는 애플리케이션의 소프트웨어 취약점 식별
- B. 현재 AWS 사용량을 기반으로 비용 최적화 권장 사항 목록 제공
- C. 계정 리소스의 권한 설정으로 인한 잠재적 보안 취약점 탐지
- D. 계정 리소스의 권한 설정으로 인한 잠재적 보안 문제 자동 해결
- E. Amazon EC2 인스턴스가 침해될 때마다 사전 예방 알림 제공

**정답: B, C**

✅ **B. 비용 최적화 권장 사항**: Trusted Advisor는 현재 AWS 사용량을 분석하여 유휴 EC2 인스턴스, 활용도 낮은 예약 인스턴스, 연결되지 않은 EBS 볼륨 등을 식별하는 실행 가능한 비용 절감 권장 사항을 제공합니다.

✅ **C. 권한에서 발생하는 잠재적 보안 취약점 탐지**: Trusted Advisor는 지나치게 허용적인 보안 그룹 규칙, 공개 S3 버킷, 루트에 MFA 없음 및 기타 권한 관련 보안 위험을 확인합니다.

❌ **A. 소프트웨어 취약점 식별**: 애플리케이션 수준의 소프트웨어 취약점 스캔은 Trusted Advisor가 아닌 Amazon Inspector가 수행합니다.

❌ **D. 보안 문제 자동 해결**: Trusted Advisor는 문제를 식별하고 알리기만 하며, 자동으로 해결하지 않습니다. 자동 수정에는 자동 수정 기능이 있는 AWS Config 규칙 또는 Lambda가 필요합니다.

❌ **E. EC2 침해 시 사전 예방 알림**: EC2 침해 탐지는 Amazon GuardDuty(위협 탐지) 및 AWS Security Hub가 처리합니다. Trusted Advisor는 인스턴스 수준 침해 이벤트를 모니터링하지 않습니다.

💡 **시험 꿀팁**: Trusted Advisor = 권장하며 수정하지 않음. 자동 수정을 위해서는 AWS Config + Lambda를 사용하세요. 위협 탐지에는 GuardDuty를 사용하세요. Trusted Advisor는 비용, 성능, 보안, 내결함성, 서비스 한도를 검사합니다.

## Q16. AWS 클라우드의 이점 (2개 선택)

다음 중 AWS 클라우드의 이점은 무엇입니까? (2개 선택)

- A. AWS가 클라우드 인프라를 유지 관리합니다.
- B. AWS가 AWS에서 구축된 애플리케이션의 보안을 관리합니다.
- C. AWS가 물리적 서버의 용량 계획을 관리합니다.
- D. AWS가 AWS의 애플리케이션 개발을 관리합니다.
- E. AWS가 가상 서버의 비용 계획을 관리합니다.

**정답: A, C**

✅ **A. AWS가 클라우드 인프라를 유지 관리합니다**: 공유 책임 모델에 따라 AWS는 하드웨어, 네트워킹, 시설, 하이퍼바이저 계층을 포함한 모든 물리적 인프라를 유지 관리합니다. 고객은 하드웨어 유지 관리에 대해 걱정할 필요가 없습니다.

✅ **C. AWS가 물리적 서버의 용량 계획을 관리합니다**: AWS는 물리적 데이터 센터 용량을 소유하고 관리합니다. 고객은 물리적 서버 조달이나 용량 계획에 대해 걱정하지 않고 온디맨드로 가상 리소스를 프로비저닝할 수 있습니다.

❌ **B. AWS가 애플리케이션 보안을 관리합니다**: 애플리케이션 보안은 공유 책임 모델에 따라 고객의 책임입니다. AWS는 인프라를 보호하고 고객은 애플리케이션, 데이터, 구성 보안을 담당합니다.

❌ **D. AWS가 애플리케이션 개발을 관리합니다**: 애플리케이션 개발은 전적으로 고객의 책임입니다. AWS는 개발을 지원하는 도구와 서비스를 제공하지만, 고객을 대신하여 애플리케이션을 개발하지 않습니다.

❌ **E. AWS가 가상 서버의 비용 계획을 관리합니다**: AWS는 요금 도구(Cost Explorer, Budgets)를 제공하지만, 비용 계획 및 최적화 결정은 고객의 책임이지 AWS가 아닙니다.

💡 **시험 꿀팁**: 공유 책임 모델: AWS = "클라우드의 보안"(하드웨어, 시설, 네트워크). 고객 = "클라우드에서의 보안"(데이터, 앱, IAM, OS 구성). 매우 자주 출제되는 개념입니다.

## Q17. 다중 AZ RDS 배포를 나타내는 Well-Architected Framework 기둥

사용자가 여러 가용 영역에 걸쳐 Amazon RDS DB 인스턴스를 배포합니다. 이 전략은 AWS Well-Architected Framework의 어떤 기둥을 나타냅니까?

- A. 성능 효율성
- B. 안정성
- C. 비용 최적화
- D. 보안

**정답: B**

✅ **B. 안정성**: 안정성 기둥은 워크로드가 의도한 기능을 올바르고 일관되게 수행하고 장애로부터 복구하는 능력에 중점을 둡니다. 다중 AZ RDS 배포는 자동 페일오버를 제공하여 내결함성 및 복구를 직접 다루며, 이는 안정성의 핵심 측면입니다.

❌ **A. 성능 효율성**: 성능 효율성은 시스템 요구 사항을 충족하기 위해 컴퓨팅 리소스를 효율적으로 사용하는 것입니다. 다중 AZ는 주로 가용성 및 내결함성에 관한 것이지 성능 최적화가 아닙니다.

❌ **C. 비용 최적화**: 비용 최적화는 최저 가격으로 비즈니스 가치를 제공하는 시스템 운영에 중점을 둡니다. 다중 AZ는 실제로 비용을 증가시키며, 비용 절감이 아닌 복원력을 위해 선택됩니다.

❌ **D. 보안**: 보안은 데이터, 시스템, 자산 보호에 중점을 둡니다. 다중 AZ는 전반적인 시스템 무결성에 기여하지만, 주요 목적은 안정성에 해당하는 고가용성 및 재해 복구입니다.

💡 **시험 꿀팁**: AWS Well-Architected 6개 기둥: 운영 우수성, 보안, 안정성, 성능 효율성, 비용 최적화, 지속 가능성. 다중 AZ = 안정성. 암호화 = 보안. 적절한 크기 조정 = 비용 최적화.

## Q18. 클라우드와 온프레미스 리소스를 연결하는 AWS 서비스 (2개 선택)

AWS 클라우드와 온프레미스 리소스 간의 연결을 제공하는 AWS 서비스는 무엇입니까? (2개 선택)

- A. AWS VPN
- B. Amazon Connect
- C. Amazon Cognito
- D. AWS Direct Connect
- E. AWS Managed Services

**정답: A, D**

✅ **A. AWS VPN**: AWS VPN(가상 사설망)은 공용 인터넷을 통해 온프레미스 네트워크와 AWS VPC 간에 암호화된 터널을 만들어 전용 하드웨어 없이 안전한 연결을 제공합니다.

✅ **D. AWS Direct Connect**: Direct Connect는 온프레미스 데이터 센터에서 AWS까지 전용 프라이빗 네트워크 연결을 제공하여 공용 인터넷을 우회하고 일관된 저지연, 고대역폭 연결을 제공합니다.

❌ **B. Amazon Connect**: Amazon Connect는 고객 지원 전화 시스템을 위한 클라우드 기반 콜센터 서비스입니다. 네트워크 연결 솔루션이 아닙니다.

❌ **C. Amazon Cognito**: Amazon Cognito는 웹 및 모바일 애플리케이션에 사용자 인증 및 권한 부여를 추가하는 ID 관리 서비스입니다. 네트워크 연결을 제공하지 않습니다.

❌ **E. AWS Managed Services**: AWS Managed Services는 AWS 인프라의 운영 관리를 제공합니다. AWS 환경 관리를 돕지만, 온프레미스와 AWS 간의 네트워크 연결 서비스가 아닙니다.

💡 **시험 꿀팁**: 온프레미스에서 AWS 연결 = VPN(암호화, 인터넷 통해, 빠른 설정) vs. Direct Connect(전용 프라이빗 회선, 일관된 대역폭, 프로비저닝에 수 주 소요). VPN = 저렴 + 빠른 설정. Direct Connect = 프로덕션 워크로드에 더 빠르고 안정적.

## Q19. AWS 청구서 지불 및 사용량 예산 모니터링 서비스

AWS 청구서를 지불하고 사용량 및 예산 비용을 모니터링하는 데 사용하는 AWS 서비스는 무엇입니까?

- A. AWS 청구 및 비용 관리
- B. 통합 청구
- C. Amazon CloudWatch
- D. Amazon QuickSight

**정답: A**

✅ **A. AWS 청구 및 비용 관리**: 이것은 AWS 청구서를 보고 지불하고, 비용 및 사용 데이터를 분석하고, 예산을 설정하고, Cost Explorer 및 AWS Budgets와 같은 비용 관리 도구에 접근하기 위한 기본 AWS 서비스입니다.

❌ **B. 통합 청구**: 통합 청구는 여러 계정의 청구를 단일 지불로 결합하는 AWS Organizations의 기능입니다. 전체 청구 및 모니터링을 위한 독립 서비스가 아닌 청구 관리의 하위 집합입니다.

❌ **C. Amazon CloudWatch**: CloudWatch는 AWS 리소스 및 애플리케이션을 위한 모니터링 및 관찰 서비스입니다. 지표, 로그, 알람을 추적하지만 AWS 청구서를 관리하는 주요 서비스가 아닙니다.

❌ **D. Amazon QuickSight**: QuickSight는 비즈니스 인텔리전스(BI) 및 데이터 시각화 서비스입니다. 비용 데이터를 시각화할 수 있지만 청구서 지불이나 AWS 지출 관리를 위한 전용 도구가 아닙니다.

💡 **시험 꿀팁**: AWS 청구 및 비용 관리 = Cost Explorer(과거 비용 분석), AWS Budgets(미래 임계값 설정), Bills(요금 보기), 결제 관리를 포함하는 우산 서비스. 각 하위 도구의 목적을 아세요.

## Q20. 중복 전원 및 네트워킹을 갖춘 AWS 글로벌 인프라 요소

AWS 글로벌 인프라에서 각각 중복 전원, 네트워킹, 연결성을 갖춘 별도 시설에 배치된 하나 이상의 개별 데이터 센터로 구성된 요소는 무엇입니까?

- A. AWS 리전
- B. 가용 영역
- C. 엣지 로케이션
- D. Amazon CloudFront

**정답: B**

✅ **B. 가용 영역**: 가용 영역(AZ)은 각각 중복 전원, 네트워킹, 연결성을 갖춘 물리적으로 분리된 하나 이상의 데이터 센터로 구성됩니다. 리전 내의 AZ는 고속 저지연 링크로 상호 연결되어 있지만 장애 전파를 방지하기 위해 서로 격리되어 있습니다.

❌ **A. AWS 리전**: 리전은 여러 가용 영역(일반적으로 3개 이상)을 포함하는 지리적 영역입니다. 개별 데이터 센터의 집합이 아닌 AZ의 더 높은 수준의 그룹입니다.

❌ **C. 엣지 로케이션**: 엣지 로케이션은 Amazon CloudFront 및 기타 서비스가 최종 사용자에게 더 가까운 위치에서 콘텐츠를 캐싱하고 전달하는 엔드포인트입니다. AZ처럼 중복 인프라를 갖춘 완전 규모 데이터 센터가 아닙니다.

❌ **D. Amazon CloudFront**: CloudFront는 콘텐츠 전달 네트워크(CDN) 서비스이지, 물리적 인프라 구성 요소가 아닙니다. 전 세계적으로 콘텐츠를 배포하기 위해 엣지 로케이션을 사용합니다.

💡 **시험 꿀팁**: AWS 인프라 계층: 리전(지리적 영역) > 가용 영역(하나 이상의 데이터 센터) > 엣지 로케이션(CDN 캐시 포인트). AZ = 리전 내 장애 격리 경계. CLF-C02에서 가장 많이 테스트되는 기본 개념 중 하나입니다.
