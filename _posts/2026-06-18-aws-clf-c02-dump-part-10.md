## Q1. ELB 로드 밸런서 유형 (두 개 선택)

Elastic Load Balancing(ELB)과 함께 사용할 수 있는 로드 밸런서 유형은 무엇입니까? (두 개를 선택합니다.)

- A. AWS 애플리케이션 자동 확장 기능이 있는 공용 로드 밸런서
- B. F5 Big-IP 및 Citrix NetScaler 로드 밸런서
- C. 클래식 로드 밸런서
- D. 공용 및 개인 IP를 사용하는 교차 영역 로드 밸런서
- E. 애플리케이션 로드 밸런서

**정답: C, E**

✅ **C. 클래식 로드 밸런서**: AWS ELB에서 지원하는 레거시 유형으로, EC2-Classic 및 VPC 환경 모두에서 동작합니다. HTTP/HTTPS 및 TCP 트래픽을 처리할 수 있습니다.

✅ **E. 애플리케이션 로드 밸런서**: HTTP/HTTPS Layer 7 기반 로드 밸런서로, 경로 기반 라우팅, 호스트 기반 라우팅 등 고급 기능을 제공하는 ELB의 주요 유형입니다.

❌ **A. AWS 애플리케이션 자동 확장 기능이 있는 공용 로드 밸런서**: Auto Scaling은 ELB와 연동되는 별도 서비스이며, 이 자체가 ELB 로드 밸런서 유형이 아닙니다.

❌ **B. F5 Big-IP 및 Citrix NetScaler 로드 밸런서**: 이는 서드파티 벤더의 로드 밸런서 제품으로 AWS ELB의 유형이 아닙니다.

❌ **D. 공용 및 개인 IP를 사용하는 교차 영역 로드 밸런서**: 교차 영역 로드 밸런싱은 ELB의 설정 옵션이지, 별도의 로드 밸런서 유형이 아닙니다.

💡 **시험 꿀팁**: AWS ELB 4가지 유형 암기 — **ALB**(Application, Layer 7, HTTP/HTTPS), **NLB**(Network, Layer 4, TCP/UDP), **GLB**(Gateway, Layer 3, 어플라이언스), **CLB**(Classic, 레거시). CLF 시험에서는 주로 ALB, NLB, CLB가 출제됩니다.

## Q2. AWS 선택 이유 (온프레미스 대비)

기업이 전통적인 데이터 센터 대신 AWS를 선택해야 하는 이유는 무엇입니까?

- A. AWS는 사용자에게 기본 리소스에 대한 완전한 제어 권한을 제공합니다.
- B. AWS는 장기 계약을 요구하지 않으며 종량제 모델을 제공합니다.
- C. AWS는 모든 국가에서 에지 위치를 제공하여 글로벌 도달 지원
- D. AWS는 생성할 수 있는 리소스 수에 제한이 없습니다.

**정답: B**

✅ **B. AWS는 장기 계약을 요구하지 않으며 종량제 모델을 제공합니다**: AWS의 핵심 장점 중 하나로, 초기 자본 지출(CapEx) 없이 사용한 만큼만 비용을 지불(OpEx)하며, 장기 계약 없이 유연하게 이용할 수 있습니다.

❌ **A. AWS는 사용자에게 기본 리소스에 대한 완전한 제어 권한을 제공합니다**: AWS 공유 책임 모델에 따라 물리적 하드웨어 및 기반 인프라는 AWS가 관리하며, 사용자는 완전한 제어권을 갖지 않습니다.

❌ **C. AWS는 모든 국가에서 에지 위치를 제공하여 글로벌 도달 지원**: AWS 에지 위치는 많은 국가에 있지만 "모든 국가"에 제공된다는 것은 사실이 아닙니다.

❌ **D. AWS는 생성할 수 있는 리소스 수에 제한이 없습니다**: AWS에는 서비스 할당량(Service Quotas)이 존재하며, 리소스 생성에 제한이 있습니다(증가 요청은 가능).

💡 **시험 꿀팁**: AWS의 6대 클라우드 장점 — **가변 비용**(종량제), **규모의 경제**, **용량 추측 불필요**, **속도와 민첩성**, **데이터 센터 운영 집중 불필요**, **글로벌 확장**. 온프레미스 대비 장점 문제는 항상 종량제·민첩성·선투자 불필요가 핵심입니다.

## Q3. 여러 리전 사용자에게 빠른 응답 제공

여러 AWS 영역의 사용자에게 자주 액세스하는 데이터에 대해 가장 빠른 애플리케이션 응답 시간을 제공하는 솔루션은 무엇입니까?

- A. 여러 가용성 영역에 걸친 AWS CloudTrail
- B. Amazon CloudFront의 에지 위치
- C. 여러 지역의 AWS CloudFormation
- D. AWS Direct Connect를 통한 가상 프라이빗 게이트웨이

**정답: B**

✅ **B. Amazon CloudFront의 에지 위치**: CloudFront는 AWS의 CDN(콘텐츠 전송 네트워크) 서비스로, 전 세계 400개 이상의 에지 위치에 콘텐츠를 캐시하여 사용자에게 가장 가까운 위치에서 데이터를 제공함으로써 응답 시간을 최소화합니다.

❌ **A. 여러 가용성 영역에 걸친 AWS CloudTrail**: CloudTrail은 AWS API 호출을 로깅하는 감사/모니터링 서비스로, 응답 시간 개선과 무관합니다.

❌ **C. 여러 지역의 AWS CloudFormation**: CloudFormation은 인프라를 코드로 배포하는 IaC 서비스이며, 콘텐츠 캐싱이나 응답 시간 최적화 기능이 없습니다.

❌ **D. AWS Direct Connect를 통한 가상 프라이빗 게이트웨이**: Direct Connect는 온프레미스와 AWS 간의 전용 네트워크 연결을 제공하지만, 글로벌 사용자 응답 속도 최적화를 위한 솔루션은 아닙니다.

💡 **시험 꿀팁**: **CloudFront = CDN = 에지 위치(Edge Location) = 캐싱 = 응답 속도 향상**. "전 세계 사용자에게 빠른 응답", "콘텐츠 캐싱", "낮은 지연 시간" 키워드가 나오면 무조건 CloudFront를 선택하세요.

## Q4. 자체 관리 데이터베이스 실행 서비스

다음 중 자체 관리 데이터베이스를 실행하는 데 사용할 수 있는 AWS 서비스는 무엇입니까?

- A. Amazon Route 53
- B. AWS X-Ray
- C. AWS Snowmobile
- D. Amazon Elastic Compute Cloud(Amazon EC2)

**정답: D**

✅ **D. Amazon EC2**: EC2는 가상 서버(인스턴스)를 제공하는 서비스로, 사용자가 OS 설치부터 데이터베이스 소프트웨어 설치 및 관리까지 직접 제어하는 자체 관리형 데이터베이스를 구축하고 실행할 수 있습니다.

❌ **A. Amazon Route 53**: Route 53은 DNS 웹 서비스로, 도메인 이름 등록 및 트래픽 라우팅에 사용됩니다. 데이터베이스 실행 기능이 없습니다.

❌ **B. AWS X-Ray**: X-Ray는 애플리케이션 성능 분석 및 디버깅을 위한 분산 추적 서비스입니다. 데이터베이스 실행과 무관합니다.

❌ **C. AWS Snowmobile**: Snowmobile은 엑사바이트 규모의 데이터를 물리적으로 AWS로 이전하는 초대형 데이터 마이그레이션 트럭 서비스입니다. 데이터베이스 실행 서비스가 아닙니다.

💡 **시험 꿀팁**: 데이터베이스 관련 문제는 **관리형(Managed) vs 자체 관리(Self-managed)** 구분이 핵심입니다. RDS/Aurora = AWS 관리형, EC2 위에 DB 직접 설치 = 자체 관리형. 자체 관리가 필요한 경우(특수 DB 엔진, 세밀한 제어) → EC2 사용.

## Q5. 엔터프라이즈 지원 전용 혜택

엔터프라이즈 지원을 사용하는 사용자에게 제공되는 독점적 혜택은 무엇입니까?

- A. 기술 프로젝트 관리자에 대한 액세스 권한
- B. 기술 계정 관리자에 대한 액세스 권한
- C. 클라우드 지원 엔지니어에 대한 액세스
- D. 솔루션 설계자에 대한 액세스

**정답: B**

✅ **B. 기술 계정 관리자(TAM)에 대한 액세스 권한**: TAM(Technical Account Manager)은 Enterprise Support 플랜에서만 제공되는 전담 AWS 전문가로, 고객의 AWS 환경을 지속적으로 관리하고 최적화를 지원하는 독점 혜택입니다.

❌ **A. 기술 프로젝트 관리자에 대한 액세스 권한**: AWS Support 플랜에 기술 프로젝트 관리자(Technical Project Manager)를 제공하는 옵션은 존재하지 않습니다.

❌ **C. 클라우드 지원 엔지니어에 대한 액세스**: 클라우드 지원 엔지니어는 Developer 플랜 이상에서 이용 가능하므로 Enterprise 전용 혜택이 아닙니다.

❌ **D. 솔루션 설계자에 대한 액세스**: AWS 솔루션 설계자 상담은 특정 프로그램(예: AWS IQ)을 통해 이용 가능하며, Enterprise Support의 독점 혜택이 아닙니다.

💡 **시험 꿀팁**: AWS 지원 플랜 핵심 암기 — **Basic**(무료, 기본 문서), **Developer**(업무시간 이메일), **Business**(24/7 전화+Trusted Advisor 전체), **Enterprise**(TAM + 15분 응답 + Concierge). TAM = Enterprise Only!

## Q6. 자연재해로 인한 리전 장애 대응

자연 재해가 전체 지역에 영향을 미치는 경우 사용자가 AWS 서비스 중단을 어떻게 방지할 수 있습니까?

- A. AWS 영역 내의 여러 가용성 영역에 걸쳐 애플리케이션을 배포합니다.
- B. 지리적 영역 내에서 하이브리드 클라우드 컴퓨팅 배치 모델을 사용합니다.
- C. 여러 AWS 영역에 걸쳐 애플리케이션을 배포합니다.
- D. AWS 아티팩트를 사용하여 애플리케이션 아티팩트를 저장하고 여러 AWS 영역에서 복제합니다.

**정답: C**

✅ **C. 여러 AWS 리전에 걸쳐 애플리케이션을 배포합니다**: 자연재해가 특정 리전 전체에 영향을 미칠 경우, 여러 리전에 애플리케이션을 분산 배포하면 한 리전이 장애를 겪더라도 다른 리전에서 서비스를 지속할 수 있습니다.

❌ **A. AWS 영역 내의 여러 가용성 영역에 걸쳐 애플리케이션을 배포합니다**: 다중 AZ 배포는 가용성 영역 수준의 장애에는 효과적이지만, 자연재해가 전체 리전에 영향을 미치는 경우에는 대응이 불가능합니다.

❌ **B. 지리적 영역 내에서 하이브리드 클라우드 컴퓨팅 배치 모델을 사용합니다**: 하이브리드 클라우드는 온프레미스와 클라우드를 혼합하는 방식이지만, 동일 지리적 영역 내의 자연재해에는 여전히 취약할 수 있습니다.

❌ **D. AWS 아티팩트를 사용하여 애플리케이션 아티팩트를 저장하고 여러 AWS 영역에서 복제합니다**: AWS Artifact는 규정 준수 문서 및 보안 보고서를 제공하는 서비스이며, 애플리케이션 배포나 재해 복구와 무관합니다.

💡 **시험 꿀팁**: 장애 복구 범위 암기 — **단일 AZ 장애** → 다중 AZ 배포로 대응, **리전 전체 장애(자연재해 등)** → 다중 리전 배포로 대응. "전체 지역(리전) 영향"이라는 키워드가 보이면 답은 항상 **다중 리전(Multi-Region)**입니다.

## Q7. 스타트업 컴퓨팅 비용 절감

성장하는 신생 기업에서 AWS가 컴퓨팅 비용을 가장 효과적으로 절감하는 방법은 무엇입니까?

- A. 최대 사용량에 대한 온디맨드 리소스를 제공합니다.
- B. 개별 개발자 환경의 프로비저닝을 자동화합니다.
- C. 고객 관계 관리를 자동화합니다.
- D. 고정된 월간 컴퓨팅 예산을 구현합니다.

**정답: A**

✅ **A. 최대 사용량에 대한 온디맨드 리소스를 제공합니다**: AWS의 온디맨드 모델은 실제 사용량에 따라 리소스를 즉시 확장하거나 축소할 수 있어, 과도한 사전 투자 없이 최대 부하 시에도 필요한 컴퓨팅 자원을 확보할 수 있습니다. 스타트업은 고정 인프라 비용 없이 성장에 따라 비용을 조절할 수 있습니다.

❌ **B. 개별 개발자 환경의 프로비저닝을 자동화합니다**: 개발자 환경 자동화는 생산성 향상에 도움이 될 수 있지만, 이것이 AWS의 핵심 비용 절감 메커니즘은 아닙니다.

❌ **C. 고객 관계 관리를 자동화합니다**: CRM 자동화는 비즈니스 운영 효율화와 관련된 것으로, AWS 컴퓨팅 비용 절감과 직접적인 연관이 없습니다.

❌ **D. 고정된 월간 컴퓨팅 예산을 구현합니다**: 고정 예산은 비용 관리 도구이지, AWS가 컴퓨팅 비용을 절감하는 방식이 아닙니다.

💡 **시험 꿀팁**: **온디맨드(On-Demand) = 선불 없음 + 사용량 기반 + 탄력적 확장**. 스타트업, 변동성 높은 워크로드, 단기 프로젝트 키워드 → 온디맨드가 최적. 반대로 안정적·예측 가능한 워크로드 → 예약 인스턴스(Reserved Instances)로 비용 절감.

## Q8. 빠른 시장 진출과 요건 변경 대응

한 스타트업이 시장에 빨리 진출해야 하는 새로운 애플리케이션을 개발하고 있다. 가까운 시일 내에 적용 요건을 조정할 필요가 있을 수 있습니다. 다음 중 이러한 특정 요구사항을 충족하는 AWS 클라우드의 특징은 무엇입니까?

- A. 탄력성
- B. 신뢰성
- C. 성능
- D. 민첩성

**정답: D**

✅ **D. 민첩성(Agility)**: 민첩성은 AWS 클라우드의 핵심 장점으로, 새로운 IT 리소스를 몇 분 만에 프로비저닝하고 빠르게 실험·출시·변경할 수 있는 능력을 말합니다. 빠른 시장 진출(Time-to-Market)과 요건 변화에 빠르게 적응하는 것이 민첩성의 핵심입니다.

❌ **A. 탄력성(Elasticity)**: 탄력성은 수요 변화에 따라 컴퓨팅 자원을 자동으로 확장하거나 축소하는 능력입니다. 빠른 시장 진출보다는 리소스 자동 조정에 초점이 맞춰져 있습니다.

❌ **B. 신뢰성(Reliability)**: 신뢰성은 시스템이 예상대로 작동하고 장애를 복구하는 능력입니다. 빠른 출시 및 요건 변경 대응과는 다른 개념입니다.

❌ **C. 성능(Performance)**: 성능은 워크로드의 처리 속도와 효율성에 관한 것으로, 빠른 시장 진출 및 유연한 요건 변경과는 직접적인 연관이 없습니다.

💡 **시험 꿀팁**: **민첩성(Agility)** = 빠른 실험·출시·변경 가능 + Time-to-Market 단축. vs **탄력성(Elasticity)** = 자동 확장/축소 (Auto Scaling). 두 단어를 혼동하지 마세요! "빠르게 출시", "빠르게 변경", "시장 대응" → 민첩성.

## Q10. Amazon Shield Standard DDoS 완화 서비스 (두 개 선택)

다음 중 Amazon Shield Standard를 통한 분산 서비스 거부(DDoS) 완화 기능이 있는 서비스는 무엇입니까? (2개 선택)

- A. AWS WAF
- B. Amazon DynamoDB
- C. Amazon EC2
- D. Amazon CloudFront
- E. Amazon Inspector

**정답: C, D**

✅ **C. Amazon EC2**: Amazon Shield Standard는 AWS의 모든 고객에게 자동으로 제공되며, EC2 인스턴스에 대한 네트워크 및 전송 계층(Layer 3, Layer 4) DDoS 공격을 자동으로 감지하고 완화합니다.

✅ **D. Amazon CloudFront**: CloudFront는 Amazon Shield Standard와 통합되어 CDN 엣지 위치에서 DDoS 공격을 자동으로 완화합니다. Route 53, Global Accelerator와 함께 Shield가 자동 적용되는 대표 서비스입니다.

❌ **A. AWS WAF**: WAF(Web Application Firewall)는 Shield와 함께 사용하면 강력하지만, WAF 자체는 Shield Standard의 DDoS 완화 기능을 가진 서비스가 아니라 별도의 웹 방화벽 서비스입니다.

❌ **B. Amazon DynamoDB**: DynamoDB는 관리형 NoSQL 데이터베이스 서비스로, Shield Standard DDoS 완화의 주요 대상 서비스가 아닙니다.

❌ **E. Amazon Inspector**: Inspector는 EC2 인스턴스 및 컨테이너 이미지의 취약점을 자동으로 검사하는 보안 서비스입니다. DDoS 완화와는 무관합니다.

💡 **시험 꿀팁**: **Shield Standard 자동 적용 서비스** = CloudFront, Route 53, Global Accelerator, ELB, EC2. Shield Standard는 무료·자동 제공, Shield Advanced는 유료로 더 강력한 보호와 DDoS 비용 보호 제공.

## Q11. 클라우드 TCO 비용 요소 (세 개 선택)

클라우드 TCO(총 소유 비용) 모델을 구축할 때 AWS에서 실행되는 워크로드에 대해 고려해야 할 비용 요소는 무엇입니까? (3가지 선택)

- A. 비용 계산
- B. 시설비
- C. 스토리지 비용
- D. 데이터 전송 비용
- E. 네트워크 인프라 비용
- F. 하드웨어 라이프사이클 비용

**정답: C, D, E**

✅ **C. 스토리지 비용**: AWS에서 S3, EBS, EFS 등 스토리지 서비스 사용에 따른 비용은 클라우드 TCO의 직접 비용 요소입니다.

✅ **D. 데이터 전송 비용**: AWS에서 인터넷으로 데이터를 전송(Egress)할 때 발생하는 비용은 TCO 계산 시 반드시 포함해야 하는 요소입니다.

✅ **E. 네트워크 인프라 비용**: VPC, Direct Connect, 로드 밸런서 등 네트워크 관련 AWS 서비스 비용은 클라우드 TCO에 포함됩니다.

❌ **A. 비용 계산**: 비용 계산 자체는 TCO를 구성하는 비용 항목이 아니라 분석 프로세스입니다.

❌ **B. 시설비**: 데이터 센터 시설비(임대료, 전기, 냉각)는 온프레미스 TCO 요소이며, 클라우드(AWS) TCO에는 포함되지 않습니다. AWS는 이 비용을 대신 부담합니다.

❌ **F. 하드웨어 라이프사이클 비용**: 서버 구매·교체·폐기 비용은 온프레미스의 CapEx 항목으로, 클라우드에서는 AWS가 관리하므로 고객의 TCO에 포함되지 않습니다.

💡 **시험 꿀팁**: 클라우드 TCO = **컴퓨팅 비용 + 스토리지 비용 + 데이터 전송 비용 + 네트워크 비용**. 온프레미스 TCO = 위 항목 + 시설비 + 하드웨어 구매/유지/교체 비용 + 인건비. "클라우드 이전 시 제거되는 비용" = 시설비, 하드웨어 비용이 핵심!

## Q12. Amazon Rekognition 시간 절약 이점

Amazon Rekognition을 사용하면 시간을 절약할 수 있는 이점이 무엇입니까?

- A. Amazon Rekognition은 이미지의 자동 워터마킹을 제공합니다.
- B. Amazon Rekognition은 사진에 나타나는 물체의 자동 감지를 제공합니다.
- C. Amazon Rekognition은 수백만 개의 이미지 크기를 자동으로 조정할 수 있는 기능을 제공합니다.
- D. Amazon Rekognition은 Amazon Mechanical Turk를 사용하여 인간이 물체 감지 작업에 입찰할 수 있도록 합니다.

**정답: B**

✅ **B. Amazon Rekognition은 사진에 나타나는 물체의 자동 감지를 제공합니다**: Rekognition은 AI/ML 기반 이미지 및 비디오 분석 서비스로, 사진 속 객체, 얼굴, 텍스트, 장면 등을 자동으로 감지·분석합니다. 사람이 수동으로 분류하던 작업을 자동화하여 시간을 크게 절약합니다.

💡 **시험 꿀팁**: **AWS AI/ML 서비스 암기** — Rekognition(이미지/얼굴/영상 분석), Transcribe(음성→텍스트), Translate(번역), Comprehend(자연어 처리), Polly(텍스트→음성), Lex(챗봇). "이미지·영상에서 객체·얼굴 감지" = Rekognition.

- C. 프로젝트 관리

❌ **D. 운영 체제 관리**: 운영 체제 관리는 클라우드(EC2)에서도 고객이 담당하는 경우가 많으므로, 두 환경 간 TCO 비교에서 차별화된 항목으로 보기 어렵습니다.

💡 **시험 꿀팁**: TCO 비교 시 온프레미스에만 있는 비용 항목 = **물리적 데이터 센터 비용**(시설 임대, 냉각, 전력, 물리 보안, 하드웨어 구매·유지·교체). AWS로 이전하면 이 비용들이 제거됩니다.

💡 **시험 꿀팁**: 공유 책임 모델 핵심 구분 — **AWS 책임(클라우드 자체)**: 물리적 인프라, 네트워크 인프라, 하드웨어, 데이터 센터, 호스트 OS, 하이퍼바이저. **고객 책임(클라우드 내부)**: 게스트 OS 패치, 애플리케이션 코드, 데이터 암호화, IAM 설정, 보안 그룹 구성.

## Q16. 열린 보안 그룹 식별 AWS 도구

- D. Amazon EC2 대시보드

❌ **A. AWS 조직(AWS Organizations)**: AWS Organizations는 여러 AWS 계정을 중앙에서 관리하는 서비스로, 개별 보안 그룹 구성 검사 기능이 없습니다.

❌ **C. AWS 사용량 보고서**: 사용량 보고서는 AWS 서비스 사용량 및 비용을 추적하는 데 사용되며, 보안 그룹 구성 검사 기능이 없습니다.

❌ **D. Amazon EC2 대시보드**: EC2 대시보드는 인스턴스 현황을 보여주지만, 자동화된 보안 그룹 취약점 검사 기능은 제공하지 않습니다.

💡 **시험 꿀팁**: **Trusted Advisor = 자동 보안 검사 도구**. 5개 카테고리 중 보안 항목에는 오픈된 보안 그룹, 공개 접근 S3 버킷, MFA 미설정 루트 계정, 노출된 IAM 키 등이 포함됩니다. "자동으로 보안 취약점 탐지" 키워드 → Trusted Advisor.

## Q17. 예상 월 청구서 기반 경고 생성 서비스

예상 월 청구서를 기반으로 경고를 생성하는 데 사용할 수 있는 AWS 서비스는 무엇입니까?

- A. AWS Config
- B. Amazon CloudWatch
- C. AWS X-Ray
- D. AWS CloudTrail

**정답: B**

✅ **B. Amazon CloudWatch**: CloudWatch는 AWS 리소스와 애플리케이션 모니터링 서비스로, 예상 청구 금액(EstimatedCharges) 지표에 대한 알람을 설정하여 월간 비용이 특정 임계값을 초과할 것으로 예상될 때 경고를 받을 수 있습니다.

❌ **A. AWS Config**: AWS Config는 AWS 리소스 구성 변경 사항을 추적하고 규정 준수를 평가하는 서비스입니다. 청구서 기반 경고 생성 기능이 없습니다.

❌ **C. AWS X-Ray**: X-Ray는 애플리케이션의 성능 분석과 분산 추적을 위한 서비스입니다. 비용 모니터링 기능이 없습니다.

❌ **D. AWS CloudTrail**: CloudTrail은 AWS 계정 내의 API 호출과 사용자 활동을 로깅하는 감사 서비스입니다. 청구서 기반 알람 기능을 제공하지 않습니다.

💡 **시험 꿀팁**: **CloudWatch 청구 알람** = Billing 지표(EstimatedCharges)에 임계값 설정 → SNS 알림. 참고로 **AWS Budgets**도 비용 임계값 알람 기능이 있지만, "예상 청구서 기반 경고"라는 표현은 CloudWatch Billing Alarm을 가리킵니다. 두 서비스의 차이를 구분하세요.

## Q18. 최대 할인 EC2 가격 모델

주문형 인스턴스에 비해 가장 큰 할인을 제공하는 Amazon EC2 가격 모델은 무엇입니까?

- A. 1년 기간 동안의 부분 사전 예약 인스턴스
- B. 1년 임기 동안의 모든 사전 예약 인스턴스
- C. 3년 임기 동안의 모든 사전 예약 인스턴스
- D. 3년 임기 동안 사전 예약 인스턴스 없음

**정답: C**

✅ **C. 3년 임기 동안의 모든 사전(All Upfront) 예약 인스턴스**: Reserved Instance에서 최대 할인은 약정 기간이 길수록(3년 > 1년), 선불 결제 방식이 클수록(All Upfront > Partial Upfront > No Upfront) 커집니다. 3년 All Upfront 예약 인스턴스는 온디맨드 대비 최대 72%까지 할인을 제공합니다.

❌ **A. 1년 기간 동안의 부분 사전(Partial Upfront) 예약 인스턴스**: 1년 약정 + 부분 선불은 상대적으로 적은 할인율을 제공합니다.

❌ **B. 1년 임기 동안의 모든 사전(All Upfront) 예약 인스턴스**: 1년 All Upfront는 1년 기준 최대 할인이지만, 3년 약정보다는 할인율이 낮습니다.

❌ **D. 3년 임기 동안 사전 예약 없음(No Upfront)**: No Upfront 방식은 초기 비용 없이 월별 지불하므로 할인율이 All Upfront보다 작습니다.

💡 **시험 꿀팁**: EC2 가격 할인 순서 암기 — **Savings Plans ≈ Reserved Instance(All Upfront, 3년) > Spot Instance(특정 상황) > Reserved Instance(1년) > On-Demand > On-Demand**. 예약 인스턴스 할인 공식: **기간 길수록 + 선불 많을수록 = 할인 커짐**.

## Q19. AWS의 책임 항목 (공유 책임 모델)

다음 중 AWS의 책임은 무엇입니까?

- A. AWS IAM(Identity and Access Management) 사용자 및 그룹 설정
- B. 수명이 다했을 때 물리적으로 스토리지 미디어 파괴
- C. 게스트 운영 체제 패치 적용
- D. Amazon EC2 인스턴스에서 보안 설정 구성

**정답: B**

✅ **B. 수명이 다했을 때 물리적으로 스토리지 미디어 파괴**: 물리적 하드웨어의 수명 주기 관리(폐기 포함)는 AWS의 책임입니다. AWS는 데이터 보안을 위해 수명이 다한 스토리지 장치를 안전하게 물리적으로 파괴하거나 삭제합니다.

❌ **A. AWS IAM 사용자 및 그룹 설정**: IAM 사용자 생성, 그룹 설정, 권한 부여는 고객의 책임입니다. AWS는 IAM 서비스를 제공하지만 실제 구성은 고객이 합니다.

❌ **C. 게스트 운영 체제 패치 적용**: EC2 인스턴스의 게스트 OS 패치 및 업데이트는 고객의 책임입니다. AWS는 호스트 OS(하이퍼바이저)만 관리합니다.

❌ **D. Amazon EC2 인스턴스에서 보안 설정 구성**: EC2 인스턴스의 보안 그룹, 방화벽, 애플리케이션 보안 설정은 고객의 책임입니다.

💡 **시험 꿀팁**: **물리적 하드웨어 관련 = 항상 AWS 책임**. 물리적 서버 구매, 데이터 센터 보안, 물리 미디어 파괴, 네트워크 장비 관리, 하이퍼바이저 → AWS. 가상 머신 위(OS, 애플리케이션, 데이터, IAM) → 고객.

## Q20. AWS 사용의 장점

다음 중 AWS를 사용할 때의 장점은 무엇입니까?

- A. AWS는 사용자 데이터를 감사한다.
- B. 데이터는 자동으로 보안됩니다.
- C. 용량 요구에 대한 추측은 없다.
- D. AWS는 컴플라이언스 요구사항을 관리합니다.

**정답: C**

✅ **C. 용량 요구에 대한 추측은 없다**: AWS 클라우드의 핵심 장점 중 하나로, 온프레미스에서는 미래 수요를 예측하여 과도하거나 부족한 인프라를 미리 구축해야 하지만, AWS에서는 필요에 따라 즉시 리소스를 추가하거나 줄일 수 있어 용량 추측이 필요 없습니다.

❌ **A. AWS는 사용자 데이터를 감사한다**: AWS는 고객 데이터에 접근하거나 감사하지 않습니다. 고객 데이터 관리와 감사는 고객의 책임입니다.

❌ **B. 데이터는 자동으로 보안됩니다**: 데이터 암호화, 접근 제어 등 데이터 보안 설정은 고객이 구성해야 하며 자동으로 보안되지는 않습니다. 공유 책임 모델에 따라 고객의 책임입니다.

❌ **D. AWS는 컴플라이언스 요구사항을 관리합니다**: AWS는 인프라 수준의 컴플라이언스를 지원하지만, 고객 애플리케이션과 데이터에 대한 컴플라이언스 요구사항 관리는 고객의 책임입니다.

💡 **시험 꿀팁**: AWS 6대 클라우드 장점 재확인 — ① 초기 비용 → 가변 비용 전환, ② 규모의 경제, ③ **용량 추측 불필요**, ④ 속도와 민첩성 향상, ⑤ 데이터 센터 운영 부담 제거, ⑥ 몇 분 만에 글로벌 확장. "추측 없음(Stop guessing capacity)" 문구는 AWS 공식 장점입니다.
