## Q1. EC2 인스턴스에 도달하는 IP 트래픽 정보를 캡처하는 VPC 기능

Amazon EC2 인스턴스에 도달하는 IP 트래픽에 대한 정보 캡처를 지원하는 Amazon VPC 기능은 무엇입니까?

- A. 보안 그룹
- B. Elastic Network Interface
- C. 네트워크 ACL
- D. VPC Flow Logs

**정답: D**

✅ **D. VPC Flow Logs**: VPC Flow Logs는 VPC의 네트워크 인터페이스를 드나드는 IP 트래픽에 대한 정보를 캡처할 수 있는 기능입니다. 로그는 분석 및 문제 해결을 위해 Amazon CloudWatch Logs 또는 Amazon S3에 게시할 수 있습니다.

❌ **A. 보안 그룹**: 보안 그룹은 인스턴스 수준에서 인바운드 및 아웃바운드 트래픽을 제어하는 가상 방화벽 역할을 하지만, 트래픽 정보를 캡처하거나 로그를 남기지 않습니다.

❌ **B. Elastic Network Interface**: ENI는 VPC의 논리적 네트워킹 구성 요소로 가상 네트워크 카드를 나타냅니다. 자체적으로 로깅 또는 트래픽 캡처 기능이 없습니다.

❌ **C. 네트워크 ACL**: 네트워크 ACL은 서브넷 수준에서 상태 비저장 트래픽 필터링을 제공하지만, 트래픽 데이터를 로그하거나 캡처하지 않습니다.

💡 **시험 꿀팁**: VPC Flow Logs = 트래픽 모니터링/로깅(EC2 인스턴스). 보안 그룹 및 NACL = 트래픽 필터링/차단. Flow Logs는 캡처하고, 보안 그룹은 제어한다는 차이를 기억하세요.

## Q2. 용량 계획 없이 자동으로 애플리케이션을 확장하는 서비스

용량 계획을 결정하지 않고도 애플리케이션을 자동으로 확장하거나 축소할 수 있는 AWS 서비스는 무엇입니까?

- A. Amazon Auto Scaling
- B. Amazon Redshift
- C. AWS CloudTrail
- D. AWS Lambda

**정답: A**

✅ **A. Amazon Auto Scaling**: Amazon Auto Scaling은 수요에 따라 EC2 인스턴스 또는 기타 리소스의 수를 자동으로 조정하여 사전에 용량을 수동으로 계획하거나 프로비저닝할 필요가 없습니다. 수요가 증가하면 확장하고 감소하면 축소합니다.

❌ **B. Amazon Redshift**: Redshift는 대규모 데이터 세트의 분석 및 쿼리에 최적화된 완전 관리형 데이터 웨어하우스 서비스입니다. 애플리케이션의 일반적인 자동 확장을 위해 설계되지 않았습니다.

❌ **C. AWS CloudTrail**: CloudTrail은 API 호출 및 계정 활동을 기록하는 감사 및 거버넌스 서비스입니다. 리소스 확장과 관련이 없습니다.

❌ **D. AWS Lambda**: Lambda는 이벤트에 응답하여 함수 실행 수를 자동으로 확장하지만(서버리스), 이벤트 기반 컴퓨팅 서비스이지 기존 애플리케이션 인프라를 위한 범용 자동 확장 서비스가 아닙니다.

💡 **시험 꿀팁**: Amazon Auto Scaling = 수요에 따라 EC2 인스턴스를 자동으로 추가/제거. Lambda = 서버리스, 자동으로 확장하지만 이벤트 기반 컴퓨팅이며 스케일링 관리 서비스가 아닙니다.

## Q3. AWS Enterprise 지원에서만 이용 가능한 서비스

다른 AWS 지원 플랜에서는 이용할 수 없고 AWS Enterprise 지원 사용자만 이용할 수 있는 서비스 또는 기능은 무엇입니까?

- A. AWS Trusted Advisor
- B. AWS 지원 케이스
- C. Concierge 팀
- D. Amazon Connect

**정답: C**

✅ **C. Concierge 팀**: AWS Concierge 팀은 Enterprise 지원 고객에게만 독점적으로 제공됩니다. Concierge 팀은 청구 및 계정 관련 문의를 지원하고 고객이 AWS 계정을 효율적으로 관리할 수 있도록 개인화된 안내를 제공합니다.

❌ **A. AWS Trusted Advisor**: Trusted Advisor는 Business, Enterprise On-Ramp 및 Enterprise 지원 고객에게 제공됩니다. 일부 검사는 Developer 및 Basic 플랜 사용자에게도 제공되므로 Enterprise 지원에 독점적이지 않습니다.

❌ **B. AWS 지원 케이스**: 지원 케이스를 열 수 있는 기능은 모든 유료 지원 플랜(Developer, Business, Enterprise)에서 제공되며, Enterprise에만 독점적이지 않습니다.

❌ **D. Amazon Connect**: Amazon Connect는 AWS 클라우드 기반 콜센터 서비스이며 별도로 구매 가능한 제품이지 Enterprise 지원 플랜의 독점 혜택이 아닙니다.

💡 **시험 꿀팁**: Enterprise 지원 독점 혜택 = Concierge 팀 + 기술 계정 관리자(TAM) + Well-Architected 검토 접근. Concierge = 청구/계정 지원, TAM = 기술 안내.

## Q4. 관리형 MySQL 데이터베이스 마이그레이션 서비스

회사가 MySQL 데이터베이스를 AWS로 마이그레이션하려 하지만 데이터베이스 관리자는 프로비저닝, 패치, 백업 수행과 같은 일상적인 작업을 처리할 예산이 없습니다. 이 사용 사례를 지원하는 AWS 서비스는 무엇입니까?

- A. Amazon RDS
- B. Amazon DynamoDB
- C. Amazon DocumentDB
- D. Amazon ElastiCache

**정답: A**

✅ **A. Amazon RDS**: Amazon Relational Database Service(RDS)는 MySQL을 지원하는 완전 관리형 관계형 데이터베이스 서비스입니다. AWS는 하드웨어 프로비저닝, 데이터베이스 설정, 패치 및 자동 백업과 같은 일상적인 관리 작업을 처리하여 DBA가 이러한 작업으로부터 자유로울 수 있습니다.

❌ **B. Amazon DynamoDB**: DynamoDB는 완전 관리형 NoSQL 데이터베이스 서비스입니다. MySQL 또는 관계형 데이터베이스 스키마를 지원하지 않으므로 MySQL 데이터베이스를 그대로 마이그레이션하는 데 사용할 수 없습니다.

❌ **C. Amazon DocumentDB**: DocumentDB는 MongoDB와 호환되는 완전 관리형 문서 데이터베이스 서비스입니다. MySQL과 호환되지 않으며 JSON 형태의 문서 워크로드용으로 설계되었습니다.

❌ **D. Amazon ElastiCache**: ElastiCache는 Redis 및 Memcached를 지원하는 인메모리 캐싱 서비스입니다. 관계형 데이터베이스가 아니며 MySQL 데이터베이스를 교체하거나 호스팅할 수 없습니다.

💡 **시험 꿀팁**: Amazon RDS = 관리형 관계형 DB(MySQL, PostgreSQL, Oracle, SQL Server, MariaDB). AWS는 패치, 백업, 복제를 관리합니다. 고객은 데이터, 쿼리 및 애플리케이션 수준 구성을 관리합니다.

## Q5. 두 번째 AWS 리전으로 확장하는 방법

회사가 하나의 AWS 리전에서 두 번째 AWS 리전으로 확장하려 합니다. 새 리전 지원을 시작하려면 어떻게 해야 합니까?

- A. AWS 계정 관리자에게 연락하여 새 계약에 서명합니다.
- B. 가용 영역을 새 리전으로 이동합니다.
- C. 두 번째 리전에 리소스를 배포하기 시작합니다.
- D. 새 리전용 AWS 관리 콘솔을 다운로드합니다.

**정답: C**

✅ **C. 두 번째 리전에 리소스를 배포하기 시작합니다**: AWS 리전은 전 세계적으로 이용 가능하며 추가 계약이나 합의 없이 사용할 수 있습니다. AWS 관리 콘솔, CLI 또는 API를 통해 원하는 리전에서 리소스(EC2, S3, RDS 등)를 시작하기만 하면 됩니다.

❌ **A. AWS 계정 관리자에게 연락하여 새 계약 서명**: AWS는 종량제 모델로 운영됩니다. 추가 리전을 사용하기 위해 새 계약이 필요하지 않으며 사용하기 시작하고 소비한 만큼만 지불하면 됩니다.

❌ **B. 가용 영역을 새 리전으로 이동**: 가용 영역은 리전 내의 고정된 물리적 위치로 이동할 수 없습니다. 각 리전에는 이미 자체 AZ 세트가 있습니다.

❌ **D. 새 리전용 AWS 관리 콘솔 다운로드**: AWS 관리 콘솔은 모든 리전에 대해 동일한 웹 기반 인터페이스입니다. 리전별 별도 다운로드가 필요하지 않습니다.

💡 **시험 꿀팁**: AWS 글로벌 인프라 = 리전 > 가용 영역 > 데이터 센터. 새 계약, 별도 콘솔 없이 즉시 모든 리전에 배포 가능합니다. 일부 옵트인 리전(예: 홍콩 ap-east-1)은 계정 설정에서 활성화가 필요합니다.

## Q6. 물리적 서버 규정 준수 요구 사항을 충족하는 EC2 인스턴스 요금 옵션

사용자가 워크로드를 물리적 서버에서 호스팅해야 하는 규정 준수 및 소프트웨어 라이선스 요구 사항을 충족해야 합니다. 이러한 요구 사항을 충족하는 Amazon EC2 인스턴스 요금 옵션은 무엇입니까?

- A. 전용 호스트
- B. 전용 인스턴스
- C. 스팟 인스턴스
- D. 예약 인스턴스

**정답: A**

✅ **A. 전용 호스트**: 전용 호스트는 전적으로 사용자 전용인 물리적 EC2 서버입니다. 서버에서 인스턴스가 배치되는 방식에 대한 가시성과 제어를 제공하여 소켓별, 코어별 또는 VM별 소프트웨어 라이선스(예: Windows Server, SQL Server)에 필요합니다. 규정 준수 요구 사항(물리적 격리)과 소프트웨어 라이선스 요구 사항을 모두 충족합니다.

❌ **B. 전용 인스턴스**: 전용 인스턴스는 단일 고객 계정 전용 하드웨어에서 실행되지만, 기본 물리적 호스트에 대한 가시성을 제공하지 않습니다. 따라서 호스트별 소프트웨어 라이선스 규정 준수에 사용할 수 없습니다.

❌ **C. 스팟 인스턴스**: 스팟 인스턴스는 할인된 비용으로 여분의 EC2 용량을 사용하지만 언제든지 중단될 수 있습니다. 물리적 호스트 배치에 대한 보장이 없으며 규정 준수 기반 워크로드에 적합하지 않습니다.

❌ **D. 예약 인스턴스**: 예약 인스턴스는 약정(1년 또는 3년) 대신 온디맨드 인스턴스에 적용되는 요금 할인입니다. 물리적 호스트 격리를 보장하거나 라이선스 목적으로 물리적 서버 가시성을 제공하지 않습니다.

💡 **시험 꿀팁**: 전용 호스트 = 물리적 서버 가시성 + 호스트별 라이선스(BYOL). 전용 인스턴스 = 하드웨어 격리하지만 호스트 가시성 없음. 핵심 구분: "소프트웨어 라이선스" 또는 "소켓/코어별"이 언급되면 전용 호스트를 선택하세요.

## Q7. 데이터 암호화에 사용할 수 있는 암호화 키를 생성하는 AWS 서비스 (2개 선택)

데이터 암호화에 사용할 수 있는 암호화 키를 생성하는 방법을 제공하는 AWS 서비스는 무엇입니까? (2개 선택)

- A. Amazon Macie
- B. AWS Certificate Manager
- C. AWS Key Management Service (AWS KMS)
- D. AWS Secrets Manager
- E. AWS CloudHSM

**정답: C, E**

✅ **C. AWS Key Management Service (AWS KMS)**: AWS KMS는 데이터를 암호화하는 데 사용되는 암호화 키를 쉽게 만들고 제어할 수 있는 관리형 서비스입니다. 많은 AWS 서비스와 통합되며 대칭 및 비대칭 키 생성을 지원합니다.

✅ **E. AWS CloudHSM**: AWS CloudHSM은 AWS 클라우드 내의 전용 하드웨어 보안 모듈(HSM) 어플라이언스를 제공합니다. FIPS 140-2 Level 3 검증 하드웨어를 사용하여 자체 암호화 키를 생성하고 관리할 수 있어 엄격한 규정 준수 요구 사항을 충족합니다.

❌ **A. Amazon Macie**: Macie는 기계 학습을 사용하여 Amazon S3에 저장된 민감한 데이터를 발견하고 보호하는 데이터 보안 서비스입니다. 암호화 키를 생성하지 않습니다.

❌ **B. AWS Certificate Manager**: ACM은 AWS 서비스와 함께 사용하기 위한 SSL/TLS 인증서를 프로비저닝, 관리 및 배포합니다. 데이터 암호화를 위한 범용 암호화 키 생성이 아닌 인증서(공개 키 인프라)를 처리합니다.

❌ **D. AWS Secrets Manager**: Secrets Manager는 시크릿(데이터베이스 비밀번호, API 키 등)을 저장, 검색, 교체 및 관리하는 데 도움이 됩니다. 암호화 키를 생성하지 않습니다.

💡 **시험 꿀팁**: KMS = 관리형 암호화 키, AWS 서비스와 통합, 사용 편리. CloudHSM = 전용 하드웨어 HSM, 키를 직접 제어, FIPS 140-2 Level 3 준수. 둘 다 키를 생성합니다. KMS는 소프트웨어 관리, CloudHSM은 하드웨어 관리입니다.

## Q8. 마이그레이션 전 예상 비용 절감에 대한 상세 보고서를 제공하는 AWS 도구

회사가 온프레미스에서 AWS 클라우드로 마이그레이션하려 합니다. 마이그레이션 후 예상 비용 절감에 대한 상세 보고서를 제공하는 AWS 도구 또는 서비스는 무엇입니까?

- A. AWS 총소유비용(TCO) 계산기
- B. Cost Explorer
- C. AWS Budgets
- D. AWS Migration Hub

**정답: A**

✅ **A. AWS 총소유비용(TCO) 계산기**: AWS TCO 계산기는 조직이 온프레미스 인프라에서 AWS로 마이그레이션하여 실현할 수 있는 비용 절감을 추정하도록 특별히 설계되었습니다. 현재 온프레미스 비용(하드웨어, 시설, 인력 등)과 예상 AWS 비용을 비교하는 상세 보고서를 생성합니다.

❌ **B. Cost Explorer**: AWS Cost Explorer는 시간 경과에 따른 실제 AWS 지출 및 사용량을 시각화하고 분석하는 데 사용됩니다. 온프레미스 환경과의 마이그레이션 전 비용 비교가 아닌 기존 AWS 비용을 분석합니다.

❌ **C. AWS Budgets**: AWS Budgets를 사용하면 사용자 정의 비용 및 사용량 예산을 설정하고 임계값이 초과될 때 알림을 받을 수 있습니다. 기존 AWS 사용량을 위한 비용 관리 및 알림 도구이지 마이그레이션 계획 계산기가 아닙니다.

❌ **D. AWS Migration Hub**: AWS Migration Hub는 여러 AWS 및 파트너 마이그레이션 도구에서 애플리케이션 마이그레이션 진행 상황을 추적하는 중앙 위치를 제공합니다. 비용 추정 도구가 아닌 마이그레이션 추적 도구입니다.

💡 **시험 꿀팁**: TCO 계산기 = "마이그레이션 전" 비용 비교(온프레미스 vs. AWS). Cost Explorer = "마이그레이션 후" 실제 AWS 지출 분석. TCO = 총소유비용 = 마이그레이션 전 계획 도구로 기억하세요.

## Q9. 클라우드 마이그레이션을 위한 애플리케이션 평가 도구 (2개 선택)

클라우드로의 마이그레이션을 위한 애플리케이션을 평가하는 데 도움이 되는 것은 무엇입니까? (2개 선택)

- A. AWS Trusted Advisor
- B. AWS Professional Services
- C. AWS Systems Manager
- D. AWS Partner Network(APN)
- E. AWS Secrets Manager

**정답: B, D**

✅ **B. AWS Professional Services**: AWS Professional Services는 조직이 클라우드 마이그레이션을 계획하고 실행하는 데 도움을 주는 AWS 전문가들로 구성된 글로벌 팀입니다. AWS로의 애플리케이션 평가 및 마이그레이션을 위한 평가 및 안내를 제공합니다.

✅ **D. AWS Partner Network(APN)**: APN은 기업의 클라우드 마이그레이션 평가, 계획 및 실행을 전문으로 하는 수천 개의 AWS 인증 컨설팅 및 기술 파트너로 구성됩니다. APN 파트너는 마이그레이션 평가 및 자문 서비스를 제공합니다.

❌ **A. AWS Trusted Advisor**: Trusted Advisor는 기존 AWS 환경에 대한 비용, 보안, 내결함성, 성능 및 서비스 한도 전반에 걸쳐 모범 사례 권장 사항을 제공합니다. 온프레미스 애플리케이션의 마이그레이션 적합성을 특별히 평가하지 않습니다.

❌ **C. AWS Systems Manager**: Systems Manager는 AWS 및 하이브리드 인프라에 대한 운영 인사이트와 관리 기능을 제공합니다. 운영 관리 도구이며, 마이그레이션 평가 서비스가 아닙니다.

❌ **E. AWS Secrets Manager**: Secrets Manager는 애플리케이션 시크릿(비밀번호, API 키 등)을 안전하게 저장하고 관리하는 서비스입니다. 마이그레이션을 위한 애플리케이션 평가에는 관련이 없습니다.

💡 **시험 꿀팁**: 마이그레이션 계획 및 평가에는 인적 전문 지식을 생각하세요: AWS Professional Services(AWS 자체 전문가) 및 APN 파트너(인증된 타사 컨설턴트). 기술 서비스가 아닌 "사람과 조직" 답변입니다.

## Q10. 데이터 보안 규정 준수를 위한 전용 하드웨어 어플라이언스 서비스

어떤 AWS 서비스가 AWS 클라우드 내의 전용 하드웨어 어플라이언스를 사용하여 사용자가 데이터 보안에 대한 계약 및 규제 규정 준수 요구 사항을 충족하는 데 도움이 됩니까?

- A. AWS Secrets Manager
- B. AWS CloudHSM
- C. AWS Key Management Service (AWS KMS)
- D. AWS Directory Service

**정답: B**

✅ **B. AWS CloudHSM**: AWS CloudHSM은 AWS 클라우드 내의 전용 단일 테넌트 하드웨어 보안 모듈(HSM) 어플라이언스를 제공합니다. FIPS 140-2 Level 3을 충족하는 물리적 하드웨어 장치로, 다른 고객과 장치를 공유하지 않습니다. 이 전용 하드웨어 측면이 핵심입니다.

❌ **A. AWS Secrets Manager**: Secrets Manager는 데이터베이스 자격 증명 및 API 키와 같은 시크릿을 안전하게 저장하고 관리합니다. 전용 하드웨어 어플라이언스를 사용하지 않으며 하드웨어 기반 규정 준수 표준을 충족하도록 설계되지 않았습니다.

❌ **C. AWS Key Management Service (AWS KMS)**: KMS는 관리형 키 관리 서비스이지만 AWS가 관리하는 공유(멀티 테넌트) 인프라를 사용합니다. 고객에게 전용 물리적 하드웨어 어플라이언스를 제공하지 않으므로 특정 엄격한 하드웨어 격리 규정 준수 요구 사항을 충족하지 못할 수 있습니다.

❌ **D. AWS Directory Service**: AWS Directory Service는 AWS 클라우드에서 관리형 Microsoft Active Directory를 제공합니다. ID 및 접근 관리 서비스이며 암호화 또는 데이터 보안 하드웨어 서비스가 아닙니다.

💡 **시험 꿀팁**: CloudHSM = 전용 하드웨어 + 단일 테넌트 + 고객이 키 제어 + FIPS 140-2 Level 3. KMS = AWS가 관리/공유 + 더 쉬운 통합 + FIPS 140-2 Level 2. 핵심 시험 키워드: "전용 하드웨어 어플라이언스" = 항상 CloudHSM을 가리킵니다.

## Q11. AWS 공유 책임 모델에서 고객이 관리하는 사항 (2개 선택)

AWS 공유 책임 모델에서 고객이 관리하는 것은 무엇입니까? (2개 선택)

- A. 물리적 스토리지 장치의 폐기
- B. 보안 그룹 및 ACL 구성
- C. Amazon RDS 인스턴스의 운영 체제에 대한 패치 관리
- D. 데이터 센터에 대한 물리적 접근 제어
- E. Amazon EC2 인스턴스의 운영 체제에 대한 패치 관리

**정답: B, E**

✅ **B. 보안 그룹 및 ACL 구성**: 보안 그룹과 네트워크 ACL은 AWS 리소스와 주고받는 트래픽을 정의하는 고객 관리 제어입니다. 이를 구성하는 것은 공유 책임 모델에 따라 전적으로 고객의 책임입니다.

✅ **E. Amazon EC2 인스턴스의 운영 체제 패치 관리**: EC2에서는 게스트 운영 체제(패치, 업데이트 및 보안 수정 설치 포함)에 대한 책임이 고객에게 있습니다. AWS는 기본 하이퍼바이저와 물리적 인프라를 관리합니다.

❌ **A. 물리적 스토리지 장치 폐기**: AWS는 스토리지 장치를 포함한 하드웨어의 물리적 보안과 적절한 폐기를 담당합니다. 고객은 물리적 하드웨어에 직접 접근할 수 없습니다.

❌ **C. Amazon RDS 인스턴스의 운영 체제 패치 관리**: RDS는 관리형 서비스입니다. AWS는 RDS의 OS 패치 및 데이터베이스 엔진 패치를 처리합니다. 고객은 데이터 및 데이터베이스 수준 구성을 담당하지만 OS 패치는 담당하지 않습니다.

❌ **D. 데이터 센터에 대한 물리적 접근 제어**: AWS는 자체 데이터 센터의 물리적 보안에 전적으로 책임이 있습니다. 고객은 AWS 시설에 물리적으로 접근할 수 없습니다.

💡 **시험 꿀팁**: 공유 책임 = "클라우드의 보안"(AWS) vs. "클라우드에서의 보안"(고객). 관리형 서비스(RDS, Lambda, S3)는 더 많은 책임을 AWS로 이전합니다. EC2 = 고객이 OS 이상을 담당. 관리형 서비스일수록 OS 책임이 줄어든다는 것을 기억하세요.

## Q12. 이벤트 기반 워크로드에 적합한 AWS 서비스

이벤트 기반 워크로드에 적합한 AWS 서비스는 무엇입니까?

- A. Amazon EC2
- B. AWS Elastic Beanstalk
- C. AWS Lambda
- D. Amazon Lumberyard

**정답: C**

✅ **C. AWS Lambda**: AWS Lambda는 이벤트에 응답하여 코드를 실행하는 서버리스 컴퓨팅 서비스입니다(예: API Gateway를 통한 HTTP 요청, S3 파일 업로드, SQS 메시지 등). 이벤트 수에 따라 자동으로 확장되며 소비된 컴퓨팅 시간에 대해서만 비용을 지불합니다.

❌ **A. Amazon EC2**: EC2는 지속적으로 실행되는 가상 서버를 제공합니다(중지하지 않는 한). EC2를 이벤트 기반 패턴에 사용할 수 있지만 항상 온 상태인 인프라가 필요하며 본질적으로 이벤트 기반이 아닙니다.

❌ **B. AWS Elastic Beanstalk**: Elastic Beanstalk은 웹 애플리케이션 및 서비스를 배포하고 관리하기 위한 PaaS 서비스입니다. 웹 애플리케이션 실행을 위해 설계되었으며 이벤트 기반 처리를 위한 것이 아닙니다.

❌ **D. Amazon Lumberyard**: Amazon Lumberyard는 현재 Open 3D Engine으로 알려진 무료 크로스 플랫폼 3D 게임 엔진입니다. 클라우드 컴퓨팅이나 이벤트 기반 워크로드와 관련이 없습니다.

💡 **시험 꿀팁**: Lambda = 서버리스 + 이벤트 기반 + 호출당 지불 + 제로로 자동 확장. 트리거 소스: S3 이벤트, API Gateway, DynamoDB Streams, SQS, SNS, EventBridge, Kinesis 등. "이벤트 기반" 질문에는 Lambda가 1순위 답변입니다.

## Q13. AWS 클라우드의 가치 제안

AWS 클라우드의 가치 제안은 무엇입니까?

- A. AWS는 AWS 클라우드의 보안을 담당합니다.
- B. 장기 계약이 필요하지 않습니다.
- C. 새 서버를 며칠 만에 프로비저닝할 수 있습니다.
- D. AWS가 AWS 클라우드에서 사용자 애플리케이션을 관리합니다.

**정답: B**

✅ **B. 장기 계약이 필요하지 않습니다**: AWS의 핵심 가치 제안 중 하나는 대부분의 서비스에 대해 선불 약정이나 장기 계약이 필요 없는 종량제 요금 모델입니다. 이를 통해 재정적 위험을 줄이고, 진입 장벽을 낮추며, 고객이 언제든지 확장하거나 중단할 수 있는 유연성을 제공합니다.

❌ **A. AWS는 AWS 클라우드의 보안을 담당합니다**: 공유 책임 모델에 따르면 AWS는 클라우드 "의" 보안(물리적 인프라)에 책임이 있지만, 고객은 클라우드 "에서의" 보안(데이터, 접근, 구성)에 책임이 있습니다. AWS가 모든 보안을 전적으로 담당하지 않습니다.

❌ **C. 새 서버를 며칠 만에 프로비저닝할 수 있습니다**: 이것은 실제로 AWS의 이점을 과소평가하는 것입니다. 클라우드 리소스는 며칠이 아닌 몇 분 안에 프로비저닝할 수 있습니다. 며칠은 전통적인 온프레미스 프로비저닝 일정에 가깝습니다.

❌ **D. AWS가 AWS 클라우드에서 사용자 애플리케이션을 관리합니다**: AWS는 고객 애플리케이션을 관리하지 않습니다. 고객은 자체 애플리케이션을 배포, 구성 및 관리할 책임이 있습니다.

💡 **시험 꿀팁**: AWS 가치 제안 = 장기 계약 없음 + 종량제 + CapEx에서 OpEx로 전환 + 몇 분 안에 확장 + 몇 분 안에 글로벌 확장 + 관리할 하드웨어 없음. "장기 약정 없음"과 "민첩성" 테마가 CLF-C02에서 자주 출제됩니다.

## Q14. Amazon S3 교차 리전 복제의 특성

Amazon S3 교차 리전 복제의 특성은 무엇입니까?

- A. 원본 및 대상 S3 버킷 모두 버전 관리가 비활성화되어 있어야 합니다.
- B. 원본 및 대상 S3 버킷이 서로 다른 AWS 리전에 있을 수 없습니다.
- C. 교차 리전 복제를 위해 구성된 S3 버킷은 단일 AWS 계정 또는 다른 계정 소유로 설정될 수 있습니다.
- D. 원본 및 대상 AWS 리전은 원본 S3 버킷 소유자 계정에서 비활성화되어야 합니다.

**정답: C**

✅ **C. 교차 리전 복제를 위해 구성된 S3 버킷은 단일 AWS 계정 또는 다른 계정 소유로 설정될 수 있습니다**: Amazon S3 교차 리전 복제(CRR)는 동일한 AWS 계정 내에서와 다른 AWS 계정 간에 복제를 모두 지원합니다. 이를 통해 교차 계정 데이터 공유 및 백업 시나리오가 가능합니다.

❌ **A. 원본 및 대상 S3 버킷 모두 버전 관리가 비활성화되어야 합니다**: 이것은 요구 사항과 정반대입니다. 교차 리전 복제는 원본 및 대상 버킷 모두에서 버전 관리가 활성화되어 있어야 합니다. 복제는 객체 버전을 추적하고 복제하기 위해 버전 관리에 의존합니다.

❌ **B. 원본 및 대상 S3 버킷이 서로 다른 AWS 리전에 있을 수 없습니다**: 이것도 반대입니다. 교차 리전 복제의 전체 목적은 객체를 다른 AWS 리전의 버킷에 복제하는 것입니다. 원본과 대상은 서로 다른 리전에 있어야 합니다.

❌ **D. 원본 및 대상 AWS 리전이 비활성화되어야 합니다**: 원본과 대상 리전 모두 활성화(활성) 상태여야 합니다. 비활성화된 리전은 활성 S3 버킷 작업을 호스팅할 수 없습니다.

💡 **시험 꿀팁**: S3 교차 리전 복제(CRR) 요구 사항: 1) 두 버킷 모두 버전 관리 활성화 필수, 2) 버킷은 서로 다른 리전에 있어야 함, 3) 동일하거나 다른 AWS 계정 가능, 4) 복제 권한이 있는 IAM 역할 필요.

## Q15. AWS 클라우드에서 애플리케이션 실행 시 고객의 책임

AWS 클라우드에서 애플리케이션을 실행할 때 사용자의 책임은 무엇입니까?

- A. 물리적 하드웨어 관리
- B. 기본 하이퍼바이저 업데이트
- C. 데이터 센터 접근이 승인된 사용자 목록 제공
- D. 애플리케이션 소프트웨어 업데이트 관리

**정답: D**

✅ **D. 애플리케이션 소프트웨어 업데이트 관리**: AWS 공유 책임 모델에 따라 고객은 애플리케이션 계층 소프트웨어 업데이트, 패치 및 구성 관리를 포함하여 자체 애플리케이션을 담당합니다. AWS는 기본 인프라를 처리합니다.

❌ **A. 물리적 하드웨어 관리**: AWS는 물리적 인프라(서버, 네트워킹 장비, 데이터 센터 시설)를 담당합니다. 고객은 물리적 하드웨어와 상호작용하거나 관리하지 않습니다.

❌ **B. 기본 하이퍼바이저 업데이트**: AWS는 EC2 인스턴스를 실행하는 하이퍼바이저 계층을 관리하고 패치합니다. 이것은 AWS의 "클라우드의 보안" 책임의 일부입니다. 고객은 게스트 OS와 그 이상만 관리합니다.

❌ **C. 데이터 센터 접근이 승인된 사용자 목록 제공**: AWS는 데이터 센터에 대한 물리적 접근 제어를 관리합니다. 고객은 AWS 시설에 대한 물리적 접근 승인이나 관리에 아무런 역할이 없습니다.

💡 **시험 꿀팁**: 공유 책임 간단한 규칙 — AWS는 OS 아래의 모든 물리적 및 가상 인프라를 담당합니다. 고객은 OS(EC2의 경우), 애플리케이션 코드, 데이터, IAM, 암호화 설정, 네트워크 구성(보안 그룹, NACL)을 담당합니다.

## Q16. 시장 출시 시간 최소화를 위한 AWS 클라우드 기능

온라인 비즈니스를 운영하는 기업이 시장 출시 시간을 최소화하기 위해 새로운 기능을 빠르고 반복적으로 제공해야 합니다. 이를 제공할 수 있는 AWS 클라우드 기능은 무엇입니까?

- A. 탄력성
- B. 고가용성
- C. 민첩성
- D. 안정성

**정답: C**

✅ **C. 민첩성**: AWS 클라우드에서 민첩성은 새로운 기능과 애플리케이션을 빠르게 개발, 테스트 및 배포하는 능력을 의미합니다. AWS는 리소스 프로비저닝에 필요한 시간을 몇 주에서 몇 분으로 줄여 팀이 빠르게 반복하고, 자주 실험하고, 새로운 기능을 더 빠르게 출시할 수 있게 합니다. 이것은 "시장 출시 시간 최소화"를 직접 다룹니다.

❌ **A. 탄력성**: 탄력성은 수요에 따라 리소스를 자동으로 확장하거나 축소하는 능력을 의미합니다. 유용하지만 용량 관리를 다루지, 기능 제공 속도나 개발 주기를 다루지 않습니다.

❌ **B. 고가용성**: 고가용성은 다운타임을 최소화하고 지속적인 운영을 보장하도록 시스템을 설계하는 것입니다. 안정성과 가동 시간에 관한 것이며, 새로운 기능을 얼마나 빠르게 제공할 수 있는지에 관한 것이 아닙니다.

❌ **D. 안정성**: 안정성은 시스템이 장애로부터 복구하고 수요를 충족하기 위해 동적으로 리소스를 획득하는 능력을 의미합니다. 시스템 복원력과 가동 시간에 관한 것이며, 개발 속도나 시장 출시 시간에 관한 것이 아닙니다.

💡 **시험 꿀팁**: AWS 클라우드 이점 기억: 민첩성 = 빠른 혁신/배포. 탄력성 = 수요에 따라 확장/축소. 고가용성 = 다운타임 최소화. 안정성 = 장애로부터 복구. 확장성 = 성장 처리. "시장 출시 시간" 및 "빠른 반복" = 민첩성.

## Q17. AWS 계정 비용 모니터링 기능 (2개 선택)

AWS 계정의 비용 및 요금을 모니터링하는 데 사용할 수 있는 기능 또는 서비스는 무엇입니까? (2개 선택)

- A. AWS 비용 및 사용 보고서
- B. AWS 제품 페이지
- C. AWS 요금 계산기
- D. 청구 알람 및 Amazon CloudWatch 알람
- E. AWS 가격 목록

**정답: A, D**

✅ **A. AWS 비용 및 사용 보고서**: AWS 비용 및 사용 보고서(CUR)는 AWS 서비스, 요금 및 예약에 대한 추가 메타데이터를 포함하여 이용 가능한 가장 포괄적인 비용 및 사용 데이터 세트를 제공합니다. S3에 전달하여 상세한 비용 모니터링 및 분석에 활용할 수 있습니다.

✅ **D. 청구 알람 및 Amazon CloudWatch 알람**: CloudWatch에서 청구 알람을 생성하여 예상 AWS 요금을 모니터링할 수 있습니다. 예상 요금이 정의된 임계값을 초과하면 CloudWatch가 Amazon SNS를 통해 알림을 보내 사전 예방적 비용 모니터링을 가능하게 합니다.

❌ **B. AWS 제품 페이지**: AWS 제품 페이지는 AWS 서비스, 기능 및 사용 사례에 대한 정보를 제공합니다. 정보/마케팅 페이지이며 실제 계정 비용을 위한 모니터링 도구가 아닙니다.

❌ **C. AWS 요금 계산기**: AWS 요금 계산기(이전 심플 월간 계산기)는 배포 전 AWS 서비스의 미래 비용을 추정하는 데 사용됩니다. 계획 도구이며 현재 또는 과거 비용을 위한 모니터링 도구가 아닙니다.

❌ **E. AWS 가격 목록**: AWS 가격 목록은 AWS 서비스 요금에 대한 참조입니다(API 또는 다운로드 가능한 JSON/CSV로 이용 가능). 서비스 가격을 나열하지만 실제 계정 사용량이나 비용을 모니터링하지 않습니다.

💡 **시험 꿀팁**: 비용 모니터링 도구 = AWS 비용 및 사용 보고서 + CloudWatch 청구 알람 + Cost Explorer(시각화) + AWS Budgets(알림). 비용 추정 도구 = AWS 요금 계산기 + TCO 계산기. 차이점을 알아두세요: 모니터링(실제) vs. 추정(미래).

## Q18. Amazon Route 53으로 할 수 있는 것

Amazon Route 53으로 사용자가 할 수 있는 것은 무엇입니까?

- A. 전송 중 데이터 암호화
- B. DNS 도메인 이름 등록
- C. SSL 인증서 생성 및 관리
- D. AWS로의 전용 네트워크 연결 설정

**정답: B**

✅ **B. DNS 도메인 이름 등록**: Amazon Route 53은 AWS의 확장 가능하고 가용성이 높은 DNS(도메인 이름 시스템) 웹 서비스입니다. 사용자가 도메인 이름을 등록하고, 인터넷 트래픽을 AWS 리소스로 라우팅하고, 리소스의 상태를 확인할 수 있게 합니다. 도메인 이름 등록은 Route 53의 핵심 기능입니다.

❌ **A. 전송 중 데이터 암호화**: 전송 중 데이터 암호화는 TLS/SSL 같은 프로토콜과 AWS Certificate Manager(ACM) 또는 AWS PrivateLink와 같은 서비스에 의해 처리됩니다. Route 53은 DNS 서비스이며 암호화 기능을 제공하지 않습니다.

❌ **C. SSL 인증서 생성 및 관리**: SSL/TLS 인증서 생성 및 관리는 AWS Certificate Manager(ACM)의 기능입니다. Route 53은 ACM 인증서를 위한 도메인 소유권을 검증할 수 있지만, 자체적으로 SSL 인증서를 생성하거나 관리하지 않습니다.

❌ **D. AWS로의 전용 네트워크 연결 설정**: AWS로의 전용 프라이빗 네트워크 연결은 AWS Direct Connect를 사용하여 설정합니다. Route 53은 DNS/애플리케이션 계층에서 작동하며 네트워크 회선 프로비저닝과 관련이 없습니다.

💡 **시험 꿀팁**: Route 53 = DNS + 도메인 등록 + 상태 확인 + 라우팅 정책(Simple, Weighted, Latency, Failover, Geolocation, Geoproximity, Multi-value). "53"은 표준 DNS 포트인 TCP/UDP 포트 53을 의미합니다. ACM = SSL 인증서, Direct Connect = 프라이빗 네트워크.

## Q19. AWS 계정 및 워크로드에서 악성 활동을 식별하는 서비스

AWS 계정 및 워크로드에서 악성 또는 무단 활동을 식별하는 데 도움이 되는 AWS 서비스는 무엇입니까?

- A. Amazon Rekognition
- B. AWS Trusted Advisor
- C. Amazon GuardDuty
- D. Amazon CloudWatch

**정답: C**

✅ **C. Amazon GuardDuty**: Amazon GuardDuty는 악성 활동 및 무단 행동에 대해 AWS 계정과 워크로드를 지속적으로 모니터링하는 위협 탐지 서비스입니다. AWS CloudTrail, VPC Flow Logs 및 DNS 로그에서 데이터를 분석하여 기계 학습, 이상 탐지 및 통합 위협 인텔리전스를 사용하여 위협을 식별합니다.

❌ **A. Amazon Rekognition**: Amazon Rekognition은 이미지 및 비디오 분석(얼굴 인식, 객체 탐지, 콘텐츠 조정)을 위한 기계 학습 서비스입니다. AWS 계정을 위한 보안 위협 탐지 서비스가 아닙니다.

❌ **B. AWS Trusted Advisor**: Trusted Advisor는 비용, 성능, 보안, 내결함성 및 서비스 한도에 대한 모범 사례 권장 사항을 제공합니다. 보안 검사가 있지만 악성 활동이나 위협을 적극적으로 모니터링하거나 탐지하지 않습니다.

❌ **D. Amazon CloudWatch**: CloudWatch는 AWS 리소스 및 애플리케이션을 위한 모니터링 및 관찰 서비스입니다. 지표와 로그를 수집하고 알람을 트리거할 수 있지만, 악성 행동이나 위협 패턴을 분석하지 않습니다. 그것이 GuardDuty의 역할입니다.

💡 **시험 꿀팁**: GuardDuty = 지능형 위협 탐지(악성 활동, 무단 접근). Macie = S3의 민감한 데이터 발견. Inspector = EC2/컨테이너의 취약점 스캔. Security Hub = 중앙 집중식 보안 조사 결과. "악성 활동" 또는 "위협 탐지" = GuardDuty.

## Q20. 장기 약정 전 타사 솔루션을 사용해 볼 수 있는 AWS 서비스

회사가 장기 사용을 약정하기 전에 타사 e-commerce 솔루션을 사용해 보려 합니다. 이를 지원하는 AWS 서비스 또는 도구는 무엇입니까?

- A. AWS Marketplace
- B. AWS Partner Network(APN)
- C. AWS Managed Services
- D. AWS Service Catalog

**정답: A**

✅ **A. AWS Marketplace**: AWS Marketplace는 독립 소프트웨어 공급업체(ISV)의 수천 개 소프트웨어 목록이 있는 디지털 카탈로그입니다. 기업이 무료 체험, 시간별, 월별 및 연간 요금을 포함한 유연한 요금 옵션으로 타사 소프트웨어 솔루션(e-commerce 플랫폼 포함)을 찾고, 테스트하고, 배포할 수 있어 장기 약정 전에 솔루션을 쉽게 사용해 볼 수 있습니다.

❌ **B. AWS Partner Network(APN)**: AWS Partner Network는 AWS를 기반으로 솔루션과 서비스를 구축하는 회사를 위한 글로벌 파트너 프로그램입니다. 컨설팅 및 기술 파트너의 네트워크이며, 타사 소프트웨어를 직접 시도하거나 구매하기 위한 마켓플레이스가 아닙니다.

❌ **C. AWS Managed Services**: AWS Managed Services는 고객을 대신하여 AWS 인프라 및 운영의 지속적인 관리를 제공합니다. 운영 관리 서비스이며, 타사 소프트웨어 솔루션을 발견하거나 시도하기 위한 플랫폼이 아닙니다.

❌ **D. AWS Service Catalog**: AWS Service Catalog는 조직이 승인된 IT 서비스의 카탈로그를 만들고 관리할 수 있게 합니다(내부적으로). 내부 제품 포트폴리오의 거버넌스 및 표준화에 사용되며, 타사 상업용 소프트웨어를 발견하거나 시도하기 위한 것이 아닙니다.

💡 **시험 꿀팁**: AWS Marketplace = 타사 소프트웨어 카탈로그 + 무료 체험 + 유연한 요금 + 원클릭 배포. AWS용 "앱 스토어"로 생각하세요. 주요 사용 사례: 구매 전 체험, 소프트웨어 라이선스(BYOL), 사전 구성된 AMI, SaaS 구독.
