## 0. 만들기 전에 먼저 답해야 할 질문들

디자인보다 먼저 해야 할 일이 있다. 이 질문에 답하지 않으면 아무리 예쁜 대시보드도 "그래서 뭘 봐야 하죠?"라는 반응이 돌아온다.

| 질문 | 왜 중요한가 |
|---|---|
| **누가 보는가?** | 임원 vs 분석가 vs 현장 담당자에 따라 정보 밀도가 달라진다 |
| **어떤 결정을 내려야 하는가?** | 그 결정에 필요한 지표만 남긴다 |
| **어디서 보는가?** | 대형 모니터면 정보량을 늘려도 되지만, 태블릿·모바일이면 타일 수를 줄여야 한다 |
| **한 화면에 다 보이는가?** | 스크롤 없이 핵심 정보를 전달할 수 있어야 한다 |

> "대시보드는 보고서가 아니다. 현재 데이터 상태를 한눈에 모니터링하는 개요다. 세부 정보는 드릴다운으로 연결하면 충분하다." — Microsoft Power BI 공식 가이드

## 1. 레이아웃 패턴 3선 — 목적에 맞게 고르기

이전 포스트에서 Z자·F자 시선 흐름을 소개했다면, 이번에는 **목적별로 어떤 구조로 대시보드를 짤지** 구체적인 패턴을 정리한다.

### ① 역피라미드 (Inverted Pyramid) — 임원 보고에 최적

가장 중요한 요약 정보를 최상단에, 아래로 갈수록 세부 정보를 배치한다. C-Level이 선호하는 방식이다.

```
┌──────────────────────────────────────┐
│  [필터] 기간 ▼  지역 ▼  제품군 ▼     │  ← 전체 필터 (최상단 가로 배치)
├──────────┬──────────┬────────────────┤
│  매출 총액 │ 활성 사용자│  목표 달성률    │  ← KPI 카드 3~5개
├──────────┴──────────┴────────────────┤
│         월별 매출 트렌드 (선 그래프)    │  ← 트렌드·비교 차트
├─────────────────┬────────────────────┤
│  지역별 매출 바차트│  제품군별 구성 파이  │
├─────────────────┴────────────────────┤
│         상세 거래 데이터 테이블         │  ← 필요할 때만 스크롤
└──────────────────────────────────────┘
```

### ② 허브앤스포크 (Hub and Spoke) — 원인 심층 분석에 최적

하나의 핵심 차트(Hub)를 중심으로, 이를 다각도로 설명하는 서브 차트(Spoke)를 배치한다. "왜 이 수치가 나왔는가?"를 파고들 때 효과적이다.

```
┌──────────────────────┬───────────────┐
│                      │ 지역별 매출 비중 │
│  월별 매출 추이        ├───────────────┤
│  (메인 선 그래프)      │ 제품군별 매출   │
│                      ├───────────────┤
│       [Hub]          │ 채널별 전환율   │
└──────────────────────┴───────────────┘
           [Spoke들이 Hub를 설명]
```

### ③ F-패턴 (F-Shape) — 필터·텍스트가 많은 대시보드에 최적

사용자가 상단을 가로로 훑고, 좌측 세로 방향으로 스캔하는 시선 흐름을 활용한다.

```
┌─────────────────────────────────────┐
│ 타이틀 | 업데이트 시간 | 필터 위젯들  │  ← F의 상단 가로축
├────────────────────────────────────┤
│ [KPI] [KPI] [핵심 요약 그래프]       │  ← F의 중간 가로축
├──┬─────────────────────────────────┤
│제│  차트 A         차트 B           │
│목│                                  │  ← F의 세로축 (좌측)
│정│  차트 C         차트 D           │
│렬│                                  │
└──┴─────────────────────────────────┘
```

## 2. 차트 타입 선택 원칙

"다양성을 위해 다양성을 추구하지 말라." — Microsoft Power BI 공식 가이드

차트는 **데이터의 특성**에 맞게 골라야 한다. 잘못된 차트 선택은 데이터를 오해하게 만든다.

### 목적별 차트 선택표

| 목적 | 권장 차트 | 피해야 할 것 |
|---|---|---|
| 시간 흐름·트렌드 | 선 그래프 | 바 차트 (변화 흐름이 끊겨 보임) |
| 항목 간 비교 | 가로·세로 바 차트 | 3D 차트 (값 왜곡 심각) |
| 구성비 | 파이 차트 (**8개 미만 범주만**) | 3D 파이, 도넛 남용 |
| 목표 대비 현재 상태 | 게이지 차트 | 선 그래프 |
| 분포 | 히스토그램, 박스플롯 | 파이 차트 |
| 상관관계 | 산점도 | 바 차트 |
| 단일 핵심 수치 | 숫자 카드 + 스파크라인 | 큰 파이·바 차트 |

### 숫자 표기 원칙

사람은 긴 숫자를 한눈에 읽지 못한다. 축약해서 표기하는 것이 전문적이다.

| 원래 표기 | 개선된 표기 |
|---|---|
| `3,400,000` | `340만` 또는 `3.4M` |
| `1,234,567,890` | `12.3억` 또는 `1.23B` |
| `0.123456` | `12.3%` |

- 소수점은 **1~2자리** 이내로 제한
- 같은 차트에 수백만 단위와 수천 단위를 혼용 금지 → 보조 축 활용
- 차트 간 축 눈금과 차원 순서는 **일관되게** 유지
- 시간 범위를 섞지 말 것 (월 단위 차트 옆에 연 단위 차트 배치 금지)

## 3. Data-Ink Ratio — Edward Tufte의 핵심 원칙

대시보드가 복잡해 보이는 가장 흔한 이유는 **데이터를 전달하지 않는 시각적 요소가 너무 많아서**다.

> "차트에서 잉크의 대부분은 데이터를 나타내는 데 써야 한다." — Edward Tufte

### 제거해야 할 요소들

| 요소 | 문제점 |
|---|---|
| 촘촘한 그리드라인 | 데이터보다 격자가 눈에 먼저 들어옴 |
| 3D 효과 | 원근감으로 인해 실제 값이 왜곡됨 |
| 차트 테두리 박스 | 데이터 전달에 기여하지 않는 장식 |
| 불필요한 데이터 레이블 | 바 차트는 레이블 없어도 상대적 크기가 읽힘 |
| 과도한 범례 | 차트 안에 직접 레이블링하는 것이 더 직관적 |
| 배경 그라데이션·패턴 | 데이터 시인성 방해 |

### 정렬 의도 설계

차트 정렬 방식도 메시지를 담는다.

- **측정값 기준 정렬**: "어느 항목이 가장 높은가/낮은가"를 강조할 때
- **범주(축) 기준 정렬**: "특정 항목을 빠르게 찾아야 할 때" (예: 알파벳 순)

## 4. KPI 카드 설계 심화

이전 포스트에서 KPI 카드 배치를 다뤘다면, 이번엔 카드 **내부를 어떻게 구성하는가**다.

### 잘 만든 KPI 카드의 구성

```
┌─────────────────────────────┐
│  매출 총액                   │  ← 지표명 (작은 글씨)
│  ₩ 1.24B                    │  ← 핵심 숫자 (크고 굵게)
│  ▲ 12.3%  vs 지난달          │  ← 변화율 + 비교 기간 명시
│  ━━━━━━━━━━━━━━━━━━━━━━━━  │  ← 스파크라인 (미니 트렌드)
│  목표 달성률  87%             │  ← 목표 대비
└─────────────────────────────┘
```

### 설계 원칙

- **변화율 색상 인코딩**: ▲ 초록 / ▼ 빨강  
  단, **비용·오류·이탈률** 지표는 반대로 적용 (감소가 긍정)
- **비교 기간은 항상 명시**: "vs 지난달"인지 "vs 전년 동기"인지 모르면 숫자가 무의미하다
- **스파크라인**: 단일 숫자만 보여주는 것보다 최근 흐름을 함께 보여줘야 맥락이 생긴다
- **목표 달성률**: 차트에도 목표선(Reference Line)을 점선으로 추가

## 5. 내러티브 추가 — 텍스트 박스 활용

차트만 나열하면 "숫자 모음집"에 불과하다. **스토리를 담아야** 전문적인 대시보드가 된다.

### Databricks AI/BI 텍스트 박스 활용법

**구역 헤더로 흐름 분리:**
```markdown
## 1. 사용자 유입 현황
## 2. 구매 전환 분석
## 3. 이탈 원인 분석
```

**이상치·예외 사항 주석:**
```markdown
(참고: 3월 데이터는 시스템 점검으로 인해 일부 유실됨)
(참고: 4월 급증은 프로모션 캠페인 효과)
```

이 작은 텍스트 한 줄이 **대시보드 신뢰도를 크게 높인다**. 보는 사람이 직접 물어봐야 알 수 있는 맥락을 미리 제공하는 것이기 때문이다.

## 6. 조건부 서식 (Conditional Formatting)

규칙 기반 색상 인코딩을 쓰면 대시보드가 스스로 "어디에 주목해야 하는가"를 알려준다.

### 테이블 조건부 서식

| 조건 | 시각 표현 |
|---|---|
| 목표치 초과 달성 | 초록 텍스트 또는 초록 배경 |
| 임계값 미달 | 빨간 배경 또는 볼드 처리 |
| 전기 대비 하락 | 빨간 화살표 ▼ |
| 전기 대비 상승 | 초록 화살표 ▲ |

### 차트 목표선 (Reference Line)

목표가 있는 모든 차트에는 **목표선을 점선**으로 추가한다. 실제 수치가 목표 대비 어느 위치인지 즉시 파악할 수 있다.

Databricks Lakeview에서는 테이블 위젯의 `Conditional formatting` 옵션으로 설정할 수 있다.

## 7. 데이터 신선도 + 신뢰 지표

아무리 잘 만든 대시보드도 이 정보가 없으면 "이 데이터 언제 기준이야?"라는 질문이 반드시 나온다.

### 대시보드 우상단에 항상 표시

```
마지막 업데이트: 2026-06-22 08:00 KST
데이터 소스: sales_db.transactions (Delta Lake)
담당자: 데이터팀 홍길동
```

이 세 줄만으로 다음을 보장할 수 있다:
- **신선도**: 데이터가 얼마나 최신인지
- **출처 추적**: 어디서 온 데이터인지
- **책임 소재**: 문제가 생겼을 때 누구에게 물어봐야 하는지

## 8. 접근성 (Accessibility) — WCAG 기준

색맹 시뮬레이터로 팔레트를 검증하는 것(1편에서 다룸)은 시작일 뿐이다. 접근성에는 구체적인 기준이 있다.

### WCAG AA 기준 적용

| 항목 | 기준 |
|---|---|
| 일반 텍스트 대비비 | **4.5:1 이상** |
| 큰 텍스트(18pt 이상) 대비비 | **3:1 이상** |
| UI 컴포넌트 대비비 | **3:1 이상** |

검증 도구: [WebAIM Contrast Checker](https://webaim.org/resources/contrastchecker/)

### 색상 외 보조 수단 병행

색상만으로 정보를 구분하면 색맹 사용자는 해당 정보를 읽지 못한다.

- 선 그래프: 색상 + **선 스타일** (실선, 점선, 파선) 함께 사용
- 바 차트: 색상 + **패턴** (사선, 격자 등) 함께 사용
- 상태 표시: 색상 + **아이콘** (✅, ⚠️, ❌) 함께 사용

## 9. 게슈탈트(Gestalt) 시각 원리

인간의 뇌는 시각 정보를 무의식적으로 특정 방식으로 그룹화한다. 이 원리를 대시보드에 적용하면 **설명 없이도 직관적으로 읽히는** 구조를 만들 수 있다.

| 원리 | 내용 | 대시보드 적용 |
|---|---|---|
| **근접성 (Proximity)** | 가까이 있는 요소는 같은 그룹으로 인식 | 관련 차트는 묶어서 배치, 서로 다른 주제는 여백으로 구분 |
| **유사성 (Similarity)** | 같은 색·크기·모양의 요소는 같은 종류로 인식 | 같은 카테고리는 같은 색 일관 적용 |
| **연속성 (Continuity)** | 선이나 패턴이 자연스럽게 이어지는 것을 선호 | 선 그래프의 흐름이 자연스럽게 이어지도록 설계 |
| **단순성 (Simplicity)** | 복잡한 형태보다 단순한 형태를 선호 | 불필요한 장식 제거, Data-Ink Ratio 유지 |

## 정리 — 심화 체크리스트

| 항목 | 확인 |
|---|---|
| 대상 사용자·디바이스·결정 목적 정의 완료 | ✅ |
| 목적에 맞는 레이아웃 패턴 선택 (역피라미드/허브앤스포크/F패턴) | ✅ |
| 데이터 특성에 맞는 차트 타입 선택 | ✅ |
| 숫자 축약 표기 적용 (340만, 3.4M 등) | ✅ |
| Data-Ink Ratio 확인 (불필요한 요소 제거) | ✅ |
| KPI 카드에 스파크라인·변화율·목표 달성률 포함 | ✅ |
| 텍스트 박스로 구역 헤더·이상치 주석 추가 | ✅ |
| 조건부 서식·목표선(Reference Line) 설정 | ✅ |
| 데이터 신선도·출처·담당자 표시 | ✅ |
| WCAG AA 대비비 4.5:1 이상 확인 | ✅ |
| 색상 외 보조 수단(모양·패턴·아이콘) 병행 | ✅ |
