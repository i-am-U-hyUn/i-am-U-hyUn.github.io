전공자이자 엔지니어로서 면접이나 실무에서 **"둘의 차이가 뭐죠?"** 라는 질문을 받았을 때 명쾌하게 답할 수 있어야 하는, 네트워크/인프라/클라우드/리눅스 필수 핵심 대비 개념들을 정리했다. 개념 정의뿐 아니라 적용 수준, 제어 방식, 상태 관리 여부까지 함께 짚어본다.

---

## 1. [클라우드/네트워크] ALB (Application Load Balancer) vs NLB (Network Load Balancer)

클라우드 인프라를 설계할 때 트래픽을 분산해 주는 로드 밸런서의 양대 산맥이다. OSI 7계층 중 어느 계층을 다루느냐에 따라 기술적 특성이 완전히 갈린다.

| 비교 항목 | ALB (Application Load Balancer) | NLB (Network Load Balancer) |
| --- | --- | --- |
| **작동 계층** | **Layer 7 (애플리케이션 계층)** | **Layer 4 (전송 계층)** |
| **라우팅 기준** | HTTP/HTTPS 헤더, URL 경로, Cookie 패턴 등 | IP 주소, 포트(Port) 번호, 프로토콜 |
| **IP 고정 여부** | IP가 가변적임 (DNS 이름으로 접근) | **고정 IP (Elastic IP)** 할당 가능 |
| **처리 속도** | 패킷 내부(데이터)까지 열어봐야 하므로 상대적으로 느림 | 패킷 헤더만 보고 바로 던지므로 **극도로 빠름 (초당 수백만 패킷)** |
| **특징적 기능** | SSL 인증서 오프로딩, 경로 기반 라우팅 가능 | 대규모 트래픽(실시간 게임, 금융 통신)에 적합 |

---

## 2. [인프라/클라우드] NAT Gateway vs Internet Gateway (IGW)

VPC(가상 네트워크) 내부의 자원들이 외부 인터넷과 어떻게 통신할지 결정하는 관문들이다. **"양방향이냐, 단방향이냐"** 가 핵심이다.

| 비교 항목 | Internet Gateway (IGW) | NAT Gateway |
| --- | --- | --- |
| **통신 방향** | **양방향 (Inbound / Outbound 모두 가능)** | **단방향 (Outbound만 가능)** |
| **배치 위치** | 퍼블릭 서브넷(Public Subnet) | 퍼블릭 서브넷에 위치하여 프라이빗 자원을 보호 |
| **주요 목적** | 웹 서버처럼 외부 사용자가 접속해야 하는 자원 연결 | 데이터베이스(DB)처럼 **외부 접근은 막고, 패치/업데이트용 인터넷만 필요할 때** 사용 |
| **IP 변환(NAT)** | 1:1 매핑 (Private IP ↔ Public IP) | N:1 매핑 (여러 Private IP → 1개의 NAT Public IP) |

---

## 3. [리눅스/인프라] 하드 링크 (Hard Link) vs 심볼릭 링크 (Symbolic Link / Soft Link)

리눅스 파일 시스템(Inode 구조)을 이해하고 있는지 검증하는 단골 질문이다.

| 비교 항목 | 하드 링크 (Hard Link) | 심볼릭 링크 (Symbolic/Soft Link) |
| --- | --- | --- |
| **개념** | 원본 파일의 **Inode를 직접 가리키는** 또 다른 이름 | 원본 파일의 **경로(Path)를 가리키는** 바로가기 아이콘 |
| **원본 삭제 시** | 링크 파일 **사용 가능** (데이터 유지됨) | 링크 파일 **사용 불가** (Broken Link 발생) |
| **디렉터리 링크** | 디렉터리에 생성 불가능 | 디렉터리에 생성 가능 |
| **파일 시스템 차이** | 동일한 파일 시스템(디스크 파티션) 내에서만 가능 | 서로 다른 파일 시스템 간에도 생성 가능 |
| **용량 측정** | 원본과 동일한 용량으로 표시됨 (공간을 더 차지하진 않음) | 경로 문자열만큼의 아주 작은 용량만 차지 |

---

## 4. [네트워크] TCP (Transmission Control Protocol) vs UDP (User Datagram Protocol)

전송 계층(L4)의 핵심 프로토콜로, 신뢰성과 속도의 트레이드오프(Trade-off) 관계를 보여준다.

| 비교 항목 | TCP | UDP |
| --- | --- | --- |
| **연결 방식** | **연결 지향형** (3-Way Handshake로 연결 설정) | **비연결형** (연결 설정 없이 패킷 투척) |
| **상태 관리** | **Stateful** (시퀀스 번호, ACK 번호로 흐름/혼잡 제어) | **Stateless** (보냈는지 받았는지 신경 쓰지 않음) |
| **신뢰성/순서** | 패킷 손실 시 재전송, **순서 보장 · 고신뢰성** | 패킷 손실 가능성 있음, **순서 보장 안 됨** |
| **전송 속도** | 상대적으로 느림 (확인 절차가 많음) | **매우 빠름** (오버헤드가 거의 없음) |
| **주요 용도** | 웹 브라우징(HTTP), 파일 전송(FTP), 이메일(SMTP) | 실시간 스트리밍, 온라인 게임, DNS 조회 |

---

## 5. [클라우드/인프라] 가상 머신 (VM) vs 컨테이너 (Container / Docker)

현대 인프라 아키텍처의 기반이 되는 가상화 기술의 차이다. **"OS를 통째로 띄우느냐, 커널을 공유하느냐"** 가 핵심이다.

| 비교 항목 | 가상 머신 (VM - e.g., AWS EC2, VMware) | 컨테이너 (Container - e.g., Docker) |
| --- | --- | --- |
| **가상화 수준** | **하드웨어 레벨** 가상화 | **OS 레벨 (프로세스 격리)** 가상화 |
| **게스트 OS** | 각 VM마다 독립된 **Guest OS 필요** (무겁고 큼) | **Guest OS 없음** (호스트 OS의 커널을 공유) |
| **구동 속도** | OS 부팅이 필요하므로 수 분(Minutes) 소요 | 프로세스 실행 수준이므로 **수 초(Seconds) 이내** 구동 |
| **자원 격리** | 하이퍼바이저를 통해 완전하고 독립된 자원 격리 | Linux Namespace, cgroups를 이용한 논리적 격리 |
| **이미지 크기** | 보통 수 GB ~ 수십 GB | 보통 수 MB ~ 수백 MB (가볍고 이식성 높음) |

---

## 6. [클라우드/보안] Security Group vs NACL (Network ACL)

AWS 같은 클라우드 환경에서 자주 헷갈리는 두 방화벽 개념이다. **"하나는 서브넷 수준, 하나는 인스턴스 수준"**, **"하나는 허용/차단 모두 가능, 하나는 허용만 가능"** 이라는 특성으로 구분된다.

### 6-1. 핵심 차이점 요약

| 비교 항목 | NACL (네트워크 ACL) | 보안 그룹 (Security Group) |
| --- | --- | --- |
| **적용 수준** | **서브넷(Subnet) 수준** | **인스턴스(Instance) 수준** |
| **제어 방식** | **허용(Allow)과 차단(Deny)** 모두 명시 가능 | **허용(Allow) 규칙만** 정의 가능 (기본 차단) |
| **상태 관리** | **Stateless (상태 비저장)** | **Stateful (상태 저장)** |
| **규칙 적용** | 번호 순서대로 순차적 적용 | 모든 규칙을 평가 후 적용 |

### 6-2. 서브넷 수준 vs 인스턴스 수준

- **NACL (서브넷 수준):** 서브넷이라는 커다란 울타리 입구에 세워진 거대한 '성문'이다. 이 서브넷 안에 있는 모든 인스턴스(서버)에 가기 전, **반드시 이 성문을 먼저 통과**해야 한다.
- **보안 그룹 (인스턴스 수준):** 각 인스턴스(서버) 바로 앞에 서 있는 '개인 경호원'이다. 성문(NACL)을 통과해 들어왔더라도, 개별 서버에 들어가려면 이 경호원의 허락을 한 번 더 받아야 한다.

### 6-3. 허용/차단 모두 vs 허용만 가능

- **NACL (허용 & 차단 모두 설정):** "10.0.0.5 IP는 들어와도 돼(Allow)"뿐만 아니라, **"블랙리스트인 20.0.0.9 IP는 절대 들어오지 마(Deny)"** 라고 특정 IP나 대역을 직접 차단할 수 있다.
- **보안 그룹 (허용만 설정):** "내가 허용한 녀석들만 들어와" 방식(화이트리스트)이다. 기본적으로 모든 접근은 '차단'되어 있으며, 규칙에 "80번 포트 허용"처럼 허용할 규칙만 등록할 수 있다. 특정 악성 IP 하나만 콕 집어서 '차단'하는 규칙은 만들 수 없다.

### 6-4. 왜 이런 차이가 생길까? (Stateless vs Stateful)

기술적으로 가장 중요한 차이는 바로 '태도(상태 저장 여부)'에 있다.

- **보안 그룹 (Stateful):** 경호원이 기억력이 좋다. 들어올 때 허락을 받고 들어온 사람이 나갈 때는 **"아까 들어온 사람이네" 하고 검사 없이 그냥 내보내 준다.** (Inbound가 허용되면 Outbound는 자동으로 허용)
- **NACL (Stateless):** 기억력이 없다. 들어올 때 검사를 빡빡하게 해서 들여보냈어도, 그 사람이 나갈 때 **"너 누구야? 나가는 규칙에 네 이름 있어?" 하고 또 검사**한다. 따라서 NACL을 쓸 때는 들어오는 규칙(Inbound)과 나가는 규칙(Outbound)을 **각각 따로** 적어주어야 통신이 된다.
