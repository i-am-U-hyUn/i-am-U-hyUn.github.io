## Q1. 공유 책임 모델 - 고객 책임 범위

공유 책임 모델에서 다음 중 고객이 책임지는 것은 무엇입니까?

- A. 사용 후 디스크 드라이브가 지워졌는지 확인합니다.
- B. 하드웨어 장치에서 펌웨어를 업데이트해야 합니다.
- C. 미사용 데이터의 암호화 확인
- D. 네트워크 케이블이 범주 6 이상인지 확인

**정답: C**

✅ **C. 미사용 데이터의 암호화 확인**: 데이터 암호화는 고객이 직접 설정하고 관리해야 하는 영역입니다. AWS는 암호화 도구(KMS, S3 서버 측 암호화 등)를 제공하지만, 이를 활성화하고 관리하는 것은 고객의 책임입니다. "클라우드에서의 보안(Security IN the Cloud)"이 고객 책임에 해당합니다.

❌ **A. 사용 후 디스크 드라이브가 지워졌는지 확인**: 물리적 하드웨어의 데이터 삭제 및 폐기는 AWS의 책임입니다. 고객은 물리적 인프라에 접근할 수 없습니다.

❌ **B. 하드웨어 장치에서 펌웨어를 업데이트**: 물리적 하드웨어 및 펌웨어 관리는 "클라우드 보안(Security OF the Cloud)"으로 AWS가 책임집니다.

❌ **D. 네트워크 케이블이 범주 6 이상인지 확인**: 물리적 네트워크 인프라의 관리와 유지는 AWS 데이터 센터 운영의 일부로 AWS가 전담합니다.

💡 **시험 꿀팁**: 공유 책임 모델 핵심 구분 — AWS 책임: 물리적 하드웨어, 데이터 센터, 네트워크 인프라, 하이퍼바이저 ("클라우드의 보안") / 고객 책임: 데이터 암호화, OS 패치, 애플리케이션, IAM 계정 관리, 방화벽 설정 ("클라우드에서의 보안")

## Q2. 지출 세부 추적 및 분류

기업이 지출을 세부적으로 추적하고 분류할 수 있는 것은 무엇입니까?

- A. 비용 할당 태그
- B. 통합 청구
- C. AWS 예산
- D. AWS 마켓플레이스

**정답: A**

✅ **A. 비용 할당 태그**: 비용 할당 태그(Cost Allocation Tags)는 AWS 리소스에 키-값 쌍을 붙여 비용을 부서, 프로젝트, 환경별로 세분화하여 추적하고 분류할 수 있게 해줍니다. Cost Explorer에서 태그별 비용 분석이 가능합니다.

❌ **B. 통합 청구**: 통합 청구(Consolidated Billing)는 여러 AWS 계정의 청구서를 하나로 합치는 기능으로, 세부 분류보다는 통합 관리와 볼륨 할인에 초점이 맞춰져 있습니다.

❌ **C. AWS 예산**: AWS Budgets는 비용 한도를 설정하고 초과 시 알림을 보내는 도구로, 지출을 분류하기보다는 예산 초과를 모니터링하는 데 사용됩니다.

❌ **D. AWS 마켓플레이스**: AWS Marketplace는 서드파티 소프트웨어를 구매하는 플랫폼으로, 비용 추적 및 분류 기능과는 관련이 없습니다.

💡 **시험 꿀팁**: 비용 할당 태그 = 리소스에 레이블 부착 → 부서/프로젝트별 비용 분류. 태그는 먼저 AWS 콘솔에서 "활성화"해야 Cost Explorer에서 필터로 사용 가능합니다.

## Q3. 객체 스토리지, 실시간 액세스, 버전 관리 및 라이프사이클

객체를 저장하고, 해당 객체에 대한 실시간 액세스를 제공하며, 버전 관리 및 라이프사이클 기능을 제공합니다.

- A. 아마존 글레이셔 (Amazon Glacier)
- B. AWS 스토리지 게이트웨이
- C. 아마존 S3
- D. Amazon EBS

**정답: C**

✅ **C. 아마존 S3**: Amazon S3(Simple Storage Service)는 대표적인 객체 스토리지 서비스로 실시간 액세스, 버전 관리(Versioning), 라이프사이클 정책을 모두 지원합니다. 99.999999999%(11 9s)의 내구성을 제공하며 글로벌하게 접근 가능합니다.

❌ **A. 아마존 글레이셔**: Amazon Glacier(현 S3 Glacier)는 장기 아카이브 스토리지로 데이터 검색에 분~시간 단위의 시간이 소요됩니다. "실시간 액세스"와는 거리가 멉니다.

❌ **B. AWS 스토리지 게이트웨이**: 온프레미스 환경과 AWS 클라우드 스토리지를 연결하는 하이브리드 스토리지 서비스로, 직접적인 객체 스토리지 기능이 아닙니다.

❌ **D. Amazon EBS**: EBS(Elastic Block Store)는 블록 스토리지로 EC2 인스턴스에 연결하여 사용합니다. 버전 관리나 라이프사이클 기능이 없으며 객체 스토리지가 아닙니다.

💡 **시험 꿀팁**: S3 = 객체 스토리지 + 글로벌 + 내구성 99.999999999% (11 9s) + 버전 관리 + 라이프사이클. EBS = 블록 스토리지 + EC2 전용 + 단일 AZ. Glacier = 아카이브 + 저렴 + 느린 검색.

## Q4. 클라우드 채택 가속화 지원 팀

어떤 AWS 팀이 고객이 여러 전문 업무 분야에서 유료 계약을 통해 클라우드 채택을 가속화할 수 있도록 지원합니까?

- A. AWS 엔터프라이즈 지원
- B. AWS 솔루션 설계자
- C. AWS 프로페셔널 서비스
- D. AWS 계정 관리자

**정답: C**

✅ **C. AWS 프로페셔널 서비스**: AWS Professional Services는 기업의 클라우드 채택을 가속화하기 위해 유료 컨설팅 계약을 통해 전문적인 기술 지원을 제공하는 AWS 전담 팀입니다. 클라우드 전략 수립, 마이그레이션, 아키텍처 설계 등을 지원합니다.

❌ **A. AWS 엔터프라이즈 지원**: 기술 지원 플랜의 일종으로, TAM(기술 계정 관리자) 배정 및 24/7 지원을 제공하지만 유료 프로젝트 기반 컨설팅 팀이 아닙니다.

❌ **B. AWS 솔루션 설계자**: AWS 내부 직원으로 고객에게 무료로 아키텍처 조언을 제공하지만, 유료 계약을 통한 프로젝트 수행 팀이 아닙니다.

❌ **D. AWS 계정 관리자**: 계정 관련 영업 및 관계 관리를 담당하며, 전문 기술 컨설팅을 유료로 제공하는 역할이 아닙니다.

💡 **시험 꿀팁**: AWS Professional Services = 유료 계약 + 클라우드 채택 가속화 + 전문 컨설팅. AWS Support(엔터프라이즈) = 기술 지원 플랜. 둘을 혼동하지 말 것!

## Q5. AWS 기술 전문 지식 없이 워크로드 구축 지원

고객이 AWS Cloud에서 새로운 워크로드를 설계 및 구축하려고 하지만 AWS 관련 소프트웨어 기술 전문 지식이 사내에 없습니다. 다음 AWS 프로그램 중 고객이 이러한 결과를 얻기 위해 활용할 수 있는 프로그램은 무엇입니까?

- A. AWS 파트너 네트워크 기술 파트너
- B. AWS 마켓플레이스
- C. AWS 파트너 네트워크 컨설팅 파트너
- D. AWS 서비스 카탈로그

**정답: C**

✅ **C. AWS 파트너 네트워크 컨설팅 파트너**: APN(AWS Partner Network) 컨설팅 파트너는 고객이 AWS 기반 솔루션을 설계, 구축, 마이그레이션할 수 있도록 돕는 전문 IT 컨설팅 회사입니다. 내부 전문 지식이 없는 고객에게 외부 전문가를 연결해주는 최적의 프로그램입니다.

❌ **A. AWS 파트너 네트워크 기술 파트너**: 기술 파트너는 AWS 기반 소프트웨어 솔루션이나 플랫폼을 개발하는 ISV(독립 소프트웨어 벤더)입니다. 컨설팅 및 구축 지원이 아닌 제품을 제공하는 파트너입니다.

❌ **B. AWS 마켓플레이스**: 서드파티 소프트웨어, SaaS, 데이터 제품을 구매하는 온라인 스토어입니다. 기술 전문 인력이나 컨설팅 서비스를 제공하지 않습니다.

❌ **D. AWS 서비스 카탈로그**: 조직이 승인된 IT 서비스 목록을 중앙에서 관리하는 도구로, 기술 전문 지식 부족 문제를 해결하는 프로그램이 아닙니다.

💡 **시험 꿀팁**: APN 파트너 유형 구분 — 컨설팅 파트너: 구축/마이그레이션/설계 지원 (시스템 인티그레이터, 컨설팅 회사). 기술 파트너: AWS 위에서 실행되는 소프트웨어 제품을 만드는 회사(ISV).

## Q6. 워크로드를 여러 가용성 영역에 분산하는 설계 원칙

워크로드를 여러 가용성 영역에 분산하는 것은 어떤 클라우드 아키텍처 설계 원칙을 지원합니까?

- A. 자동화 구현
- B. 민첩성을 위한 설계
- C. 고장에 대한 설계
- D. 탄성을 구현한다

**정답: C**

✅ **C. 고장에 대한 설계 (Design for Failure)**: 여러 가용성 영역(AZ)에 워크로드를 분산하면 하나의 AZ가 장애를 겪더라도 서비스가 계속 운영됩니다. "단일 장애 지점(Single Point of Failure) 제거"가 핵심으로, 이는 고장을 가정하고 설계하는 원칙입니다.

❌ **A. 자동화 구현**: 자동화는 수동 작업을 줄이고 일관성을 높이는 원칙입니다. AZ 분산과는 직접적인 관련이 없습니다.

❌ **B. 민첩성을 위한 설계**: 신속한 실험과 반복을 가능하게 하는 원칙으로, 여러 AZ 분산과 다른 개념입니다.

❌ **D. 탄성을 구현**: 탄성(Elasticity)은 수요에 따라 리소스를 자동으로 늘리거나 줄이는 개념입니다. AZ 분산은 가용성에 관한 것이지 자동 확장과는 다릅니다.

💡 **시험 꿀팁**: 여러 AZ 분산 = "고장에 대한 설계" = 고가용성(HA) = 단일 장애 지점 제거. 탄성(Elasticity) = Auto Scaling = 수요에 따른 자동 확장/축소. 이 둘을 구분하는 것이 핵심!

## Q7. Microsoft SQL Server 데이터베이스 호스팅 서비스 (두 개 선택)

Microsoft SQL Server 데이터베이스를 호스팅할 수 있는 AWS 서비스는 무엇입니까? (두 개 선택)

- A. 아마존 EC2
- B. Amazon RDS(Amazon Relational Database Service)
- C. 아마존 오로라
- D. Amazon Redshift
- E. 아마존 S3

**정답: A, B**

✅ **A. 아마존 EC2**: EC2 인스턴스에 Windows OS를 설치하고 Microsoft SQL Server를 직접 설치하여 호스팅할 수 있습니다. 완전한 OS 수준의 제어가 필요할 때 사용합니다.

✅ **B. Amazon RDS**: Amazon RDS는 Microsoft SQL Server를 관리형 데이터베이스 엔진으로 공식 지원합니다. 패치, 백업, 복제 등을 AWS가 관리해주는 완전 관리형 서비스입니다.

❌ **C. 아마존 오로라**: Aurora는 MySQL과 PostgreSQL 호환 엔진만 지원합니다. Microsoft SQL Server는 지원하지 않습니다.

❌ **D. Amazon Redshift**: Redshift는 데이터 웨어하우스 서비스로 OLAP 분석에 특화되어 있으며, SQL Server를 호스팅하는 서비스가 아닙니다.

❌ **E. 아마존 S3**: S3는 객체 스토리지 서비스로 데이터베이스 엔진을 호스팅하는 용도가 아닙니다.

💡 **시험 꿀팁**: RDS 지원 엔진 암기 — MySQL, PostgreSQL, MariaDB, Oracle, Microsoft SQL Server, IBM Db2. Aurora는 MySQL/PostgreSQL만 지원. SQL Server 호스팅 = EC2(직접 설치) 또는 RDS(관리형).

## Q8. AWS 환경 검사 - 비용 절감 및 성능 향상

다음 중 사용자를 위해 비용을 절감하고 시스템 성능을 향상시킬 수 있는 기회를 찾기 위해 AWS 환경을 검사하는 것은 무엇입니까?

- A. AWS 비용 탐색기
- B. AWS Trusted Advisor
- C. 통합 청구
- D. 상세 청구

**정답: B**

✅ **B. AWS Trusted Advisor**: AWS 환경을 자동으로 분석하여 비용 최적화, 성능, 보안, 내결함성, 서비스 한도의 5가지 범주에서 개선 권고사항을 제공합니다. "AWS 모범 사례"를 기반으로 실시간 조언을 제공하는 도구입니다.

❌ **A. AWS 비용 탐색기**: Cost Explorer는 과거 비용 및 사용량 데이터를 시각화하고 분석하는 도구입니다. 환경을 검사하여 최적화 기회를 찾는 기능이 아닌 비용 데이터 분석 도구입니다.

❌ **C. 통합 청구**: 여러 AWS 계정의 청구를 하나로 통합하는 기능으로, 환경 검사 및 최적화 추천과는 관련이 없습니다.

❌ **D. 상세 청구**: 세부적인 청구 데이터를 제공하는 기능으로, 환경 분석 및 최적화 권고와는 다릅니다.

💡 **시험 꿀팁**: Trusted Advisor = AWS 환경 자동 점검 + 5가지 카테고리(비용 최적화, 성능, 보안, 내결함성, 서비스 한도). 기본(무료) 계획은 핵심 보안 + 서비스 한도 체크만 제공. Business/Enterprise 지원 플랜에서 전체 기능 사용 가능.

## Q9. 기존 서버 바인딩 소프트웨어 라이센스 사용 가능한 EC2 가격 모델

다음 중 고객이 기존 서버 바인딩 소프트웨어 라이센스를 사용할 수 있는 Amazon EC2 가격 모델은 무엇입니까?

- A. 스폿 인스턴스
- B. 예약된 인스턴스
- C. 전용 호스트
- D. 주문형 인스턴스

**정답: C**

✅ **C. 전용 호스트 (Dedicated Host)**: 전용 호스트는 물리적 서버 전체를 고객이 독점적으로 사용하므로, 소켓 수, 코어 수, VM 수 기반의 BYOL(Bring Your Own License) 라이센스를 그대로 사용할 수 있습니다. Windows Server, SQL Server, Oracle 등의 라이센스에 유용합니다.

❌ **A. 스폿 인스턴스**: 미사용 EC2 용량을 저렴하게 사용하는 모델로, 인스턴스가 중단될 수 있어 라이센스 관리에 적합하지 않으며 특정 물리 서버를 보장하지 않습니다.

❌ **B. 예약된 인스턴스**: 1년 또는 3년 약정으로 할인을 받는 모델이지만, 특정 물리 서버를 전용으로 사용하는 것이 아니어서 기존 서버 바인딩 라이센스 사용에는 적합하지 않습니다.

❌ **D. 주문형 인스턴스**: 사용한 만큼 지불하는 가장 기본적인 모델이지만, 공유 물리 인프라에서 실행되어 서버 바인딩 라이센스를 적용할 수 없습니다.

💡 **시험 꿀팁**: BYOL(기존 라이센스 활용) = 전용 호스트(Dedicated Host). 단순 격리 = 전용 인스턴스(Dedicated Instance). Dedicated Host는 물리 서버 전체를 독점 + 소켓/코어 기반 라이센싱 가능. 비용이 가장 비싸지만 컴플라이언스 요구사항 충족.

## Q10. 동적 사용자 요구 워크로드의 AWS 비용 효율성 특성 (두 개 선택)

동적 사용자 요구가 있는 워크로드에 AWS를 비용 효율적으로 만드는 AWS 특성은 무엇입니까? (두 개를 선택합니다.)

- A. 고가용성
- B. 공유 보안 모델
- C. 탄력성
- D. 종량제 가격
- E. 신뢰성

**정답: C, D**

✅ **C. 탄력성 (Elasticity)**: 수요에 따라 리소스를 자동으로 확장하거나 축소할 수 있습니다. 사용량이 많을 때는 늘리고 적을 때는 줄여 불필요한 비용을 방지합니다. 동적 워크로드에 최적화된 특성입니다.

✅ **D. 종량제 가격 (Pay-as-you-go)**: 사용한 리소스에 대해서만 비용을 지불합니다. 동적 수요 변화에 따라 비용이 실제 사용량과 비례하므로 과잉 프로비저닝 없이 비용 효율을 달성할 수 있습니다.

❌ **A. 고가용성**: 가용성은 서비스 중단 없이 운영되는 능력으로 중요하지만, 동적 수요에 따른 비용 효율성과는 직접적인 관련이 없습니다.

❌ **B. 공유 보안 모델**: 보안 책임을 AWS와 고객이 나누는 모델로, 비용 효율성과 무관합니다.

❌ **E. 신뢰성**: 시스템이 의도한 대로 작동하는 능력으로 중요한 특성이지만, 동적 수요에 대한 비용 효율성을 설명하지는 않습니다.

💡 **시험 꿀팁**: 동적 워크로드 + 비용 효율 = 탄력성(Elasticity) + 종량제(Pay-as-you-go). 이 두 개념은 항상 함께 나옵니다. 탄력성은 Auto Scaling과 연결, 종량제는 온디맨드 과금 방식과 연결됩니다.

## Q11. 계정 활동 모니터링 및 로깅 - 리스크 감사

AWS Management Console 및 AWS SDK의 사용자 작업을 포함하여 계정 활동을 지속적으로 모니터링 및 로깅하여 리스크 감사를 가능하게 하는 서비스는 무엇입니까?

- A. Amazon CloudWatch
- B. AWS CloudTrail
- C. AWS 구성 (AWS Config)
- D. AWS Health

**정답: B**

✅ **B. AWS CloudTrail**: AWS CloudTrail은 AWS 계정에서 발생하는 모든 API 호출(누가, 언제, 어디서, 무엇을)을 기록하고 로깅합니다. 콘솔, CLI, SDK, AWS 서비스를 통한 모든 활동이 기록되어 보안 감사, 규정 준수, 운영 문제 해결에 사용됩니다.

❌ **A. Amazon CloudWatch**: 리소스의 성능 지표(CPU, 메모리, 네트워크 등)를 모니터링하고 경보를 설정하는 서비스입니다. API 호출 로깅이 아닌 시스템 성능 모니터링 도구입니다.

❌ **C. AWS Config**: AWS 리소스의 구성 변경 이력을 추적하고 규정 준수를 평가하는 서비스입니다. API 호출 감사보다는 리소스 구성 상태 추적에 초점이 맞춰져 있습니다.

❌ **D. AWS Health**: AWS 서비스의 상태, 유지 관리 일정, 계정에 영향을 미치는 이벤트를 알려주는 서비스로 API 활동 로깅과는 관련이 없습니다.

💡 **시험 꿀팁**: CloudTrail = "누가 무엇을 했는가" = API 호출 로그 = 감사(Audit). CloudWatch = "시스템이 어떻게 동작하는가" = 메트릭 + 로그 + 경보. 시험에서 "감사", "로깅", "API 활동 추적" 키워드가 나오면 CloudTrail!

## Q12. Amazon S3의 특징 (두 가지 선택)

다음 중 아마존 S3의 특징은 무엇입니까? (두 가지 선택)

- A. 글로벌 파일 시스템
- B. 객체 저장소
- C. 로컬 파일 저장소
- D. 네트워크 파일 시스템
- E. 내구성이 뛰어난 스토리지 시스템

**정답: B, E**

✅ **B. 객체 저장소**: S3는 파일을 객체(데이터 + 메타데이터 + 고유 키)로 저장하는 객체 스토리지 서비스입니다. 파일 시스템이나 블록 스토리지와는 다른 방식으로 데이터를 관리합니다.

✅ **E. 내구성이 뛰어난 스토리지 시스템**: Amazon S3는 연간 99.999999999%(11 9s)의 내구성을 제공합니다. 데이터는 동일 리전의 여러 AZ에 걸쳐 자동으로 복제되어 저장됩니다.

❌ **A. 글로벌 파일 시스템**: S3는 글로벌 서비스이지만 파일 시스템이 아닌 객체 스토리지입니다. 글로벌 파일 시스템은 Amazon EFS(Elastic File System)와 같은 서비스에 해당합니다.

❌ **C. 로컬 파일 저장소**: S3는 클라우드 기반 원격 스토리지이며 로컬 파일 스토리지가 아닙니다. 인스턴스 스토어가 로컬 스토리지에 해당합니다.

❌ **D. 네트워크 파일 시스템**: NFS 프로토콜을 사용하는 파일 시스템은 Amazon EFS입니다. S3는 HTTP/HTTPS API를 통해 접근하는 객체 스토리지입니다.

💡 **시험 꿀팁**: 스토리지 유형 구분 — 객체 스토리지: S3 (API 접근, 내구성 11 9s). 블록 스토리지: EBS (EC2 전용, 하드디스크처럼 사용). 파일 스토리지: EFS (NFS, 여러 EC2 동시 접근). 인스턴스 스토어: EC2 로컬 임시 스토리지.

## Q13. 하이브리드 AWS 클라우드 아키텍처에서 사용 가능한 서비스 (두 개 선택)

하이브리드 AWS 클라우드 아키텍처에서 사용할 수 있는 서비스는 무엇입니까? (두 개를 선택합니다.)

- A. Amazon Route 53
- B. 가상 사설 게이트웨이 (Virtual Private Gateway)
- C. 클래식 로드 밸런서
- D. 자동 확장 (Auto Scaling)
- E. Amazon CloudWatch 기본 메트릭

**정답: A, B**

✅ **A. Amazon Route 53**: Route 53은 DNS 서비스로 온프레미스와 AWS 클라우드 환경 간의 트래픽을 라우팅하는 데 사용됩니다. 하이브리드 환경에서 두 환경 간의 네트워크 연결과 트래픽 분산에 활용됩니다.

✅ **B. 가상 사설 게이트웨이**: Virtual Private Gateway(VGW)는 AWS VPC와 온프레미스 네트워크를 VPN 또는 AWS Direct Connect를 통해 연결할 때 VPC 측의 게이트웨이입니다. 하이브리드 아키텍처의 핵심 구성 요소입니다.

❌ **C. 클래식 로드 밸런서**: AWS 내부에서 트래픽을 분산하는 서비스로, 하이브리드 환경 연결을 위한 전용 서비스가 아닙니다.

❌ **D. 자동 확장**: AWS 내 EC2 인스턴스를 자동으로 확장/축소하는 서비스로, 온프레미스와의 연결을 담당하는 하이브리드 서비스가 아닙니다.

❌ **E. Amazon CloudWatch 기본 메트릭**: AWS 리소스 모니터링 도구로, 하이브리드 아키텍처 연결 자체를 담당하지 않습니다.

💡 **시험 꿀팁**: 하이브리드 아키텍처 핵심 서비스 — Virtual Private Gateway(VGW) + AWS Direct Connect 또는 VPN = 온프레미스 ↔ AWS 연결. AWS Storage Gateway = 온프레미스 ↔ AWS 스토리지 하이브리드. Route 53 = 온프레미스와 클라우드 간 DNS 라우팅.

## Q14. AWS TCO와 사내 TCO 비교 시 포함 비용

AWS 총소유비용(TCO)을 사내 TCO와 비교할 때 포함되는 비용은 얼마입니까?

❌ **D. 소프트웨어 개발**: 소프트웨어 개발 비용은 클라우드 사용 여부와 관계없이 발생하는 비용입니다.

## Q15. 야간 종료가 필요한 자체 호스팅 데이터베이스

한 기업은 유지보수 및 비용 절감을 위해 야간 종료가 필요한 자체 호스팅 데이터베이스로 AWS를 사용하는 것을 고려하고 있습니다. 회사는 어떤 서비스를 이용해야 하나요?

- A. Amazon Redshift
- B. 아마존 다이너모DB
- C. Amazon EC2 인스턴스 스토어가 포함된 Amazon EC2
- D. Amazon Elastic Block Store 포함 Amazon EC2 (Amazon EBS)

**정답: D**

✅ **D. Amazon EBS 포함 Amazon EC2**: EC2 인스턴스에 데이터베이스를 직접 설치하고, EBS 볼륨에 데이터를 저장하면 야간에 인스턴스를 중지(Stop)해도 EBS에 저장된 데이터는 유지됩니다. 인스턴스를 중지하면 인스턴스 요금이 발생하지 않아 비용 절감이 가능합니다.

❌ **A. Amazon Redshift**: 데이터 웨어하우스 서비스로 완전 관리형이며 임의로 야간 종료가 불가능한 구조입니다. 일반 OLTP 데이터베이스 용도가 아닙니다.

❌ **B. 아마존 다이너모DB**: 완전 관리형 NoSQL 서비스로 고객이 임의로 종료할 수 없습니다. 서버리스 방식이라 야간 종료 개념이 적용되지 않습니다.

❌ **C. Amazon EC2 인스턴스 스토어가 포함된 Amazon EC2**: 인스턴스 스토어는 인스턴스가 중지되면 모든 데이터가 삭제(휘발성)됩니다. 데이터베이스를 야간에 종료하면 다음날 데이터가 사라져 사용할 수 없습니다.

💡 **시험 꿀팁**: EC2 중지 시 비용 — 인스턴스 스토어: 데이터 사라짐(Stop 불가). EBS: 인스턴스 중지해도 데이터 유지 + 인스턴스 요금 미발생(EBS 스토리지 요금만 발생). 야간 종료 + 데이터 유지 = EC2 + EBS!

## Q16. 지역, 가용성 영역 및 엣지 로케이션 간의 관계

다음 중 지역, 가용성 영역 및 가장자리 위치(엣지 로케이션) 간에 올바른 관계는 무엇입니까?

- A. 데이터 센터에는 지역이 포함됩니다.
- B. 지역에는 가용성 구역이 포함됩니다.
- C. 가용성 영역에는 가장자리 위치가 포함됩니다.
- D. 가장자리 위치에는 영역이 포함됩니다.

**정답: B**

✅ **B. 지역에는 가용성 구역이 포함됩니다**: AWS 인프라 계층 구조는 리전(Region) > 가용성 영역(AZ) > 데이터 센터 순서입니다. 각 리전은 최소 2개(보통 3개 이상)의 AZ를 포함하며, 각 AZ는 하나 이상의 물리적 데이터 센터로 구성됩니다.

❌ **A. 데이터 센터에는 지역이 포함됩니다**: 반대 관계입니다. 지역(리전)이 더 큰 개념이며 데이터 센터를 포함합니다.

❌ **C. 가용성 영역에는 가장자리 위치가 포함됩니다**: 엣지 로케이션은 AZ와 별개의 개념입니다. CloudFront CDN을 위한 별도 거점으로, AZ의 하위 개념이 아닙니다.

❌ **D. 가장자리 위치에는 영역이 포함됩니다**: 엣지 로케이션은 AZ보다 작은 개념이 아니며 서로 독립적인 개념입니다. 엣지 로케이션은 전 세계에 400개 이상 분포하며 AZ와는 다른 목적으로 사용됩니다.

💡 **시험 꿀팁**: AWS 인프라 계층 구조 암기 — 리전(Region) > 가용성 영역(AZ) > 데이터 센터. 엣지 로케이션(Edge Location)은 별도 개념 = CloudFront + Route 53 + Global Accelerator용 캐시/라우팅 거점. 리전 수(30+) < 엣지 로케이션 수(400+).

## Q17. 비용 견적 지원 AWS 도구 (세 개 선택)

비용 견적을 지원하는 AWS 도구는 무엇입니까? (세 개를 선택합니다.)

- A. 상세한 청구 보고서
- B. 비용 할당 태그
- C. AWS 가격 계산기
- D. AWS 총소유비용(TCO) 계산기
- E. 비용 추정기 (AWS Cost Estimator)

**정답: A, C, D**

✅ **A. 상세한 청구 보고서 (Detailed Billing Reports)**: AWS 사용량과 비용을 항목별로 세분화한 보고서로, 과거 비용 데이터를 분석하여 미래 비용을 추정하는 데 활용됩니다.

✅ **C. AWS 가격 계산기 (AWS Pricing Calculator)**: AWS 서비스의 예상 비용을 사전에 계산할 수 있는 도구입니다. 다양한 서비스 조합과 사용량을 입력하여 월별 예상 비용을 견적 낼 수 있습니다.

✅ **D. AWS TCO 계산기**: 온프레미스 환경과 AWS 클라우드 환경의 총소유비용을 비교하여 클라우드 전환의 비용 절감 효과를 견적합니다.

❌ **B. 비용 할당 태그**: 비용을 분류하고 추적하는 도구로, 미래 비용 견적이 아닌 현재/과거 비용 분류에 사용됩니다.

❌ **E. 비용 추정기**: 명확하게 정의된 AWS 독립 서비스가 아닙니다. AWS Pricing Calculator가 비용 추정 기능을 담당합니다.

💡 **시험 꿀팁**: 비용 견적 도구 구분 — AWS Pricing Calculator: 신규 아키텍처 비용 예측. TCO 계산기: 온프레미스 vs AWS 비용 비교. Cost Explorer: 과거 비용 분석 + 미래 비용 예측. 상세 청구 보고서: 세부 비용 내역 확인.

## Q18. AWS 통합 과금의 장점 (두 개 선택)

다음 중 AWS 통합 과금의 장점은 무엇입니까? (두 개를 선택합니다.)

- A. 여러 계정에 대해 하나의 청구서를 수령할 수 있는 능력
- B. 모든 계정에서 기본적으로 서비스 제한 증가
- C. 월 청구서에 대한 고정 할인
- D. 모든 계정에서의 사용이 결합된 잠재적인 볼륨 할인
- E. 마스터 계정의 AWS 지원 계획을 모든 계정으로 자동 확장

**정답: A, D**

✅ **A. 여러 계정에 대해 하나의 청구서**: AWS Organizations의 통합 청구는 마스터(관리) 계정에서 모든 멤버 계정의 비용을 하나의 청구서로 통합 관리할 수 있습니다. 재무 팀의 청구 관리가 간소화됩니다.

✅ **D. 모든 계정에서의 사용이 결합된 잠재적인 볼륨 할인**: 여러 계정의 사용량을 합산하여 더 높은 사용량 티어에 도달하면 볼륨 기반 할인(예: S3, 데이터 전송 등)을 받을 수 있습니다.

❌ **B. 모든 계정에서 기본적으로 서비스 제한 증가**: 통합 청구가 서비스 한도를 자동으로 증가시키지는 않습니다. 서비스 한도 증가는 별도로 AWS 지원에 요청해야 합니다.

❌ **C. 월 청구서에 대한 고정 할인**: 통합 청구 자체가 고정 할인율을 제공하지는 않습니다. 볼륨 기반 할인은 가능하지만 고정 할인은 아닙니다.

❌ **E. 마스터 계정의 AWS 지원 계획을 모든 계정으로 자동 확장**: 지원 계획은 계정별로 별도로 구매해야 하며, 자동으로 확장되지 않습니다.

💡 **시험 꿀팁**: 통합 청구(Consolidated Billing) 핵심 혜택 2가지 — 1) 단일 청구서로 관리 간소화. 2) 사용량 합산을 통한 볼륨 할인. Reserved Instance나 Savings Plans도 계정 간 공유 가능!

## Q19. 온디맨드 대비 가장 높은 절감 효과 - RI 가격 모델

다음 RI(예약 인스턴스) 가격 모델 중 온디맨드 가격 대비 가장 높은 평균 절감 효과를 제공하는 모델은 무엇입니까?

- A. 1년, 선불제, 표준 RI 가격
- B. 1년 만기, 모든 선불 전환 가능 RI 가격
- C. 3년 만기, 모든 선불, 표준 RI 가격
- D. 3년제, 선불 없음, 컨버터블 RI 가격

**정답: C**

✅ **C. 3년 만기, 모든 선불, 표준 RI 가격**: 절감률을 극대화하는 조건을 모두 갖추고 있습니다. 약정 기간이 길수록(3년 > 1년), 선불 금액이 많을수록(전체 선불 > 일부 선불 > 선불 없음), 유연성이 낮을수록(표준 RI > 컨버터블 RI) 할인율이 높아집니다.

❌ **A. 1년, 선불제, 표준 RI**: 표준 RI에 선불이지만 1년 약정으로 절감률이 C보다 낮습니다.

❌ **B. 1년, 모든 선불, 컨버터블 RI**: 전체 선불이지만 1년 약정에 컨버터블(유연성 높음)이라 표준 RI보다 할인율이 낮습니다.

❌ **D. 3년, 선불 없음, 컨버터블 RI**: 3년 약정이지만 선불이 없고 컨버터블이라 할인율이 가장 낮은 조합입니다.

💡 **시험 꿀팁**: RI 할인율 최대화 공식 = 3년 + 전체 선불(All Upfront) + 표준(Standard). 할인율 감소 순서 — 기간: 3년 > 1년. 선불: All Upfront > Partial Upfront > No Upfront. 유형: Standard > Convertible (Convertible은 인스턴스 패밀리 변경 가능하지만 할인율은 낮음).

## Q20. 기존 데이터 센터 대비 AWS의 비용 이점

기존 및 가상화된 데이터 센터의 비용과 비교하여 AWS는 다음과 같은 이점을 제공합니다.

- A. 변동 비용 및 초기 비용 증가
- B. 고정 사용 비용 및 초기 비용 절감
- C. 변동 비용을 낮추고 초기 비용을 높입니다.
- D. 가변 비용 절감 및 초기 비용 절감

**정답: D**

✅ **D. 가변 비용 절감 및 초기 비용 절감**: AWS 클라우드는 대규모 규모의 경제를 통해 단위 비용을 낮추어 변동 비용을 절감하고, 서버/네트워크 장비 등 초기 자본 지출(CapEx)이 필요 없어 초기 비용도 절감됩니다. 온디맨드 과금 방식으로 사용한 만큼만 지불합니다.

❌ **A. 변동 비용 및 초기 비용 증가**: AWS를 사용하면 두 비용 모두 감소하는 것이 핵심 이점입니다. 증가하는 것이 아닙니다.

❌ **B. 고정 사용 비용 및 초기 비용 절감**: AWS는 고정 비용이 아닌 변동(종량제) 비용 모델로 전환됩니다. 고정 비용 모델은 온프레미스에 더 가깝습니다.

❌ **C. 변동 비용을 낮추고 초기 비용을 높입니다**: AWS는 초기 비용(자본 지출)을 높이지 않습니다. 오히려 초기 인프라 투자 없이 즉시 시작할 수 있는 것이 핵심 장점입니다.

💡 **시험 꿀팁**: AWS의 핵심 비용 이점 — CapEx(자본 지출) → OpEx(운영 지출) 전환. 초기 대규모 투자 불필요 + 규모의 경제로 단위 비용 절감. "Trade capital expense for variable expense" = AWS 클라우드의 6가지 이점 중 하나!
